# VIP会员体系功能需求 · v1.2

当前迭代 v1.2：把现网【用户管理 › 会员等级】改造为 VIP 体系，替换原 LEVEL，旧版 VIP（VIP特权、旧版 VIP活动）完全移除。VIP0 + VIP1–VIP24、SUPER VIP（默认 26 档，后台可新增最高级、删除最高级）；VIP0 前台、后台都显示「VIP0」，前台等级按段位显示样式（黑铁、青铜、白银、黄金、铂金、钻石、荣耀）；累计有效投注和累计充值同时达标即实时升级，每级生成一次升级奖金：任何页面弹 3 秒动画，回到平台页面在确认弹窗点「领取奖金」领取；每月 1 日 13:00（GMT+8）结算，按当月达到保级投注的最高等级 k（不超过历史最高）生成月度工资，未保级次月只降 1 级，降级玩家可一次恢复多级；「KYC 限制」开启时完成 KYC 补发已达到等级的升级奖金；三种奖金都由玩家在等级卡「查看详情」弹窗里手动领取（升级奖金另可在确认弹窗领取），升级奖金、月度工资默认 7 天有效、生日奖金 15 天，过期作废；不设审核（以上为用户 2026-10-29 更新）。后台 4 个页签：VIP会员等级配置、VIP会员等级奖励配置、活动奖励统计、VIP月度结算记录；前台 Level Center 改为 VIP中心。

涉及端：H5、iOS 原生、iOS Flutter、安卓 Flutter 和管理后台。规模（完整需求）：前台原型 2 页、后台原型 4 页；大功能点 8 个、子功能点 41 个；规则 68 条；待确认事项 19 项（以 PRD 为准，打包时入口页统计自动刷新）。

本文件夹是源文件（相当于产品站点的内容）。四个角色站点由 `.claude/tools/build_role_sites.ps1` 生成，不手工修改。

## 发布到 GitHub Pages

1. 解压压缩包，把里面的 `pdm`、`opr`、`dev`、`repo` 四个文件夹和 `index.html`、`.nojekyll`、`README.md` 放到仓库根目录。
2. 提交并推送，在仓库的 Settings › Pages 里选择发布分支。
3. 把四个访问链接分别发给产品、运营、开发和报告对象。直接打开仓库根地址（没有分身份的链接）时，先进这台电脑上次使用的角色站点；没有记录时进产品站点，需要输入密码。

不需要构建。本地预览时，可以在源文件夹页面地址后加 `?role=pdm`、`?role=opr`、`?role=dev` 或 `?role=repo` 模拟不同角色。

产品站点打开时要先输入访问密码（向该需求的产品管理人获取）；运营、开发和报告站点不需要。

注意：静态页面没有登录，这只是按链接和密码做的简单区分，不是真正的权限控制；拿到别的角色链接的人也能打开，懂技术的人也能绕过密码。
