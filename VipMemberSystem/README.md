# VIP会员体系功能需求 · v1.0

在【用户管理 › VIP特权】新建可配置的 VIP 体系（默认 VIP1–VIP24、SUPER VIP 共 25 级，可新增、可关闭）：按「累计金额」（累计充值 + 累计有效投注双门槛）或「成长值」实时升级并发放升级奖励；每月 1 日按上月整月有效投注（或新增成长值）保级、发保级奖励、未达标降 1 级，降级后可按条件恢复；生日当天按当前等级发生日奖励；奖励可配置为自动到账或手动领取，可开启强制审核。普通会员（Level）配置留在【会员等级】并做配套改造。C 端在等级中心展示 VIP 段。

涉及端：H5、iOS 原生、iOS Flutter、安卓 Flutter 和管理后台。规模（完整需求）：前台原型 2 页、后台原型 4 页；大功能点 8 个、子功能点 41 个；规则 68 条；待确认事项 17 项（以 PRD 为准，打包时入口页统计自动刷新）。

- 需求名称：VIP会员体系
- 依据：产品方案「VIP 会员体系方案」（Claire，2026-10-09）和 Claire 2026-10-17 的答复（C-01–C-15），二者优先级最高；产品在原文之外补充的规则在 PRD「起因」列注明「原文外补充」。
- 文档分三套：v1.0 迭代、v1.1 迭代、完整需求。每套是一份独立、完整、可单独交给开发的需求，内容只对应本迭代：
  - v1.0 迭代：在【用户管理 › VIP特权】新建可配置的 VIP 体系（固定 VIP1–VIP24、SUPER VIP 共 25 级）：按「累计金额」（累计充值 + 累计有效投注双门槛）或「成长值」实时升级，升级奖励立即自动到账；每月 1 日按上月整月有效投注（或新增成长值）保级、保级奖励自动到账、未达标降 1 级，降级后可按条件恢复；生日当天按当前等级生成生日奖励，玩家在等级中心领取；可开启强制审核、注册天数。【会员等级】保持现状。C 端在等级中心展示 VIP 段，没有 VIP 等级的玩家显示「普通用户」。不含实体奖品（C-10），VIP 等级不能新增、关闭。
  - v1.1 迭代：包含 v1.0 全部内容，范围与完整需求相同：【会员等级】配套改造（前台显示方式、等级表并入下注限额与返水、添加 / 修改 / 删除等级、场馆成长值倍数）；VIP 等级新增、关闭和复核，SUPER VIP 只是等级名称、不作为最高等级标识（规则 N74）；奖励领取方式（自动到账 / 手动领取）；VIP奖品配置。
  - 完整需求：全部功能（与 v1.1 迭代一致）。
- 实体奖品：v1.1 和完整需求只做「VIP 等级 → 奖品」的选择和活动库存预占（规则 N72）；实体奖品的领取、审核、扣库存和发货，以及前台的收货地址和领取页面，由「实体奖品管理」需求负责，不在本需求包里。

## 按角色访问

需求包发布成四个角色站点，每个角色一个文件夹，各自的访问链接只发给对应的人（权限按 `assets/nav-data.js` 的 `roles`）：

| 角色 | 包含人员 | 文件夹 | 访问链接 | 能看的页面 |
|---|---|---|---|---|
| 产品 | 产品经理、行政管理人员 | `pdm/` | `<Pages 地址>/<仓库名>/pdm` | 全部页面；默认页是需求与原型中心（含需求文档架构图、运营需求修改记录）；顶栏可切换运营、开发、报告视角 |
| 运营 | 运营、客服、商务 | `opr/` | `<Pages 地址>/<仓库名>/opr` | 全部原型、各迭代的需求修改总结（默认页为 v1.1 迭代这一份）、运营需求确认、后台操作手册、客服QA |
| 开发 | UI 设计、前端、后端、测试 | `dev/` | `<Pages 地址>/<仓库名>/dev` | 全部原型、三套需求要点（默认页为 v1.1 迭代需求要点）、三套需求开发 PRD 文档、三套开发自查清单 |
| 报告 | 汇报和评审对象 | `repo/` | `<Pages 地址>/<仓库名>/repo` | 全部原型、三套需求开发 PRD 文档（默认页为 v1.1 迭代 PRD），只读 |

本文件夹是源文件（相当于产品站点的内容）。四个角色站点由 `.claude/tools/build_role_sites.ps1` 生成，不手工修改。

## 发布到 GitHub Pages

1. 解压压缩包，把里面的 `pdm`、`opr`、`dev`、`repo` 四个文件夹和 `index.html`、`.nojekyll`、`README.md` 放到仓库根目录。
2. 提交并推送，在仓库的 Settings › Pages 里选择发布分支。
3. 把四个访问链接分别发给产品、运营、开发和报告对象。直接打开仓库根地址（没有分身份的链接）时，先进这台电脑上次使用的角色站点；没有记录时进产品站点，需要输入密码。

不需要构建。本地预览时，可以在源文件夹页面地址后加 `?role=pdm`、`?role=opr`、`?role=dev` 或 `?role=repo` 模拟不同角色。

产品站点打开时要先输入访问密码（向该需求的产品管理人获取）；运营、开发和报告站点不需要。

注意：静态页面没有登录，这只是按链接和密码做的简单区分，不是真正的权限控制；拿到别的角色链接的人也能打开，懂技术的人也能绕过密码。
