规则批注

  1. 页面范围：4 个页签在同一页面切换；去掉【用户管理 › VIP特权】菜单和系统参数「新版VIP特权状态」。原方案的 VIP 会员数据、等级变动记录查询页不补回，数据保留在数据库；操作日志改为各页签右上角「操作日志」弹窗查询。PRD 7.1、规则 N47 去掉旧版 VIP（VIP特权）、Q23 原方案后台功能是否补回（已定）、Q65 资金防护 · F09-05 权限与操作日志
  2. 等级档位：两张等级表默认 26 行（VIP0 + VIP1–SUPER VIP）；等级名按位置自动生成，不能手改。VIP0（等级值 0，前台、后台都显示「VIP0」）整行为 0、只读、不能删除；只有最高一级 SUPER VIP 可删除。PRD 规则 N1 等级档位 · F01-01 VIP 等级配置表
  3. 新增等级：点 VIP0 行「新增」，表格最下方加一行，新行名为 SUPER VIP，原 SUPER VIP 改名为 VIP25（以此类推）。新行三项门槛必填，且大于上一级；保存前可点「取消」去掉。一次只能新增 1 行，不设等级数量上限。点「保存」后在影响预览里填写新等级的升级奖金、月度工资、生日奖金（默认 0，0–9,999,999.99，最多 2 位小数，不合法时标红、不能确认），填谷歌验证码「确认保存」后门槛和奖金一起生效（达到审批条件的审批通过后生效）。保存后全部玩家按新配置重算等级：重算前历史最高那一级的升级奖金未领取的系统作废，生成 1 笔不超过原金额的「等级调整补偿」（待领取；该等级已有记录的不生成）；领过被删等级升级奖金的玩家，到达的第 1 个新增等级不发；不弹窗、不发站内信。PRD 规则 N49 新增等级、N55 新增和删除等级后的等级重算 · F01-04 新增与删除等级
  4. 删除等级：只有 SUPER VIP 行显示「删除」，确认框写明删除内容、该等级玩家人数和处理、等级名变化，填谷歌验证码「确认删除」后立即生效、不能撤销：原次高级改名为 SUPER VIP，两张表同步删除该行。被删等级的玩家改为新的 SUPER VIP；降级玩家的历史最高按累计重新确定；记「等级配置调整」，不算降级、不显示 BACK、不弹窗、不发站内信；未领取的升级奖金系统作废，按规则 N55「新增、删除等级后的等级重算」生成等级调整补偿；已发奖金不追回。只剩 1 个 VIP 等级、有未保存的新增行或结算期间，不能删除。PRD 规则 N50 删除等级、N55 新增和删除等级后的等级重算 · F01-04 新增与删除等级
  5. 前台段位：新增、删除等级保存后，前台段位按新的等级数立即重新分配；影响预览和删除确认框提示「前台段位将按新的等级数重新分配」并列出新分段。VIP0 固定「黑铁」，SUPER VIP 固定「荣耀」；中间 N 级（VIP1 至次高级，默认 N = 24）分为青铜、白银、黄金、铂金、钻石、星耀 6 段：
    · N < 6：从青铜起每段 1 级；
    · N ≥ 6：s = N ÷ 6 向上取整，星耀、钻石、铂金、黄金、白银各 s 级（从高往低），剩下 N − 5s 级给青铜；
    · 若 N − 5s < 1（N = 7–10、13–15、19、20、25）：各段先分 N ÷ 6 向下取整级，余数从星耀往下各多 1 级。
    例：N = 24 → 每段 4 级（青铜 VIP1–4、白银 VIP5–8、黄金 VIP9–12、铂金 VIP13–16、钻石 VIP17–20、星耀 VIP21–24）；N = 25 → 星耀 5 级（VIP21–25），其余各 4 级；N = 27 → 青铜 2 级，其余各 5 级。PRD 规则 N51 前台段位层级、Q27 段位分配算法（已决定）
  6. VIP月度结算记录：第 4 个页签；除明细「重新结算」「完成」和列表「重新结算」外只读；发放状态只在活动奖励统计维护。
    · 列表：每月一行，列为结算月份、执行时间、状态、参与人数、升级、等级变更、保级成功、恢复、降级、其中降为 VIP0、结算失败、已到账；生日奖金、到账核算只在明细显示。参与人数 = 保级成功 + 恢复 + 降级 + 结算失败。
    · 升级：结算月份内实时升级和 KYC 定级的去重人数（一人多次升级、跨多级或两类都有都算 1 人）；「KYC 限制」开启时 KYC 定级计入完成 KYC 的那个月；不含上线结算、等级配置调整、结算恢复；不计入参与人数，结算失败时也照常显示，不可点击。
    · 等级变更：结算月份内等级发生变化的去重人数，含实时升级、KYC 定级、上线结算、等级配置调整（升 / 降）、本结算月份的恢复和降级，保级成功不算；点人数弹出各类人数，同一玩家可计入多类。
    · 已到账：该结算月份三类奖金（升级奖金、月度工资、生日奖金）已到账的笔数和金额，含补发到账；点数字跳到活动奖励统计（结算月份 + 已到账 + 奖励类型全部），两边笔数、金额一致。
    · 状态：有单人结算失败时为橙色「部分完成」（可点击，失败人数看「结算失败」列），点击进入该月明细并筛选结算结果「未完成」；整次结算每 30 分钟自动重试、最多 3 次仍失败为「结算失败」，操作列「重新结算」补跑，补跑完成前等级配置锁定。
    · 明细：列出当月每位参与玩家的考核等级、历史最高、当月有效投注、保级投注、月度工资等级（k）、结算结果、结算后等级、月度工资、生日奖金（已到账正常显示，未到账浅色，没有「-」）、到账核算（应到账 / 实际到账 / 未领取）、失败原因、「查看记录」（跳活动奖励统计：该会员 + 结算月份）；可筛选、导出。
    · 重新结算与完成：未完成行红色显示，操作列「重新结算」（确认框，按考核月生效的配置补结算，写操作日志，成功后提示「补结算完成，请确认」）和「完成」（备注选填）；确认后该行显示补结算后的实际结果（绿色，小字「手动完成 · 操作人 · 时间」），列表失败人数减 1，减到 0 时状态变为「已完成」。没有补结算结果时提示「该玩家尚未补结算，不能完成」。「完成」只做确认标记，不改玩家数据；补结算生成的月度工资按正常规则生成待领取。
    · 告警：结算开始后 N 分钟（「结算告警时间」，默认 30）仍未完成时向技术和运营告警，单人重试结束后另发汇总告警。PRD 7.5、规则 N14–N19 月度结算
  7. 月度结算口径：k = 当月有效投注达到保级投注的最高等级（不超过历史最高 H，一级都没达到为 VIP0），C = 考核等级。k ≥ C：次月等级 = k（k = C 为保级成功，k > C 为恢复，可一次恢复多级）；k < C：次月降 1 级。三种情况都按 k 级生成待领取的月度工资，k = VIP0 不生成。明细示例：H = C = VIP5、投注 ₱30,000 → 降为 VIP4、发 VIP2 ₱12；H = VIP5、C = VIP2：₱80,000 → 恢复 VIP4、发 ₱28，₱180,000 → 恢复 VIP5（不超过 H）、发 ₱38；C = VIP0、H = VIP3、₱45,000 → 恢复 VIP3、发 ₱18。PRD 规则 N14 月度工资等级 k 与保级成功、N15 未保级与降级、N16 降级后恢复、N17 VIP0
  8. 表内修改与保存：在输入框直接修改，点表格下方「保存」一次提交整张表；门槛表、奖金表保存须谷歌验证码，影响预览试算完成前「确认保存」置灰。升级奖金、生日奖金按生成时配置；保级投注、月度工资的修改从下一个自然月起生效，不影响本月考核。两人同时保存时，后保存的提示「配置已被他人修改，请刷新后重试」（门槛表、奖金表、等级列表共用一个版本号）。PRD 7.2、规则 N11 门槛修改后的重算、N43 配置生效时间 · F01-02 表内修改与保存

  14. VIP领取奖励（= VIP 体系开关）：上线时关闭。
    · 第一次开启：立即执行上线结算——按累计定级，写入初始数值（含当月有效投注）；已到达的等级不发升级奖金、不弹窗；为生日在上线当天及以后（同月）的玩家生成生日奖金；不发月度工资。次月结算时间（默认 1 日 13:00）照常结算上线当月。上线结算只有这一次，生成的记录归上线当月；结算记录不新增行，上线当月一行同时包含上线结算和次月月度结算的数据。确认框里的人数和金额为示意数，正式环境按试算结果显示。
    · 再次开启：按当前累计重新核算全部玩家的等级（只升不降，历史最高同步）；关闭期间达到的等级记「不发放（重新开启核算）」，不发升级奖金、不弹动画；确认框显示预计升级人数，试算完成后才能确认。
    · 关闭：停止生成新奖金，已生成未领取的在原有效期内仍可领取。

  16. 不设审核、领取方式：没有审核节点。
    · 手动领取（默认）：三种奖金生成「待领取」记录，玩家领取即到账，流水倍数按奖金生成时的值。升级奖金在升级确认弹窗点「领取奖金」或在对应等级卡「查看详情」弹窗里领取；月度工资、生日奖金在当前等级卡「查看详情」弹窗里领取。
