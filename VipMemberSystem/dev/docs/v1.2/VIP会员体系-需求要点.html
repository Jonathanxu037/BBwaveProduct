VIP会员体系-v1.2-需求要点

版本：v1.2端：H5、iOS 原生、iOS Flutter、安卓 Flutter、管理后台依据：需求开发 PRD 文档

一句话需求

把现有【用户管理 › 会员等级】（LEVEL）模块改造为 VIP 体系：后台菜单改名「VIP会员等级配置」，前台等级中心（Level Center）改为「VIP中心」。
  • 等级：默认 VIP1–VIP24、SUPER VIP 共 25 个 VIP 等级，门槛和奖金可改，可新增、删除等级（不设数量上限，增删后全部玩家重算等级）；未达到 VIP1 的玩家为 VIP0（等级值 0）；前台按段位分层级。
  • 升级：累计有效投注和累计充值同时达标即实时升级，每级生成一次升级奖金。
  • 月度结算：次月结算时间（默认 1 日 13:00，GMT+8）按当月达到保级投注的最高等级 k（不超过历史最高）生成月度工资；未保级次月只降 1 级；降级玩家可一次恢复多级。
  • 生日奖金：金额按生日所在月份结算后的等级确定，生日当天起可领；只认第一次 KYC 审核通过的出生日期。
  • 领取：三种奖金默认由玩家手动领取，共用「领奖有效期」（默认 15 天），过期作废；不设审核，大额补发、放行和关键配置修改须第二人审批（规则 N58「第二人审批」）。
  • 前台：不显示结算状态、日期、时间（规则 N12 ⑤，Q59「前台不显示结算」），不显示任何与流水有关的内容（Q60「前台不显示流水」）。
  • 上线：原 LEVEL 和旧版 VIP 体系（【用户管理 › VIP特权】、系统参数「新版VIP特权状态」、旧版「VIP活动」）被完全替换；上线时只按累计定级，已到达的等级不发升级奖金；旧体系未到账的奖励一律作废（用户 10-28 定）。

业务流程

1
上线开启：核对门槛表和奖金表 → 版本发布（去掉原 LEVEL 和旧版 VIP 体系，未到账旧奖励作废）→ 运营开启「VIP领取奖励」→ 立即执行上线结算：按累计定级、写入初始数值（含当月有效投注），不发升级奖金和月度工资，为上线当月生日的玩家生成生日奖金 → 次月结算时间照常结算上线当月。建议每月 5 日前开启（规则 N26 VIP 体系开关与上线结算；Q38 上线当月的结算、Q39 上线首月的生日奖金）。上线结算的记录归上线当月，结算记录中该月一行包含两次结算的数据。
↓
2
累计：充值成功、注单结算 → 更新累计充值、累计有效投注、当月有效投注。
↓
3
升级：两项同时达标 → 立即升级 → 逐级生成升级奖金（待领取）→ 弹 3 秒升级动画 → 回到平台页面弹确认弹窗，点「领取奖金」领取（详见 F08-01）。
↓
4
月度结算：结算时间到 → 算 k → 定次月等级（保持 / 降 1 级 / 恢复到 k）→ 生成 k 级月度工资（待领取），发站内信和推送 → 玩家在当前等级「查看详情」弹窗领取；设为自动领取时结算完成即到账。
↓
5
生日：生日所在月份的月度结算完成时按结算后等级生成 → 按后台设置发生日短信提醒 → 生日当天 00:00 起在当前等级「查看详情」弹窗领取；设为自动领取时当天到账。

月度结算分支（C = 考核等级，即月末 23:59:59 的当前等级；k = 当月有效投注达到保级投注的最高等级，不超过历史最高，都未达到为 VIP0）：

A - k = C

保级成功，次月保持 + k 级月度工资生成待领取（自动领取时直接到账），发站内信、推送

B - 降过级且 k > C

次月直接恢复到 k + k 级月度工资可一次恢复多级，最多到历史最高；不发升级奖金、不弹动画

C - k < C

次月降 1 级 + k 级月度工资k = VIP0 不发；VIP1 降为 VIP0

D - VIP0（历史最高 ≥ VIP1）

同一公式：k ≥ VIP1 → 次月到 k得 k 级月度工资；k = VIP0 保持 VIP0

参与资格分支：

A - 未完成 KYC（「KYC 限制」开启时）

只累计、不参与完成 KYC 时按累计定级，补发已达到等级的升级奖金（见 F03-03）

B - 风控暂停

等级照算，奖金暂停发放、不能领取不发 VIP 通知；运营放行（恢复待领取）或作废（见 F06-03）

C - 奖金待领取

玩家手动领取（默认），过期作废不设审核；有效期见 F02-03；后台可按奖金类型改为自动领取，生成即到账

等级状态示意：

VIP0累计达标 →VIP n（当前 = 历史最高）保级失败 →VIP n−1（当前 < 历史最高）当月达到 VIP n 保级投注（得 VIP n 月度工资）→次月直接回到 VIP n（可一次恢复多级）累计超过历史最高 →立即升到新等级

要做什么

F01-04新增与删除等级查看 PRD

要做什么
  • 新增：点 VIP0 行「新增」→ 表格最下方加一行新的 SUPER VIP，原 SUPER VIP 顺延为 VIP25；新行三项门槛必填且大于上一级，保存前可「取消」；一次只能新增 1 行，不设等级数量上限。点「保存」后，影响预览列出新增、改名和重算后升到新等级的人数，并在预览里填写新等级的升级奖金、月度工资、生日奖金（默认 0，范围 0–9,999,999.99）；填谷歌验证码确认后门槛和奖金同时生效，之后达到新等级的按填写的升级奖金生成待领取。
  • 删除：被删等级的玩家改为新的 SUPER VIP；降级玩家历史最高为被删等级的，下调为按累计能满足的最高等级（不低于当前等级）；记「等级配置调整」，不算降级、不弹窗、不发站内信。
  • 重算（规则 N55「新增、删除等级后的等级重算」，按全量重算任务执行）：只处理等级因重算改变的玩家，一律看重算前历史最高（H0）的升级奖金记录：未领取的系统作废，为重算后的历史最高生成 1 笔「等级调整补偿」（金额 = min(新配置, 被作废金额)，该等级已有任何记录的不生成，一律先待领取）；已领取、已过期等不生成。领过被删等级升级奖金的玩家，到达的第 1 个新增等级记「不发放（已领被删等级）」，再升照常发。本年已生成的生日奖金不在新等级再生成；已发奖金不追回。
  • 限制：VIP0 不能删除；至少保留 1 个 VIP 等级；有未保存的新增行时不能删除；结算期间不能新增、删除。
  • 前台刻度、等级卡、等级表按实际等级数显示；段位按新等级数立即重新分配，影响预览和确认框提示「前台段位将重新分配」（见 F07-06）。
公式
VIP 等级数 ≥ 1（不设上限）；等级名：第 i 级（1 ≤ i < 等级数）＝ VIPi，最高一级 ＝ SUPER VIP

F02 奖励参数

F02-01VIP 体系开关与上线结算查看 PRD

要做什么
  • 开关：【VIP会员等级配置 › VIP会员等级奖励配置】顶部「VIP领取奖励」（开启 / 关闭，由「活动状态」改名，用户 10-28 定），即 VIP 体系开关；系统参数「新版VIP特权状态」去掉。上线时为关闭，版本发布后由运营开启。
  • 开启或关闭：确认框 + 谷歌验证码 + 写日志。
  • 第一次开启（上线结算）：只按截至开启时刻的累计有效投注和累计充值定级，不参考原 LEVEL 和旧版 VIP 等级；已到达的等级记「不发放（上线结算）」，不弹窗、不补发。
  • 旧奖励作废：版本发布时，原 LEVEL（升级奖励、生日礼包）和旧版 VIP（会员福利，含旧版 VIP活动未领取或待派奖审核的福利）未到账的一律作废、不能再领；已到账的不追回；上线前导出待作废清单留档。
  • 旧版 VIP 体系整体去掉：【用户管理 › VIP特权】菜单（旧版成长值、限额与返水、成长值记录、会员福利记录）和【活动配置 › 活动列表】中的旧版「VIP活动」，数据不迁移。
  • 关闭期间：停止升级、结算、生成新奖金和 VIP 通知，事后不补；已生成未领取的奖金在原有效期内仍可领取（用户 10-29 定）。
  • 再次开启：按当前累计重新核算全部玩家等级（只升不降，历史最高同步）；关闭期间达到的等级不发升级奖金、不弹动画（Q13 再次开启重新核算、Q44 重新开启不发奖）；确认框显示预计升级人数，试算完成后才能确认。
  • 全量重算任务（规则 N59「全量重算任务」）：上线结算、再次开启、下调门槛、增删等级、「KYC 限制」切换都逐个玩家处理；状态执行中 / 已完成 / 失败；执行中锁定门槛表、奖金表、增删等级、「VIP领取奖励」「KYC 限制」和三项领取方式（提示「等级重算进行中，完成后才能修改」）；以任务结果为准；失败自动重试 3 次后告警；完成后写一条汇总日志；通知按批发送。
公式
上线结算：当前等级 ＝ 历史最高 ＝ 截至开启时刻累计有效投注和累计充值同时满足门槛的最高等级

F02-02KYC 限制开关查看 PRD

要做什么
  • 由原「是否需要 KYC」改造，默认开启，开关后面不显示提示语。
  • 开启时三类奖金都要求完成 KYC；关闭时等级、升级奖金、月度工资不要求 KYC，生日奖金仍须有 KYC 出生日期（规则 N24「KYC 限制关闭」）。
  • 切换：确认框 + 谷歌验证码，日志写「KYC 限制：开启 → 关闭」；按全量重算任务执行。
  • 开启 → 关闭（规则 N25「KYC 限制切换」）：不补发任何奖金；未定级的玩家按切换时累计定级，已达到的等级记「不发放（KYC 限制关闭定级）」，不弹窗、不发站内信（Q51 已定）；之后新达到的等级照常发奖。
  • 关闭 → 开启：未完成 KYC 的玩家等级冻结，未领取的奖金改为暂停发放（原因「KYC 限制开启（未完成 KYC）」）；完成 KYC 后的处理见 F03-03。

F02-04免打扰与短信模板查看 PRD

要做什么
  • 位置：「VIP会员等级奖励规则」参数区在「VIP领取奖励」之后、奖金表之上；各行标题定宽、控件对齐，不换行、不重叠（用户 10-30 定）。
  • 领取方式：「升级奖金领取方式」「月度工资领取方式」「生日奖金领取方式」三项，单选自动 / 手动，默认手动；切换时弹确认框，只影响之后新生成的奖金，即时生效并写日志（规则 N53 领取方式）。
  • 去掉原「生日礼包发放方式」「升级奖励发放方式」，不设强制审核（规则 N30 不设审核）；领奖有效期见 F02-03。
  • 免打扰：开始、结束时间（默认 21:00–10:00），开始 = 结束视为不设。
  • 短信两行「生日短信提醒」「奖金到账提醒」：勾选框 + 短信模板下拉，勾选才发送。
    • 下拉只列【公告管理 › 短信模板列表】中「个人」类型的模板；没有个人模板时显示「暂无可用模板，请先创建个人短信模板」，不能保存；未勾选时下拉置灰；勾选但未选模板，保存时提示「请选择短信模板」。
    • 「生日短信提醒」另有发送时间点下拉：生日所在月 1 日 / 前三天 / 前一天 / 当天，默认当天。
