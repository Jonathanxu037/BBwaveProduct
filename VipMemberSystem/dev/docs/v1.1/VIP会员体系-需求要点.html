VIP会员体系-v1.1-需求要点

版本：v1.0端：管理后台（后台前端 + 后端）、C 端（H5、iOS 原生、iOS Flutter、安卓 Flutter）依据：需求开发 PRD 文档

一句话需求

在管理后台【用户管理 › VIP特权】把旧版 VIP特权与新 VIP 体系合并：可新增、可关闭的 VIP 等级（默认 VIP1–SUPER VIP 25 级，按全局「计算方式」用累计金额双门槛或成长值判定）、VIP0 起始级别（可沿用普通会员级别）、VIP 奖励与全局参数、VIP奖品配置、按 VIP 等级的下注限额与返水，以及会员福利记录、VIP会员数据、等级变动记录、月度结算记录；后端实时升级并发升级奖励，每月 1 日按上月有效投注结算保级、降级和恢复，生日当天生成生日奖励；C 端等级中心展示普通用户卡与 VIP 等级卡、奖励详情、VIP 奖励表和规则；【用户管理 › 会员等级】改造普通会员（LEVEL）等级表、前台显示方式和奖励配置；实物奖品的领取、审核和发货由实体奖品管理需求负责。

业务流程

1
配置：选计算方式 → 设 VIP0（默认勾选沿用普通会员最高级）→ 配 VIP 等级门槛、奖励、奖品预占、限额与返水、全局参数
↓
2
第一次开启：导出存量初始化预览抽查 → 开启「VIP 体系状态」→ 存量初始化（已到达的等级不发升级奖励）→ 开始实时判定
↓
3
累计：自行充值成功、注单结算 → 累计充值、累计有效投注、当月有效投注（成长值方式另算 VIP 成长值）
↓
4
升级：达到更高开启等级的升级标准 → 立即升级 → 首次到达的每级生成升级奖励 → 自动到账或待领取 → 升级弹窗
↓
5
月度结算：每月最后一天 23:59:59（GMT+8）截止 → 次月 1 日结算保级、降级、恢复（见分支一）→ 保级短信
↓
6
生日：生日前一天和当天 10:00 短信 → 当天 00:00 按当前等级生成生日奖励 → 玩家在生日卡片或奖励详情领取
↓
7
记录与运营：会员福利记录（放行、作废、补发、审核）、月度结算记录（重跑失败）、VIP会员数据、等级变动记录

分支一：月度结算（按结算时的当前等级考核上月整月）

保持当前等级月内有升级的按升级后的等级考核

↓

↓

↓

次月降 1 级VIP1 未达到 → 变为普通用户；历史最高等级不变

D - VIP1 降下来的普通用户

↓

次月回到 VIP1不发保级奖励、不重发升级奖励，只计恢复人数

分支二：VIP0「沿用普通会员级别」

A - 勾选（上线默认）

VIP0 ＝ LEVEL nn 默认为普通会员当前最高级；LEVEL n 之上一级为 VIP1

↓

B - 不勾选

↓

两边奖励、返水各自达标都可领例：LEVEL 10 奖励 100 ＋ VIP2 奖励 10 ＝ 110

↓

分支三：VIP 体系状态

A - 第一次开启

↓

B - 关闭

↓

↓

F01-01VIP 等级配置查看 PRD ›

要做什么
  • 【用户管理 › VIP特权 › VIP特权】分 4 个子页签：VIP等级配置、VIP全局参数、VIP奖励配置、下注限额与返水；切换子页签不丢失 VIP 全局参数未保存的修改
  • 「VIP等级配置」最上方单选「计算方式：累计金额 / 成长值」，必选其一，默认累计金额；所有等级统一按所选方式判定
  • 等级表：VIP0 行固定在最上（见 F01-06），下面默认 25 行 VIP1–VIP24、SUPER VIP；列为 VIP 等级（L 号 L1–LN，按顺位，悬停显示「配置 ID：CFG-xx」）、等级名称、门槛（累计金额：累计有效投注、累计充值、每月保级投注；成长值：成长值最低要求、保级所需成长值（每月）、降级保留成长值比例（%））、状态（开启 / 已关闭 / 关闭待复核；不符合标准的已关闭等级另标「不符合标准」）、操作（修改设定、关闭 / 开启）
  • 表头分「升级标准（先填）」「保级标准（后填）」；表格只读，修改只走「修改设定」弹窗：等级名称、当前方式门槛（必填）、另一方式门槛（选填，供切换前补齐）、谷歌验证码，确定即生效、写日志
  • 两种计算方式的门槛各存一套，切换后旧方式的门槛保留，切回时显示上次保存的值
  • 后端按等级配置 ID 判定和记录；L 号、等级名称只用于展示；SUPER VIP 只是等级名称，最高等级 ＝ 当前开启的最高 L 号
  • 等级名称必填、≤ 20 字符、不重复；金额只收 ≥ 0 的整数（₱600K 录 600000）
  • 某级升级标准未填或无效时，该级保级输入框置灰，占位「请先设置升级标准」
  • 修改设定、新增等级、表格、切换计算方式四处校验一致，服务端同样校验；提示「{等级} 的{字段}需大于上一级 Lk {上一等级} 的 {数值}」「{等级} 的{字段}需小于下一级 Lk {下一等级} 的 {数值}」「保级标准需小于升级标准」「等级名称必填」「等级名称不能超过 20 字符」「等级名称不能重复」「请输入 ≥ 0 的整数」
  • 切换计算方式：先检查新方式门槛是否齐全并满足校验 → 不齐全弹「不能切换计算方式」，列出缺的等级和字段，只有「知道了」；VIP0 勾选沿用时从成长值切回累计金额，开启中的等级累计有效投注不高于 VIP0（沿用的 LEVEL n）即不符合标准，同样弹此窗并逐个列出，先提高门槛或关闭这些等级后才能切换，不勾选时不检查 → 检查通过弹「切换计算方式 · 影响预览」（按门槛下调处理，内填谷歌验证码）→ 直接生效或进入待复核；日志写「计算方式：A → B」；切到成长值且成长值规则未配置齐时，先在弹窗里填写并保存规则（见 F01-07）
  • 门槛下调（累计有效投注、累计充值、成长值最低要求变小）先弹影响预览，按 F02-05 复核和重算；有待复核时不能修改 VIP 等级配置（修改设定、新增等级、开启、切换计算方式）
  • 默认值取原方案：VIP1 累计有效投注 600,000、累计充值 50,000、每月保级投注 100,000；SUPER VIP 2,000,000,000、80,000,000、60,000,000
  • 后台菜单：【用户管理 › VIP特权】页签为 VIP特权、成长值记录（现有，不改）、会员福利记录、VIP会员数据、等级变动记录、月度结算记录；【用户管理 › 会员等级】页签为会员等级配置、会员等级奖励配置、活动奖励统计（只含普通会员奖励记录）。左侧【实体奖品管理】属于实体奖品管理需求，本需求不开发；顶栏不显示「库存告急」「待派发奖品」
  • 后台页面统一写「VIP 等级」，不加「（新）」；时间一律按 GMT+8 显示和计算，表头缩短后在表格下方注明「表中时间均为 GMT+8」，导出文件列名不变
  • 谷歌验证码直接放在操作弹窗里，点「确定」时与其他字段一起校验：为空提示「请输入谷歌验证码」，错误提示「谷歌验证码错误」，弹窗不关、内容保留
  • 所有配置修改都在弹窗内直接保存，没有暂存和整表「保存 / 撤销」；配置表只读显示（金额千分位、比例带 %、未填红字「未配置」），按行「修改」或勾选后「批量修改」（全选只选当前页，翻页或改条数清空勾选并提示，批量弹窗不分页、可「统一填写」一列）
  • 开 / 关类配置用拨杆开关（开蓝色滑块在右、关灰色滑块在左，旁显状态文字，键盘可切换）；二选一但不是开 / 关语义的（领取方式、计算方式、流水计入游戏范围、KYC 认证要求）用单选
  • 「?」帮助紧跟在对应文字后面同一行，内容一两句写清是什么、怎么填。上线页面只显示运营操作内容：原型的规则批注、模拟场景、模拟操作和「※ 此内容仅作为需求说明」说明块不开发
  • 按钮级权限码服务端校验，授权后重新登录生效；所有保存、开关、复核、放行、作废、补发、审核、重跑写操作日志（操作人、时间 GMT+8、对象、修改前后值）
  • 只适用于 789Bingo：VIP 配置、会员数据、结算任务按站点隔离
判定条件
可保存 ＝ 当前方式门槛均为 ≥ 0 的整数
　且 累计有效投注、成长值最低要求、每月保级投注、保级所需成长值 都 ＞ 上一级 且 ＜ 下一级（已关闭的等级也参与比较）
　且 上一级 ≤ 累计充值 ≤ 下一级（可相等）
　且 每月保级投注 ＜ 本级累计有效投注；保级所需成长值 ＜ 本级成长值最低要求
　且（勾选沿用、累计金额方式）开启中的等级累计有效投注 ＞ VIP0（LEVEL n）；已关闭的不符合标准等级不受此限，见 F01-06
　且 等级名称非空、≤ 20 字符、不重复 且 谷歌验证码正确

F01-05新增与关闭 VIP 等级查看 PRD ›

要做什么
  • 等级表上方蓝色主按钮「新增VIP等级」：弹窗填「新增到第几级」（正整数，L1 ~ 当前最高等级 + 1）、等级名称（默认按新顺位 VIPn，改过后不再自动变化）、当前方式门槛（必填，旁边显示该位置的上下限）、另一方式门槛（选填）、谷歌验证码；状态默认开启
  • 位置填好后同一弹窗显示「原 Lk–LN 依次顺延为 Lk+1–LN+1」；填「当前最高等级 + 1」时加在最高级之上，没有顺延、没有上限
  • 校验：位置为空「请填写新增到第几级」，非正整数「请输入正整数」，超范围「超出范围：请输入 1–N」；门槛为空「必填」，不在上下限内「不在该位置的上下限内：须大于 X 且小于 Y」（累计充值「不低于 X 且不高于 Y」），相邻两级相差不足 2 时提示没有可填的整数；保级 ＜ 升级；勾选沿用（累计金额方式）时新等级累计有效投注须高于 VIP0，否则拦截（见 F01-06）；成长值规则未配置齐时成长值门槛置灰
  • 通过校验 → 影响预览（列出 L 号顺延，按门槛下调处理）→ 不需复核直接生效，需复核进入待复核、复核通过时生效
  • 生效后：后续等级 L 号 +1，默认名称 VIPn 随之改为 VIPn+1，自定义名称（如 SUPER VIP）不变；分配新的配置 ID；VIP 奖励配置、下注限额与返水、VIP奖品配置在相同位置生成该级条目（红字「未配置」，表格上方提示「新增 VIPn 的奖励 / 返水 / 奖品未配置，请用『修改』补填」）
  • 条目未配置期间：该级不发升级、保级、生日奖励；返水按 0；下注限额按平台默认；没有可领取的奖品、不预占库存
  • 玩家按配置 ID 判定：所在等级不变，显示的 L 号和默认名称随顺位变化；已越过新等级的玩家不补发新等级的升级奖励；等级数不限；已保存的等级不能删除，只能关闭
  • 关闭：点「关闭」→「关闭等级 · 影响预览」（该级当前人数、按历史累计归入 VIPx 的人数、降级玩家上移到 VIPy 的人数、需发升级奖励的人数和金额、释放的奖品预占）→ 弹窗内谷歌验证码「提交复核」→ 状态「关闭待复核」，期间仍按开启运行
  • 复核：另一名有「复核 VIP 门槛」权限的人员打开「复核关闭等级」（按复核时刻重新试算）→ 通过才生效，驳回保持开启；关闭一律复核，不看复核金额阈值；提交人不能复核自己（「不能复核自己提交的修改」）；同一时间只有一条待复核；在修改设定里把状态改为关闭时同样走此流程，且不能同时改其他设定（「关闭等级要单独提交复核：请只改状态，或先保存其他修改再关闭」）
  • 关闭生效时重新归级：当前等级 ＝ 历史最高的玩家按历史累计（成长值方式用成长值）判定所属开启等级，降到更低等级不发奖、不回收；降过级的玩家只上移到当前等级之上的下一个开启等级，不越级，该级升级奖励未领过的按领取方式发放；每人写一条等级变动记录「重新归级 / 等级关闭」；历史最高等级仍记原等级，后台显示「VIPx（已关闭）」；自动释放该级奖品剩余预占
  • 关闭后升级判定和降级恢复的目标都跳过该级；前台刻度、等级卡、VIP 奖励表不显示该级（「关闭待复核」期间照常显示）
  • 再次开启不复核，弹窗内谷歌验证码后生效；「不符合标准」的等级不能开启（见 F01-06）；该级配了奖品时校验库存：可分配余量（不含本行）≥ 原剩余预占 → 开启并恢复预占；不足 → 保持关闭，提示「当前奖品库存不足，请调整库存或更换奖励」
判定条件
新增位置 ∈ [1，当前最高 L 号 ＋ 1]
新等级门槛：前一级 ＜ 累计有效投注 / 成长值最低要求 / 每月保级投注 / 保级所需成长值 ＜ 原该级；前一级 ≤ 累计充值 ≤ 原该级
关闭归级：当前 ＝ 历史最高 → 按历史累计重判；当前 ＜ 历史最高 → 上移到当前等级之上的下一个开启等级
例：关闭 VIP13，maya_r（历史最高 VIP14、当前 VIP13）上移到 VIP14，已领过 VIP14 升级奖励不再发；carlo_v（当前 ＝ 历史最高 ＝ VIP13）按历史累计归入 VIP12，不发奖

F01-06VIP0 与沿用普通会员级别查看 PRD ›

要做什么
  • VIP 等级配置表最上方固定一行 VIP0（L0，不计入分页），标准随计算方式显示，只读，用「修改设定」修改（谷歌验证码、直接保存、写日志）
  • 勾选「沿用普通会员级别」（上线默认勾选）：下拉列 LEVEL 1 ~ 普通会员当前最高级（显示有效投注累计值），默认当前最高级，所有级别可选，选择时不拦截
  • VIP0 标准：累计金额方式下累计有效投注自动带入 LEVEL n 的有效投注累计值（只读），累计充值为 0；成长值方式下成长值最低要求另填、必填，VIP1 成长值最低要求须大于 VIP0（保存时校验），不使用「不符合标准」
  • VIP0 不设保级、不降级；不发 VIP 奖励，没有 VIP 下注限额和 VIP 返水（按普通会员现有规则）；VIP 奖励配置、下注限额与返水、VIP奖品配置三张表不出现 VIP0 行
  • VIP0 行下方提示（上线显示）：勾选时「VIP0 不发 VIP 奖励；如需给 VIP0 奖励，请在【会员等级】普通会员对应等级（沿用的 LEVEL n）设置奖励」；不勾选时「未达到 VIP1 的玩家没有 VIP 等级，不发 VIP 奖励；普通会员级别的奖励和返水照【会员等级】配置发放，两边各自达标都可领取」
  • 删除 LEVEL n 之后的级别：在开启 VIP 体系时执行（第一次开启确认弹窗列出「将删除 LEVEL n+1 ~ 最高级」）；开启前保存的只是选择；已开启后再改沿用级别，弹窗提示会再删除一次，须勾选「我已确认」（未勾选提示「请勾选确认删除」）并填谷歌验证码，保存即删除；关闭期间改沿用级别只保存，重新开启时删除；n 为最高级时不删除
