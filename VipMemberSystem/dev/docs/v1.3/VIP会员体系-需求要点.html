VIP会员体系-v1.3-需求要点

版本：v1.3端：H5、iOS 原生、iOS Flutter、安卓 Flutter、管理后台依据：需求开发 PRD 文档

一句话需求

把现有会员等级（LEVEL）模块改造为 VIP 体系：玩家按累计有效投注和累计充值实时升级，按当月有效投注每月结算每月奖金和保级、降级，可领取升级、每月、生日三种奖金；前台提供「VIP中心」，后台在「VIP会员等级配置」管理等级、奖金、领取规则和通知。
总原则：与平台已有功能重复的部分（如免打扰与发送时段限制、短信发送与失败处理、站内信和推送通道、操作日志、结算告警等），以平台现有逻辑为准，本需求的对应内容可不开发；VIP 会员体系本身（等级、升级奖金、每月奖金、生日奖金、结算、领取、暂停与放行、作废与补发等）是本需求的核心，必须按本需求的逻辑开发（用户 2026-11-09）。

业务流程

1
上线开启：核对等级表（门槛和奖金）→ 版本发布（去掉原 LEVEL 和旧版 VIP 体系，未到账旧奖励作废）→ 运营开启「VIP会员系统」→ 立即执行上线结算：按累计定级，不发升级奖金和每月奖金，为生日在上线当天及以后（同月）的玩家生成生日奖金 → 第一次开启满 28 天后的月度结算时间点起正常结算；之前的结算时间点只生成生日奖金；再次开启不重新计 28 天（见 F02-01 VIP 体系开关与上线结算）。
↓
2
累计：充值成功、注单结算 → 更新累计充值、累计有效投注、当月有效投注。
↓
3
升级：两项同时达标 → 立即升级 → 逐级生成升级奖金（待领取）→ 弹现网升级弹窗，有手动领取金额时点「领取」领取，未领取就退出的下次进入平台补弹（见 F08-01 现网升级弹窗）。
↓
4
月度结算：结算时间到 → 算 k → 定次月等级（保持 / 降 1 级 / 恢复到 k）→ 生成 k 级每月奖金（待领取），按「通知配置」发站内信和推送 → 玩家在当前等级「查看详情」弹窗领取；设为自动领取时结算完成即到账，发已到账通知。
↓
5
生日：生日所在月份的月度结算完成时按结算后等级生成 → 按后台设置发生日提醒短信 → 从生日和奖金生成日中较晚的一天起在当前等级「查看详情」弹窗领取（生日晚于生成日：生日 00:00 起；否则从生成时起）；设为自动领取时同一时点到账。

月度结算分支（C = 考核等级，即月末 23:59:59 的当前等级；k = 当月有效投注达到每月奖金标准的最高等级，不超过历史最高，都未达到为 VIP0）：

A - k = C

保级成功，次月保持 + k 级每月奖金生成待领取（自动领取时直接到账），按「通知配置」发站内信、推送

B - 降过级且 k > C

次月直接恢复到 k + k 级每月奖金可一次恢复多级，最多到历史最高；不发升级奖金、不弹升级弹窗

C - k < C

次月降 1 级 + k 级每月奖金k = VIP0 不发；VIP1 降为 VIP0

D - VIP0（历史最高 ≥ VIP1）

同一公式：k ≥ VIP1 → 次月到 k得 k 级每月奖金；k = VIP0 保持 VIP0

参与资格分支：

A - 未完成 KYC（「KYC 限制」开启时）

只累计、不参与完成 KYC 时按累计定级，补发已达到等级的升级奖金（见 F03-03 KYC 定级）

B - 风控暂停

等级照算，奖金暂停发放、不能领取升级弹窗照弹、不显示奖金；不发奖金短信、站内信、推送；运营放行或作废（见 F06-03 风控暂停与人工处理）

C - 奖金待领取

默认手动领取，按每笔记录的截止日期判断是否过期不设审核；有效期见 F02-03 流水与奖金有效期；后台可按奖金类型改为自动领取（升级、每月奖金生成即到账，生日奖金按生日与生成日中较晚的一天到账，配置变更批次除外）；每笔只按自己的截止日期过期，生成新奖金时不作废旧记录（见 F02-04 领取方式与通知配置）

D - VIP会员系统关闭

前台隐藏 VIP中心，停止 VIP 逻辑关闭时勾选的玩家待领取奖金直接到账，未勾选的作废；风控暂停、被中止结算月份已生成的、还没到可领日的生日奖金保持原状态；配置变更批次按勾选结果发放或作废；修改等级表须先关闭（见 F02-01 VIP 体系开关与上线结算）

等级状态示意：

VIP0累计达标 →VIP n（当前 = 历史最高）未达当前等级每月奖金标准 →VIP n−1（当前 < 历史最高）当月达到 VIP n 每月奖金标准（得 VIP n 每月奖金）→次月直接回到 VIP n（可一次恢复多级）累计超过历史最高 →立即升到新等级

F01-02表内修改与保存查看 PRD ›

要做什么
  • 三个配置页签独立保存：规则页点「保存规则配置」，只校验规则字段，统一列出改动并确认后生效；涉及KYC或流水倍数修改须谷歌验证码，领取方式及有效期只影响之后生成的记录，存量按原方式和截止日期处理。等级页点「保存等级配置」，只校验等级表，沿用影响预览、标红金额核对和谷歌验证码。通知页点「保存通知配置」，只校验和保存通知内容及免打扰设置，不需要谷歌验证码。任一页保存均不提交、不校验、不清空其他页签草稿；切换这三个页签保留草稿。取消、验证码错误、校验失败或保存失败均不提交，保留填写；保存中防重复提交，无改动不写日志。各配置独立检查版本，发生并发冲突提示「配置已被他人修改，请刷新后重试」，不覆盖其他人的结果。刷新页面恢复最近成功保存的值；离开整个页面不另加确认。等级试算失败或超时显示「试算失败，请重试」和「重试」，确认按钮保持置灰。修改等级表（门槛、三种奖金、每月奖金标准、新增 / 删除等级）须先关闭「VIP会员系统」：开启时等级表置灰，提示「请先关闭 VIP会员系统再修改」；关闭期间可以修改并保存，保存时只做影响预览试算并保存配置；作废、重算、生成奖金在重新开启时统一执行（见 F02-01）。只有等级表须先关闭，其他配置保持现方式。没有修改时提示「没有修改」。
  • 只有「VIP会员系统」总开关经确认框立即生效，不随任何保存按钮提交；「KYC 限制」、三项领取方式、领奖有效期随「保存规则配置」生效。
  • 本期不做单项修改弹窗、批量修改和「最后修改」列。
  • 月度结算时间后台可配置：每月 1–28 日的时、分，默认 1 日 13:00（GMT+8）。
  • 锁定：月度结算进行中、上月结算失败待补跑、全量重算任务执行中、关闭期间重新结算进行中，等级表输入框置灰，「新增」「删除」「保存等级配置」不可用；「KYC 限制」、三项领取方式、领奖有效期、月度结算时间置灰；流水倍数、结算告警时间和通知配置（含免打扰时段）仍可保存。页签顶部提示「月度结算进行中，结算完成后才能修改」「上月结算失败，补跑完成后才能修改」「等级重算进行中，完成后才能修改」，后面括号列出锁定项。结算状态变为「部分完成」即解锁。锁定期间「VIP会员系统」仍可关闭（只能关闭、不能开启）：须谷歌验证码和二次确认，关闭后中止当前的结算或重算任务。
  • 有未保存的新增行时，其他门槛输入框置灰，新增等级须单独保存。有未保存的修改时「新增」置灰，提示先保存或放弃；「VIP会员系统」开关确认后保留其他未保存修改；删除等级的确认框提示未保存修改将全部丢失。「VIP会员系统」开关的确认框点「取消」或 × 时恢复原值。
  • 生效：等级表在重新开启「VIP会员系统」时生效，其他参数保存即生效；升级奖金、生日奖金、流水倍数按奖金生成时的配置；每月奖金标准、每月奖金在重新开启时生效，还没结算的考核月份（含重新开启所在月）都按新值，已结算的不变。
  • 不设第二人审批：确认后执行（等级表保存后在重新开启时生效），不区分金额和变动比例；按权限控制，写操作日志。

F01-03递增校验与影响预览查看 PRD ›

要做什么
  • 三列门槛（累计有效投注、累计充值、每月奖金标准）逐级严格递增（新增行同样必填，且三项门槛都必须大于当前最高一级的对应门槛；新增只能加在最高一级之后，不支持插入中间）；不通过时出错的输入框标红，表格下方列出全部出错等级，不保存。
  • 保存前试算影响预览，试算完成后才能保存。试算失败时显示「试算失败，请重试」和「重试」，确认按钮保持置灰，关闭后输入保留（开启确认框的试算同样处理）。预览只列等级表的改动：修改内容（门槛、奖金、新增行整行；最多列 4 项，其余写「等共 n 项」）、重新开启时预计升级人数和升级奖金合计、每月奖金标准和每月奖金的修改对还没结算的月份生效、生日奖金变化的等级和人数、各级奖金变动比例和影响金额；新增等级时另列前台段位重新分配结果（重新开启后按新的等级数重新分配）。流水倍数的修改在「保存规则配置」确认框列出。
  • 金额核对提醒（不是审批）：影响预览中，奖金单项变动超过 ±50%、或高于高一级同类奖金（如 VIP3 升级奖金高于 VIP4）的数值标红，提示「变动较大，请核对」；门槛任一列下调超过 20% 也标红；原值为 0 的不按比例，只按高于高一级 / 低于低一级判断；新增行奖金为 0 也标红；有标红项时须勾选「已核对标红的奖金」才能确认保存。本次配置变更批次（门槛下调生成的升级奖金和等级调整补偿）合计超过 ₱100,000 时标红，须勾选「已核对金额」才能保存。
  • 下调门槛后，在重新开启「VIP会员系统」时按全量重算任务对全部玩家重算一次升级（只升不降）；新到达等级的升级奖金一律先「待领取」（自动领取也一样，前台按手动领取显示「领取」、截止日期和红点，进待领取奖金通知；有效期按该类领奖有效期天数从重新开启当天起算，第 18 批 X02），重新开启后 24 小时内可整批作废（见 F06-03 风控暂停与人工处理）。

校验 ＝ 每级门槛 > 低一级门槛（VIP1 > 0）；奖金不要求递增

F01-04新增与删除等级查看 PRD ›

要做什么
  • 新增：点 VIP0 行「新增」→ 等级表最下方加一整行新的 SUPER VIP，原 SUPER VIP 顺延为 VIP25；新行三项门槛必填，且都必须大于当前最高一级的对应门槛（不支持插入中间），升级奖金、每月奖金、生日奖金在同一行填写（默认 0，0–9,999,999.99，最多 2 位小数，不合法时标红、不保存），影响预览里不单独填写；保存前可「取消」去掉整行；一次只能新增 1 行，不设等级数量上限。点「保存等级配置」弹影响预览（列出新增、改名和重算后升到新等级的人数），填谷歌验证码「确认保存」后保存配置，重新开启时门槛和奖金一起生效：重新开启时因新增等级新达到的，只按等级调整补偿处理（见下方「重算」），重算前历史最高那一级的升级奖金已领取的不再发；重新开启之后玩家自己达到新等级的，按填写的升级奖金生成待领取。新增、删除都只能在「VIP会员系统」关闭期间操作。
  • 删除：只有最高一级 SUPER VIP 行有「删除」，确认框填谷歌验证码后保存、不能撤销，玩家等级调整和奖金作废在重新开启时执行；等级表删除整行（门槛和奖金），原次高级改名 SUPER VIP；被删等级的玩家改为新的 SUPER VIP；降级玩家历史最高为被删等级的，下调为按累计能满足的最高等级（不低于当前等级）；记「等级配置调整」，不算降级、不弹窗、不发站内信。
  • 重算（重新开启时按全量重算任务执行）：新增等级时，只处理等级因重算改变的玩家，看重算前历史最高（H0）的升级奖金记录：未领取的系统作废，为重算后的历史最高生成 1 笔「等级调整补偿」（金额 = min(新配置, 被作废金额)，该等级已有升级奖金记录的不生成，一律先待领取）；已领取、已过期等不生成。删除等级时被作废的升级奖金不补偿，不以新的最高级是否已有记录为条件（用户 2026-11-04）；删除确认框写「被作废的升级奖金不补偿」。领过被删等级升级奖金的玩家，到达的第 1 个新增等级记「不发放（已领被删等级）」，再升照常发。本年已生成的生日奖金不在新等级再生成；已发奖金不追回。
  • 限制：VIP0 不能删除；至少保留 1 个 VIP 等级；有未保存的新增行时不能删除；「VIP会员系统」开启期间、结算期间、全量重算任务执行中不能新增、删除（按钮置灰，悬停显示原因）。
  • 新增的等级：从重新开启时起参与还没结算的月份的考核（第 18 批 X03）；已删除的等级不再作为每月奖金等级 k 的候选。
  • 前台刻度、等级卡、等级表按实际等级数显示；段位在重新开启「VIP会员系统」后按新的等级数重新分配，影响预览和确认框提示「前台段位将重新分配」（见 F07-06 段位层级）。
公式
VIP 等级数 ≥ 1（不设上限）；等级名：第 i 级（1 ≤ i < 等级数）＝ VIPi，最高一级 ＝ SUPER VIP

F02-01VIP 体系开关与上线结算查看 PRD ›

要做什么
