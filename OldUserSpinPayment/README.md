# 老用户充值转盘功能需求 · v1.0

老用户充值转盘的活动配置里，「范围配置 › 充值渠道 › 充值方式」下拉由技术新增「原生Gcash」选项，交互和生效方式与现有选项一致；其他沿用平台现有规则。后台前端、后端开发；C 端只做回归，是否需要发版由技术研发决定。

## 目录说明

| 路径 | 内容 |
|---|---|
| `index.html` | 入口页：需求概览和目录 |
| `prototype/admin/` | 后台原型：活动管理（「活动配置」Tab，含活动列表和创建 / 编辑表单） |
| `docs/老用户充值转盘-需求要点.html` | 需求要点：一句话需求、业务流程、开发功能点（要做什么、公式、涉及端） |
| `docs/老用户充值转盘-需求开发PRD文档.html` | 需求开发 PRD 文档 |
| `docs/老用户充值转盘-开发自查清单.html` | 按设计、前端、后端、测试角色的开发自查清单 |
| `docs/老用户充值转盘-后台操作手册.html` | 给运营和客服的后台操作手册 |
| `docs/老用户充值转盘-客服QA.html` | 客服 QA（中英双语）：适用范围、本次改动、核查步骤、常见问答 |
| `docs/老用户充值转盘-需求修改总结.html` | 运营默认页：最新一版运营需求修改意见的内容和产品回复总结 |
| `docs/老用户充值转盘-运营需求确认.html` | 运营需求确认：左侧上方切换查看原型、下方填写意见（可上传或粘贴截图）并添加到右侧意见列表；勾选后确认提交为一个版本（首次 v1.0，每次提交 +1.0，每次修改 +0.1）。已提交的版本、产品回复和补充保存在云端，换电脑、换浏览器都能看到。产品回复后，这条意见不能再修改或删除，产品的回复和结论也不能改，只能补充（运营和产品都能补充，封板后只有产品能补充）；重新打包上传不会删除或覆盖这些记录。只对产品和运营开放：运营只能查看产品回复和是否修改，产品可以填写；开发和报告站点里没有本页 |
| `assets/` | 共用样式、目录栏脚本、目录数据（`nav-data.js`）、原型修改标注数据（`proto-changes.js`，首版 v1.0 为空）、原型公共脚本（`proto.js`：跨页模拟状态、模拟操作面板、清空原型状态）和运营意见云端读写（`oc-store.js`） |
| `.nojekyll` | 让 GitHub Pages 按原样发布 |

「云端接口」（运营需求修改意见的接口代码 `oc-worker.js` 和部署、更新、常见问题说明）不在本压缩包里，也不上传到 GitHub 仓库；它单独输出在与需求包同级的「老用户充值转盘功能需求-云端接口」文件夹，由产品负责人保管。所有需求共用一个接口，已部署时不用重复部署。

## 按角色访问

需求包发布成四个角色站点，每个角色一个文件夹，各自的访问链接只发给对应的人：

| 角色 | 包含人员 | 文件夹 | 访问链接 | 能看的页面 |
|---|---|---|---|---|
| 产品 | 产品经理、行政管理人员 | `pdm/` | `<Pages 地址>/<仓库名>/pdm` | 全部页面；默认页是需求与原型中心（含需求文档架构图、运营需求修改记录）；顶栏可切换运营、开发、报告视角 |
| 运营 | 运营、客服、商务 | `opr/` | `<Pages 地址>/<仓库名>/opr` | 原型、需求修改总结（默认页）、运营需求确认、后台操作手册、客服QA |
| 开发 | UI 设计、前端、后端、测试 | `dev/` | `<Pages 地址>/<仓库名>/dev` | 原型、需求要点（默认页）、PRD、开发自查清单 |
| 报告 | 汇报和评审对象 | `repo/` | `<Pages 地址>/<仓库名>/repo` | 全部原型页面、完整 PRD（默认页），只读 |

本文件夹是源文件（相当于产品站点的内容）。四个角色站点由 `.claude/tools/build_role_sites.ps1` 生成，不手工修改。

## 发布到 GitHub Pages

1. 解压压缩包，把里面的 `pdm`、`opr`、`dev`、`repo` 四个文件夹和 `index.html`、`.nojekyll`、`README.md` 放到仓库根目录。
2. 提交并推送，在仓库的 Settings › Pages 里选择发布分支。
3. 把四个访问链接分别发给产品、运营、开发和报告对象。直接打开仓库根地址（没有分身份的链接）时，先进这台电脑上次使用的角色站点；没有记录时进产品站点，需要输入密码。

不需要构建。本地预览时，可以在源文件夹页面地址后加 `?role=pdm`、`?role=opr`、`?role=dev` 或 `?role=repo` 模拟不同角色。

产品站点打开时要先输入访问密码（向该需求的产品管理人获取）；运营、开发和报告站点不需要。

注意：静态页面没有登录，这只是按链接和密码做的简单区分，不是真正的权限控制；拿到别的角色链接的人也能打开，懂技术的人也能绕过密码。
