## 按角色访问

需求包发布成三个角色站点，每个角色一个文件夹，各自的访问链接只发给对应的人：

| 角色 | 包含人员 | 文件夹 | 访问链接 | 能看的页面 |
|---|---|---|---|---|
| 产品 | 产品经理、行政管理人员 | `pdm/` | `<Pages 地址>/<仓库名>/pdm` | 全部页面；默认页是需求与原型中心（含需求文档架构图、运营需求修改记录）；顶栏可切换运营、开发视角 |
| 运营 | 运营、客服、商务 | `opr/` | `<Pages 地址>/<仓库名>/opr` | 原型、需求修改总结（默认页）、运营需求确认、后台操作手册、客服QA |
| 开发 | UI 设计、前端、后端、测试 | `dev/` | `<Pages 地址>/<仓库名>/dev` | 原型、需求要点（默认页）、PRD、开发自查清单 |

本文件夹是源文件（相当于产品站点的内容）。三个角色站点由 `.claude/tools/build_role_sites.ps1` 生成，不手工修改。

## 发布到 GitHub Pages

1. 解压压缩包，把里面的 `pdm`、`opr`、`dev` 三个文件夹和 `index.html`、`.nojekyll`、`README.md` 放到仓库根目录。
2. 提交并推送，在仓库的 Settings › Pages 里选择发布分支。
3. 把三个访问链接分别发给产品、运营、开发。直接打开仓库根地址（没有分身份的链接）时，先进这台电脑上次使用的角色站点；没有记录时进产品站点，需要输入密码。

不需要构建。本地预览时，可以在源文件夹页面地址后加 `?role=pdm`、`?role=opr` 或 `?role=dev` 模拟不同角色。

产品站点打开时要先输入访问密码（向该需求的产品管理人获取）；运营和开发站点不需要。

注意：静态页面没有登录，这只是按链接和密码做的简单区分，不是真正的权限控制；拿到别的角色链接的人也能打开，懂技术的人也能绕过密码。
