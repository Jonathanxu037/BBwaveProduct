老用户充值转盘 · 需求要点 · v1.0

版本：v1.0端：管理后台（后台前端 + 后端），C 端只回归依据：需求开发 PRD 文档

一句话需求

在管理后台【活动中心 › 老用户充值转盘】活动配置的「范围配置 › 充值渠道 › 充值方式」下拉中，于线上现有选项之后新增选项「原生Gcash」；交互、是否必填及勾选后的转盘次数判定，均与现有选项一致。

业务流程

1
打开配置：活动中心 › 老用户充值转盘 → 创建或编辑活动
↓
2
勾选并保存：范围配置 › 充值方式 → 勾选「原生Gcash」（可多选）→ 保存
↓
3
用户充值：老用户经原生Gcash 通道充值成功
↓
4
判定给次数：按订单实际通道判定 → 按现有金额档位给转盘次数
A - 活动已勾选「原生Gcash」

原生Gcash 订单充值成功满足活动现有的全部参与门槛

↓

给转盘次数C 端对应入口显示 Lucky Spin 标识

B - 活动未勾选「原生Gcash」

原生Gcash 订单充值成功—

↓

不给次数充值照常到账

开发功能点

F01-01新增原生Gcash 选项查看 PRD ›

要做什么
  • 充值方式下拉在线上现有选项之后追加「原生Gcash」
  • 选项对应在线支付配置中的 GCash 原生通道
  • 保存值与现有选项同一口径（生产通道标识待后端确认）
示意
充值方式（现有选项以线上为准）
PayMongo
PayCools
TraxionPay
原生Gcash（新增）
公式
下拉选项 ＝ 线上现有选项 ＋「原生Gcash」
涉及端
后台前端后端

F01-02勾选、保存与已选值显示查看 PRD ›

要做什么
  • 可单选，也可与其他选项多选；点 × 删除
  • 保存后再次编辑，显示已保存的值
  • 已有活动默认不勾选「原生Gcash」
  • 是否必填保持原有规则
公式
无

后台前端后端

F02-01原生Gcash 订单获得转盘次数查看 PRD ›

要做什么
  • 充值成功后，原生Gcash 通道的订单进入现有判定逻辑
  • 命中则按现有金额档位给转盘次数，判定逻辑不改
  • C 端已选入口显示 Lucky Spin 标识（回归，是否需发版待前端确认）
判定条件
给次数 ＝ 订单充值成功
　　　 且 订单实际通道 ∈ 活动已选充值方式
　　　 且 满足活动现有的全部参与门槛（沿用现有规则）
次数 ＝ 现有金额档位规则（不变）
