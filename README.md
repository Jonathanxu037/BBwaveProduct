# 产品需求管理系统

版本：v1.0　｜　发布方式：GitHub Pages（GitHub 的静态网页托管服务），无需构建

## 功能

- **登录**：进入系统先输入访问密码，验证通过后当前浏览器标签页不再询问；连续输错 5 次锁定 30 秒。密码由系统的产品管理人提供，页面只保存密码的哈希值。
- **需求列表**：显示已创建的需求，列为序号、需求名称、需求方、版本号、创建时间、最后上传时间，按创建时间从早到晚排列。点击任意一行进入该需求的产品角色页面（`<文件夹名称>/pdm/`）。
- **查询**：四个条件可以组合使用，点「查询」生效，点「重置」清空。
  - 需求名称：模糊匹配，不区分大小写，忽略空格。
  - 需求方：下拉列出当前列表里所有的需求方，选中后立即查询。
  - 创建时间、最后上传时间：按日期区间查询，包含开始日期和结束日期，可以只填一端；开始日期晚于结束日期时提示错误、不执行查询。设置了最后上传时间区间时，「未上传」的需求不在结果里。
  - 查询后序号保持原来的编号，不重新排。
- **新增需求**：填写需求名称、需求方、文件夹名称（英文）。点「确定」后生成记录（创建时间自动记录，初始版本号 v1.0），并在仓库根目录创建同名文件夹，用来存放之后上传的需求包；点「取消」不保存任何内容。
- **修改需求方**：点需求方后面的「✎」，填写新的需求方后确定。本地管理模式和 GitHub 模式都可以用。
- **上传需求包、改版本号**：只在本地管理模式下显示（列表最右边的「操作」列），见下文「上传需求包」。

## 目录说明

| 路径 | 说明 |
|---|---|
| `index.html` | 系统入口（登录页 + 需求列表） |
| `assets/` | 样式、脚本和配置（`config.js` 存密码哈希） |
| `data/requirements.json` | 需求列表数据 |
| `<文件夹名称>/` | 每个需求一个文件夹；上传需求包前是「待上传」占位页 |
| `<文件夹名称>/pdm/`、`opr/`、`dev/` | 需求包的产品、运营、开发三个角色站点 |
| `.nojekyll` | 让 GitHub Pages 按原样发布 |

## 发布步骤

1. 新建一个 GitHub 仓库（或使用已有仓库）。
2. 把压缩包解压后的全部文件（包括 `.nojekyll`）放到仓库根目录，提交并推送。
3. 仓库 Settings（设置）→ Pages → Source 选 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)`，保存。
4. 约 1 分钟后访问 `https://<用户名>.github.io/<仓库名>/`。

## 在 GitHub 上新增需求

静态网站本身不能创建文件夹，所以在 GitHub Pages 上新增需求时，页面通过 GitHub API 直接向仓库提交：

1. 登录后点顶栏右侧的「只读 · 未连接」，填写仓库所有者、仓库名、分支和访问令牌，点「测试并保存」。
   - 令牌建议用 Fine-grained token（细粒度令牌），只授权这一个仓库的 Contents（内容）读写权限。
   - 令牌只保存在当前浏览器的本地存储里，不会写入仓库；不用时点「断开连接」删除。
2. 连接后点「新增需求」，确定后会一次提交：新建 `<文件夹名称>/`（含占位页）并更新 `data/requirements.json`。
3. GitHub Pages 约 1 分钟后重新发布；已连接的浏览器直接从仓库读取列表，立即可见。

## 配合 GitHub Desktop 使用（推荐，不需要访问令牌）

1. 用 GitHub Desktop 把仓库克隆到本机，建议放在 `C:\GitHub\prd-hub`，不要放进 OneDrive 同步的文件夹。
2. 每次操作前先点「Fetch origin（获取远程更新）」，有更新就点「Pull origin（拉取）」。
3. 启动本地管理服务（`prd-hub-server.ps1`，不在本仓库里，由系统的产品管理人保管），`-Root` 指向本地仓库文件夹，浏览器打开 `http://localhost:<端口>/`，顶栏显示「本地管理模式」。
4. 在页面上新增需求、修改需求方、上传需求包、改版本号，改动会直接写进本地仓库。
5. 回到 GitHub Desktop 填写摘要，点「Commit to main（提交）」→「Push origin（推送）」，约 1 分钟后网上更新。

## 上传需求包

在本地管理模式下，点该需求的「上传需求包」，选择 zip 压缩包并填写版本号：

- 支持两种压缩包：角色站点包（含 `pdm/`、`opr/`、`dev/`）原样放进需求文件夹；旧版单站点包（只有 `index.html`）整体放进 `pdm/`。
- 上传后替换需求文件夹里的全部旧内容，同时更新版本号和最后上传时间。
- 版本号格式为 v主版本.次版本，不能低于当前版本；默认在当前版本上加 0.1（v1.9 的下一版是 v2.0），首次上传默认沿用当前版本。
- 压缩包不能超过 300 MB；系统本身的压缩包会被识别并拒绝。

只改列表里显示的版本号时，点「改版本号」。

在 GitHub 模式下暂不支持上传需求包，需要在 GitHub 网页上把三个角色站点上传到对应文件夹，再修改 `data/requirements.json` 里该需求的 `version` 和 `lastUploadAt`。

## 安全说明

- 静态网页的密码只能挡住随手打开的人：懂技术的人可以绕过页面直接打开需求文件夹，6 位数字密码的哈希也能被穷举。需要真正保密时，请把仓库设为私有并使用带登录的托管方式。
- 访问令牌有仓库写入权限，只在自己的电脑上配置，不要在公用电脑上保存。
