    0. 本迭代范围

    本章写本迭代做什么、不做什么；与其他章节冲突时以本章为准。

    类别本迭代包含顺延至
    H5、iOS、Flutter 游戏页浮标（拖动、吸边、闲置贴边）、进入游戏 loading（加载）页的小猫开车动画、快捷侧边栏（Home、Deposit、CS、Mini Banner、推荐游戏）、每款游戏首次退出时自动展开侧边栏—
    H5、iOS、Flutter 游戏页点推荐游戏直接切换游戏；离开当前游戏前先完成结算与余额同步—
    H5、iOS、Flutter 游戏页游戏内充值弹窗：不退出游戏，在游戏上方打开充值弹窗，Submit 后打开二维码支付页（H5 新开浏览器标签页；APP 用独立支付页、WebView 或外部浏览器），支付完回到原游戏—
    管理后台「活动配置 › 游戏快捷侧边栏管理」页面：配置功能开关、Mini Banner、推荐游戏—
    数据第 7 章全部埋点事件—
    iOS 原生 / Flutter（安卓）和 H5 同期上线（产品 2026-10-20 确认），功能和规则与 H5 一致；APP 的支付页打开方式和付款后切回规则见 N16—
    三端本需求是对现有 G 图标悬浮快捷按钮的优化升级：新版本上线后，G 图标改为本需求的浮标和侧边栏（产品 2026-10-20 确认）；低于最低支持版本的 APP 继续显示 G 图标（G 图标按 APP 版本控制，不受后台总开关影响），最低支持版本和是否强更由技术根据实际情况判断（Q15）—
    其他不改游戏内现有退出入口、退出二次确认页面的样式、文案、按钮和交互；不新增任何充值配置；不改充值到账判定和入账逻辑（到账后通知厂商刷新游戏内余额为本需求新增，见 N16）不顺延

    1. 项目概述

    项目说明
    需求描述在 H5、iOS、Flutter 三端的游戏页新增可拖动的小猫浮标（两个站点共用）和快捷侧边栏（由现有 G 图标悬浮快捷按钮优化升级而来；含 Home、Deposit、CS（客服）、Mini Banner、推荐游戏），每款游戏首次点退出时自动展开侧边栏，点推荐游戏直接切换游戏；点 Deposit 时不退出游戏，在游戏上方打开充值弹窗，内容沿用现有充值页，支付完回到原游戏；管理后台新增「活动配置 › 游戏快捷侧边栏管理」页面，配置开关、Mini Banner 和推荐游戏。
    背景与目标玩家在游戏里想换游戏或充值时，要先退出到大厅再进入，步骤多，退出后容易流失。目标：① 提升游戏间切换率和推荐后的继续投注；② 降低「退出即流失」的比例；③ 为活动提供游戏内曝光位，把流量导到活动详情页或指定页面；④ 实现「游戏中直接充值 → 完成支付 → 回到原游戏继续玩」，减少退出游戏、返回大厅、重新进入游戏和重新加载的步骤（依据 Claire《游戏中半屏充值功能需求》）。
    范围做：第 0 章所列内容。不做：退出入口和退出二次确认页面的任何修改；新的充值配置；充值到账判定和入账逻辑的修改（到账后通知厂商刷新游戏内余额除外，N16）；游戏内充值成功弹窗或 Toast。
    多端范围H5 游戏页、iOS 原生、Flutter（安卓）、管理后台：同期做。
    后台范围每个站点有自己的管理后台，本页面在各自后台单独配置，配置只对本站点生效；页面内不区分站点
    名词说明本需求的「侧边栏」专指游戏页内的「游戏快捷侧边栏」；789games 首页左上角的汉堡菜单（GAM-10 等单子里也叫「侧边栏」）不在本需求范围。「免费次数（Free Spin）」专指玩家通过新用户转盘获得、带入厂商游戏使用的免费旋转次数；平台上的「Spin」指转盘游戏，本文不用它指代厂商游戏内的其他玩法。涉及砸金蛋、Spin、转盘等活动的问题（含免费次数的来源和处理），一律由技术按当前平台逻辑处理（产品 2026-10-20 确认）。玩家从 My Rewards（奖券）进入游戏的会话中，充值到账和切换游戏推哪个余额，由技术按当前平台逻辑处理（产品 2026-10-22 确认）。
    视觉浮标、侧边栏、充值弹窗各模块的视觉样式、尺寸和动效以设计稿为准；本文档只写功能与交互逻辑。按钮配色和所有尺寸由设计按自己的标准确定，文中的像素数值只是原型参考。横屏游戏里的浮标、侧边栏、loading 动画、客服对话窗由 UI 出横屏适配设计，逻辑和竖屏一致（充值弹窗的横屏方案见 Q11）。小猫浮标、loading 动画和侧边栏跟随节日换肤需求更换素材，素材做成可替换（产品 2026-10-22 确认）。
    时间与时区GMT+8

    2. 整体业务流程

    2.1 主流程（玩家视角）

    1
    进入游戏：准入校验通过 → loading 页播放小猫开车动画，按加载进度开向浮标位置（N19）→ loading 结束进入游戏页 → 后台总开关开启时显示浮标（默认屏幕右侧上方）
    ↓
    2
    展开侧边栏：点浮标 → 侧边栏在浮标所在一侧展开
    ↓
    3
    使用快捷功能：点 Home / Mini Banner（选择活动）/ 推荐游戏 → 推荐游戏先做准入校验（不通过不结算、留在游戏）→ 完成当前游戏结算与余额同步 → 执行跳转；点 CS 从底部打开客服对话窗，不结算、不离开游戏；Mini Banner 的自定义链接在新标签页打开，不结算（见 2.2 离开当前游戏分支）
    ↓
    4
    游戏内充值：点 Deposit → 侧边栏收起 → 充值弹窗盖在游戏上方 → 选支付方式和金额 → Submit → 弹窗收起，打开二维码支付页（H5 新标签页 / APP 支付页）→ 完成支付 → 回到原游戏（见 2.4 充值弹窗分支）
    ↓
    5
    首次退出：在当前游戏首次点退出 → 平台现有退出确认弹出，同时自动展开侧边栏（见 2.3 首次退出分支）

    2.2 离开当前游戏分支（按当前局是否已结算）

    A - 当前局已结算

    结算同步按平台现有退出规则同步第三方与平台余额，显示「正在结算游戏余额…」

    ↓

    执行跳出进入新游戏 / 平台首页 / 活动页

    B - 已投注、当前局未结算

    loading（加载）蒙层半透明，玩家能看到当前局结算过程；屏蔽其他操作

    ↓

    等本局结算 → 结算同步 → 执行跳出同 A

    C - 任一环节失败

    未离开当前游戏时失败关闭蒙层并提示，玩家留在当前游戏

    已离开、新游戏启动失败回到原游戏并同步余额，提示「所选游戏暂时不可用，请换一款试试」

    2.3 首次退出分支（按玩家选择）

    A - 点推荐游戏

    关闭退出确认结算同步后直接进入所选游戏，不经过大厅

    B - 取消退出 / 收起侧边栏

    侧边栏和退出确认一起关闭留在当前游戏；再次点退出按现有流程退出，不再自动展开

    C - 确认退出

    按平台现有流程退出退出前同样先结算同步

    2.4 充值弹窗分支（按端和支付结果）

    充值弹窗期间游戏保留在底层，不关闭、不刷新、不重新加载；打开充值弹窗前不做游戏结算。

    A - H5

    Submit 成功创建订单新开浏览器标签页显示二维码支付页；弹窗收起，原游戏标签页保持打开

    ↓

    支付完成回跳到「支付完成」中间页，自动关闭新标签页，回到原游戏标签页；不能自动关闭时提示玩家关闭此页面，不跳大厅；内置浏览器、小程序、PWA 见 5.1

    B - APP

    Submit 成功创建订单按该支付方式现有的打开方式，用独立支付页、WebView 或外部浏览器显示二维码；弹窗收起，原游戏页面保持

    ↓

    支付完成需玩家手动切回 APP（现状），原游戏保持，不跳大厅

    C - 随时关闭

    点 × 或点上方游戏区域立即关闭充值弹窗，回到当前游戏

    2.5 系统时序（后端视角）

    触发执行方动作
    进入游戏前端 → 后端读取侧边栏配置和推荐游戏列表；配置读取失败时不显示浮标
    点推荐游戏 / Home / Mini Banner（选择活动）/ 确认退出（推荐游戏先做准入校验，不通过不结算）后端 ↔ 第三方游戏判断当前局是否未结算 → 等待结算 → 按平台现有退出规则同步余额 → 返回结果；目标是新游戏时，再把结算后的余额同步到新游戏供应商并启动
    充值弹窗 Submit前端 → 后端 → 支付渠道沿用现有充值下单接口和校验，返回支付页地址；前端按端打开支付页（H5 新标签页 / APP 支付页）；H5 下单时传入游戏内充值专用的回跳地址（「支付完成」中间页），平台其他入口的充值回跳不变
    支付渠道回调支付渠道 → 后端沿用现有到账逻辑和站内信通知；不向游戏页推送额外的成功提示；到账后后端通知当前游戏厂商刷新游戏内余额，不支持的厂商由前端自动刷新游戏页面；玩家已在离开当前游戏时，先完成离开结算再做到账同步（N13、N16）
    点 CS前端 → 客服系统打开和首页客服挂件相同的客服（选择逻辑沿用现状）；身份传递沿用首页客服方式，地址里不拼接登录 token（N18）
    进入游戏 loading 页前端按厂商游戏的加载进度驱动小猫开车动画，进度 100% 时开到浮标位置，进入游戏页（N19）
    后台保存配置后台 → 后端保存全部配置；之后新进入游戏的玩家读取新配置，已在游戏中的玩家下次进入游戏时生效

    3.2 本需求规则

    编号规则起因功能点

    5.1 运行环境与支付页打开方式

    玩家所在的运行环境决定二维码支付页在哪里打开、付完款怎么回到原游戏（N16）。所有环境下：回跳地址不带登录 token 和玩家身份信息，其他参数由技术按当前平台规则处理；支付页和「支付完成」中间页都不依赖登录态；原游戏页面始终保持，弹窗在支付页打开后已收起。

    运行环境支付页在哪里打开付完款后中间页关闭失败时
    H5：手机系统浏览器（Safari、Chrome 等）同一浏览器新开标签页回跳到「支付完成」中间页，自动关闭新标签页，回到原游戏标签页显示「支付已完成，请返回游戏页面」和「关闭此页面」按钮，不进大厅
    H5：TG、Facebook 等 App 内置浏览器；Maya、GLife 等小程序（小程序内的实际行为由技术按当前平台规则处理）；已安装的 PWA（独立窗口）由系统打开手机系统浏览器（无平台登录态）回跳到中间页；中间页不是由游戏页打开的，自动关闭通常不生效。玩家切回原 App 或 PWA，原游戏保持；原游戏页被关闭（-2044）等情况由技术按当前平台规则处理只显示文字「支付已完成，请返回游戏页面」，不显示「关闭此页面」按钮（在这些环境里同样无效），也不提供进入平台的入口（避免在系统浏览器里打开第二个未登录的平台页面）
    APP：iOS 原生、Flutter（安卓）按该支付方式现有的打开方式：独立支付页、WebView 或外部浏览器现状无法自动回到 APP（-2207、-2208、-2301、-2320），玩家手动切回，原游戏保持按现有支付结果页显示

    ※ 内置浏览器和 PWA 下的跳转行为来自线上历史问题（-1946、-1981、-2044、-2083），上线前按第 13 章测试 Tips 在每种环境实测；某个环境实测无法打开支付页时，按第 8 章「支付页打开失败」处理。
