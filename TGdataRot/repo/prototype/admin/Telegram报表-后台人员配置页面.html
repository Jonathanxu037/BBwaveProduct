789Bingo 后台、789Games 后台 › 系统管理 › Telegram报表配置 › 人员配置（整页为本需求新增），配置流程第二步：先在渠道配置建好渠道，再登记人员。新站 789Games 和旧站 789Bingo 两个子站后台各自登记可查看本子站数据的人员及其可查看渠道；同一个人在两个后台用同一个 Telegram ID，在全部子站都有权限时自动可看全网数据。

规则批注

  1. 群 + 人员双重授权：只有在对接的群（由技术配置，目前为「BBwave平台数据」）里操作，且已在本页登记并启用，才生成报表。权限长期有效，不再需要时停用或删除。PRD 规则 N4 · F01-03
  2. 适用子站与 Telegram ID：系统按 Telegram ID 识别同一个人。在哪个子站后台登记并启用，群里就显示哪个子站按钮；全部子站后台都登记并启用同一个 Telegram ID，自动显示「全网数据」，少一个子站都不显示。两边填的 ID 不一致时当作两个人。新增子站同理，新子站后台也有本页。PRD 规则 N35 · F01-03
  3. 首页：两个及以上子站有权限，首页为一级菜单；只有一个子站权限，首页为该子站的二级菜单（不显示「⬅ 返回上一级」「🏠 首页菜单」）。权限按人员在群里操作时的配置判断。PRD 规则 N2、N35 · F05-03
  4. Telegram 昵称：不填姓名，系统按 Telegram ID 从授权群自动获取，与群里显示一致，机器人 @ 人员时也用它；人员改昵称后，下次在群里操作时自动更新；还没进群显示「未进群」；后台不能修改。PRD 5.1 人员配置 · F05-03
  5. 可查看渠道：按渠道配置的父子关系树状显示全站、自然流量、自建渠道和代理线查询。勾父级时子渠道全部勾上；取消某个子渠道时父级半选，群里下一级菜单不显示「父级·全渠道」，列表显示如「谷歌（部分：谷歌品牌词）」。添加时默认不勾选，至少勾选一个渠道（「代理线查询」不算）。新建顶层渠道时已登记人员默认不勾选；新建子渠道时，已全选其父级的人员自动勾选。全网数据下只显示每个子站都勾选的渠道（取交集）；代理线查询在全网数据下只查勾选了它的子站。
    无可查看渠道：渠道被删光时保留登记，列表标红「无可查看渠道」。人员在某个范围没有可显示的渠道（含渠道被设为群里不显示、无可用代理）时，群里回复「你没有可查看的渠道，请联系管理员开通。」；有代理线查询权限的仍可用「🔍 代理线查询」。PRD 5.1 人员配置、5.2 渠道配置、规则 N23、N39、N65 · F05-03
  6. 没有权限时：未登记或已停用的人员操作时，机器人在群里回复「@昵称 你还没有报表查看权限，请联系管理员开通。你的 Telegram ID：xxx」（点消息里的按钮时只弹同一句，不 @），1 分钟后删除，也计入发送限制。PRD 规则 N43 · F01-04
  7. 群内共享：报表发在群里，群成员都能看到；个人权限只控制能发起哪些查询。入群成员由 Telegram 群主和群管理员控制，只拉可以看全部报表数据的人。删除或停用人员后，他已看到的报表收不回，仍在群里时能看到别人查询的报表，需要时请把他移出群。PRD 规则 N36、5.1 人员配置 · F01-03
  8. 保存后生效：添加、编辑、删除、启用、停用保存后立即生效，机器人不在群里群发；被修改的人员下次在群里发消息或点按钮时，机器人先按新权限 @ 他发送本人的首页菜单，再按当前权限处理这次操作。PRD 规则 N61 · F05-03
  9. 发送前再校验：报表排队期间权限被停用或删除的，发送前再校验一次，不通过则取消发送。PRD 规则 N50 · F02-03
  10. 校验：Telegram ID 为正整数、不能重复，编辑时不能修改；可查看渠道至少勾选一个渠道（「代理线查询」不算），否则提示「至少选择一个渠道」；在渠道配置里设为群里不显示的渠道仍可勾选，重新显示后才对人员出现。PRD 5.1 人员配置 · F05-03
  11. 列表：按添加时间倒序，每页 20 条；关键字匹配 Telegram ID 或昵称；筛选后回到第 1 页；删除后当前页为空时回到上一页。保存、删除记入操作日志（沿用现有）。PRD 5.1 人员配置、5.4 列表分页、规则 N56 · F05-03
  12. 操作权限：沿用后台现有「角色 → 权限组 → 菜单 / 按钮权限」配置，分四项授予：查看三个页面；编辑人员配置；编辑渠道配置；机器人管理。本页的添加、编辑、删除、启用和停用需要「编辑人员配置」权限。PRD 规则 N56 · F05-03
