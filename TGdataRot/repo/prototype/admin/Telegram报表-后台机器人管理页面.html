  1. 该机器人已在全部子站自动停用；它服务的群已切换到可接替的机器人，没有时全部子站和全网数据暂停出报表。

规则批注

  1. 一群一个机器人：对接的群和初始服务机器人由技术指定，后台不设置；一个群只有一个服务机器人，不轮换、不按渠道拆分发送（条款 5.2(f)）。
    切换：当前服务机器人在任一子站被停用（手动停用、不可用时自动停用），或状态变为「异常（不在群或权限不足）」时，整个群切换到可接替的机器人。可接替 = 全部子站都启用、已在群里且权限正常；状态正常的优先，限流中的其次，同组按本页列表顺序（最早添加的在前）。没有时，被停用的子站和全网数据回复「报表机器人暂不可用，正在更换，请稍后再试。」，其他子站仍由原机器人服务。原机器人恢复后不自动切回，由技术决定是否换回。切换后点原机器人发出的按钮，只弹「请发 /menu 打开你的菜单」。PRD 规则 N52、N54 · F05-04
  2. 两站信息同步：机器人以用户名识别为同一个；添加、改名称或用户名、更换 Token、删除在全部子站同步（操作日志记在操作的子站）；在一个子站添加后，其他子站里它初始为「停用」，由该站手动启用；启用、停用和总停用开关各子站分别管理。只在一个子站启用的机器人不能接替服务，也不能出全网数据。新增子站上线时，已有机器人同步出现在新子站本页，初始为停用；开放新子站按钮前，先在新子站启用当前服务机器人，再登记人员。PRD 规则 N53、N35 · F05-04
  3. 总停用开关：异常时一键止损，只作用于本子站。打开：本子站和全网数据都不再出报表，排队中的这些报表取消，群里点本子站或全网数据回复「报表服务暂停中，请稍后再试。」（全网数据范围的代理线查询只查其他正常子站），其他子站不受影响；关闭：恢复服务，已取消的报表不补发。打开和关闭都要二次确认。PRD 规则 N53、N55 · F05-04
  4. 状态：正常；限流中——按 Telegram 返回的等待时间暂停，到时自动恢复；停用——在本子站人工停用，不调取本子站数据；异常（不在群或权限不足）——对所有机器人检测：不在授权群、不是群管理员或没有发言权限；是服务机器人时立即通知后台管理员并切换，是备用机器人时只显示该状态、不作为接替对象；恢复在群且权限正常后自动变回原状态，不自动切回服务；停用（疑似封禁）——连续发送失败且错误提示指向账号受限时自动停用并通知后台管理员，需人工核查，系统不直接判定为封禁；停用（Token 失效）——需更换 Token。疑似封禁、Token 失效时全部子站自动停用，不能手动启用；「确认已恢复」或更换 Token 后，全部子站恢复为之前的启用或停用状态。
    告警：后台顶部实时提醒栏新增「Telegram报表告警」（疑似封禁、Token 失效、机器人不在群或权限不足、删除提醒发不出、连续限流 3 次），有机器人管理权限的账号（即后台管理员）可见，点击进入本页；告警方式待技术确认。PRD 规则 N54、N59、待确认 Q15 · F05-04
  5. 启用与停用：停用表示不再调取本子站数据，重新启用后恢复。停用的是当前服务机器人时按「切换」处理，按钮照常显示；没有可接替的机器人时，群里点本子站或全网数据回复「报表机器人暂不可用，正在更换，请稍后再试。」，不含数据，1 分钟后删除。PRD 规则 N53、N55 · F05-04、F02-04
  6. 疑似封禁处理：按「停止发送 → 核查整改 → 申诉 → 技术核查后恢复」处理；可生成脱敏故障材料（机器人用户名、发生时间、官方提示、近 7 天发送量、错误记录、整改记录）。期间按「切换」由其他机器人服务。PRD 5.3 机器人管理 · F05-04
  7. 只显示表格：机器人数量少，只显示总停用开关和机器人表格，不做汇总、筛选和分页，不显示发送条数。排序：状态为正常、限流中、异常的排在前面，各类停用排在后面；同组按添加时间先后（最早添加的在上）。PRD 5.3 机器人管理 · F05-04
  8. 发送限制：由技术配置，后台不设置（如每分钟 16 条），见机器人对话页规则批注「发送限制」。PRD 规则 N51 · F02-03
  9. 未删除的报表：报表到删除时间（发出满 15 分钟）删除失败时自动重试，状态旁显示橙色「未删除 N 份」，悬停或点击显示份数和最早的应删除时间（GMT+8）。只统计报表图片。删除成功或群内合并提醒发出后，对应报表从份数中去掉，份数为 0 时标签消失，不提供手动清除；合并提醒的文案和提醒发不出时的处理见机器人对话页「删除失败」。机器人被停用、替换或删除后，它的未删除报表由当前服务机器人按时删除，标签移到当前服务机器人。PRD 规则 N28 · F04-03
  10. 操作权限：沿用后台现有「角色 → 权限组 → 菜单 / 按钮权限」，分四项授予：查看三个页面；编辑人员配置；编辑渠道配置；机器人管理（含 Token、启用停用、总停用开关、确认已恢复、删除）。上线时机器人管理只授予超级管理员。PRD 规则 N56 · F05-04
  11. Token 安全：保存后只显示后 4 位，任何地方（列表、编辑弹窗、操作日志、故障材料）都不显示完整 Token；编辑时留空表示不修改。更换后系统立即停用旧 Token，提示「保存成功，系统已停用旧 Token；如旧 Token 已泄露，请在 Telegram 作废」。「测试连接」只校验 Token，不在群里发消息。PRD 5.3 机器人管理 · F05-04
  12. 校验：名称必填，1–30 个字符（中文、英文字母、数字、符号各算 1 个，去掉首尾空格后计算）；用户名必填、以 bot 结尾、不加 @、不能重复；添加时 Token 必填、格式正确、不能和已有机器人重复（提示「该 Token 已被其他机器人使用」）；绕过页面直接提交同样拦截。添加时状态选启用的显示「正常」，选停用的显示「停用」。PRD 5.3 机器人管理 · F05-04
  13. 删除：标「服务中」的机器人不能删除，点「删除」直接提示「这个机器人正在服务群，请联系技术更换后再操作」，只有「知道了」。其余机器人确认后在全部子站删除；它发出且未删除的报表由当前服务机器人按时删除。PRD 5.3 机器人管理、规则 N28、N53 · F05-04
  14. 操作日志：本页所有操作（添加、编辑、更换 Token、启用、停用、删除、总停用开关、确认已恢复、生成故障材料）都记入后台现有操作日志，Token 只记后 4 位。PRD 规则 N56 · F05-04
