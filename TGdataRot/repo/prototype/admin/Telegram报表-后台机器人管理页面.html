每个子站后台各有本页：机器人以用户名识别为同一个，添加、改名称或用户名、更换 Token、删除在全部子站同步；启用、停用和总停用开关只作用于本子站。人员在 Telegram 私聊当前服务机器人使用报表；服务机器人同一时间只有一个，初始由技术指定，不轮换、不分担发送（Telegram 开发者条款 5.2(f)「不得绕过频率限制或审核」）。服务机器人在任一子站停用时，切换到可接替的机器人，人员须打开新机器人私聊并点「开始」；没有可接替的机器人时，原机器人手动停用的，被停用的子站和全网数据暂停出报表，原机器人疑似封禁或 Token 失效的，全部子站和全网数据停止出报表；之后有机器人可接替或原机器人恢复时自动恢复出报表。本页时间均为 GMT+8。

疑似封禁处理

  1. 该机器人已在全部子站自动停用；它是服务机器人时已切换到可接替的机器人（它发不出更换通知，请把新机器人私聊链接转告人员），没有可接替的机器人时全部子站和全网数据停止出报表，人员私聊收不到回复。
  2. 核查原因：异常发送、Token 泄露、数据越权、业务是否符合条款。
  3. 整改完成后，通过 Telegram 官方渠道申诉并附上故障材料。
  4. 确认解封后，由技术核查后恢复：核查可正常使用后，点「确认已恢复」。

模拟场景

规则批注

  1. 一个服务机器人：人员在 Telegram 私聊当前服务机器人使用报表。服务机器人同一时间只有一个，初始由技术指定，后台不设置；不轮换、不按渠道拆分发送（条款 5.2(f)）。
    切换：当前服务机器人在任一子站被停用（手动停用，或疑似封禁、Token 失效时自动停用）时，切换到可接替的机器人。可接替 = 全部子站都启用；状态正常的优先，限流中的其次，同组按本页列表顺序（最早添加的在前）。切换时原机器人上已在生成、排队中的报表由原机器人发完再停；原机器人疑似封禁或 Token 失效发不出的取消。
    没有可接替的机器人：① 原机器人只是手动停用、仍能发消息：被停用的子站和全网数据回复「报表机器人暂不可用，正在更换，请稍后再试。」，其他子站仍由原机器人服务；本页红字「本子站和全网数据暂停出报表，其他子站仍由原机器人服务」。② 原机器人疑似封禁或 Token 失效：全部子站和全网数据停止出报表，人员私聊收不到任何回复，发「Telegram报表告警」；本页红字「服务机器人不可用，也没有可接替的机器人：全部子站和全网数据停止出报表，人员私聊收不到回复」。
    没有可接替之后的恢复：没有可接替期间，任一机器人变为可接替（全部子站都启用，状态正常或限流中）时，自动切换为服务机器人并通知人员；原机器人只是手动停用的，在被停用的子站重新启用后，疑似封禁的「确认已恢复」后，Token 失效的更换 Token 后，仍是服务机器人，直接恢复出报表，不发更换通知；两种情况以先发生的为准，恢复后红字消失。已切换到其他机器人后，原机器人恢复不自动切回，由技术决定是否换回。（演示：列表里先停用 B、C，再停用服务中的 A，可看到 ① 的红字；之后启用 B 可看到自动切换，或重新启用 A 可看到恢复出报表。）PRD 规则 N52、N55 · F05-04
  2. 更换后通知人员：Telegram 不允许机器人给没点过它「开始」的人员发消息，人员须打开新机器人私聊并点「开始」才能收到消息。原机器人还能发消息时（如手动停用），由它私聊通知在任一子站已登记并启用的人员，同一 Telegram ID 只发一次（只能送达点过它「开始」且没有屏蔽它的人员）：「报表机器人已更换，请打开 @当前服务机器人用户名 并点「开始」。」，发出满 24 小时删除。非服务机器人（含原服务机器人、备用机器人）收到私聊一律回复这句，@ 的始终是当前服务机器人。原机器人发不出时（疑似封禁、Token 失效），本页顶部提示后台管理员把新机器人私聊链接（t.me/用户名）转告人员，并发「Telegram报表告警」。本页顶部始终显示当前服务机器人和私聊链接，可复制。PRD 规则 N67 · F05-04
  3. 两站信息同步：机器人以用户名识别为同一个；添加、改名称或用户名、更换 Token、删除在全部子站同步（操作日志记在操作的子站）；在一个子站添加后，其他子站里它初始为「停用」，由该站手动启用；启用、停用和总停用开关各子站分别管理。只在一个子站启用的机器人不能接替服务，也不能出全网数据。新增子站上线时，已有机器人同步出现在新子站本页，初始为停用；开放新子站按钮前，先在新子站启用当前服务机器人，再登记人员。PRD 规则 N53、N35 · F05-04
  4. 总停用开关：异常时一键止损，只作用于本子站。打开：本子站和全网数据都不再出报表，排队中的这些报表取消，人员点本子站或全网数据回复「报表服务暂停中，请稍后再试。」（全网数据范围的代理线查询只查其他正常子站），其他子站不受影响；关闭：恢复服务，已取消的报表不补发。打开和关闭都要二次确认。PRD 规则 N53、N55 · F05-04
  5. 状态：正常；限流中——按 Telegram 返回的等待时间暂停，到时自动恢复；停用——在本子站人工停用，不调取本子站数据；停用（疑似封禁）——连续发送失败且错误提示指向账号受限时自动停用并通知后台管理员，需人工核查，系统不直接判定为封禁；停用（Token 失效）——需更换 Token。疑似封禁、Token 失效时全部子站自动停用，不能手动启用；「确认已恢复」或更换 Token 后，全部子站恢复为之前的启用或停用状态。
    告警：后台顶部实时提醒栏新增「Telegram报表告警」（疑似封禁、Token 失效、更换机器人需转告人员、报表满 48 小时未删除、连续限流 3 次），有机器人管理权限的账号（即后台管理员）可见，点击进入本页；告警方式待技术确认。PRD 规则 N54、N59 · F05-04
  6. 启用与停用：停用表示不再调取本子站数据，重新启用后恢复。停用的是当前服务机器人时按「切换」处理，按钮照常显示，提示同时写明切换结果；没有可接替的机器人时按「没有可接替的机器人」①，人员点本子站或全网数据回复「报表机器人暂不可用，正在更换，请稍后再试。」，不含数据，1 分钟后删除。没有可接替期间重新启用原服务机器人或启用其他机器人，按「没有可接替之后的恢复」处理。PRD 规则 N52、N55 · F05-04
  7. 疑似封禁处理：按「停止发送 → 核查整改 → 申诉 → 技术核查后恢复」处理；可生成脱敏故障材料（机器人用户名、发生时间、官方提示、近 7 天发送量、错误记录、整改记录）。是服务机器人时按「切换」由其他机器人服务，它发不出更换通知，由后台管理员转告新机器人私聊链接。PRD 5.3 机器人管理、规则 N54、N67 · F05-04
  8. 只显示表格：机器人数量少，只显示总停用开关、当前服务机器人和机器人表格，不做汇总、筛选和分页，不显示发送条数。排序：状态为正常、限流中的排在前面，各类停用排在后面；同组按添加时间先后（最早添加的在上）。PRD 5.3 机器人管理 · F05-04
  9. 发送限制：由技术配置，后台不设置（如单个私聊每秒 1 条、整体每秒 24 条），见机器人对话页规则批注「发送限制」。PRD 规则 N51 · F02-03
  10. 未删除的报表：报表发出满 24 小时自动删除，失败时自动重试。Telegram 只允许机器人删除发出 48 小时内的消息：满 48 小时仍未删除的，状态旁显示橙色「未删除 N 份」并通知后台管理员；点击显示份数、最早发出时间（GMT+8）和涉及人员（昵称、Telegram ID），由后台管理员通知这些人员手动删除，通知后点「已通知，清除标记」。只统计报表图片。机器人被停用或更换后，仍由它删除自己发出的报表（只删除，不发新消息）；疑似封禁、Token 失效期间删不掉的，满 48 小时后同样计入。到时发现消息已不存在（人员手动删除、清空私聊或注销 Telegram 账号）视为删除成功，不计入；因人员屏蔽机器人等原因删不掉的，满 48 小时计入，弹窗里照常列出涉及人员。PRD 规则 N28 · F04-03
  11. 操作权限：沿用后台现有「角色 → 权限组 → 菜单 / 按钮权限」，分四项授予：查看三个页面；编辑人员配置；编辑渠道配置；机器人管理（含 Token、启用停用、总停用开关、确认已恢复、清除未删除标记、删除）。上线时机器人管理只授予超级管理员。PRD 规则 N56 · F05-04
  12. Token 安全：Token 保存后，后台页面和接口都只返回后 4 位，任何账号（含有机器人管理权限的账号）都不能再看到完整 Token；技术配置的初始服务机器人同样。列表、编辑弹窗、操作日志、故障材料都只显示后 4 位；编辑时留空表示不修改。更换后系统立即停用旧 Token，提示「保存成功，系统已停用旧 Token；如旧 Token 已泄露，请在 Telegram 作废」。泄露时先在 Telegram 作废，再填新 Token。PRD 5.3 机器人管理 · F05-04
  13. 校验：名称必填，1–30 个字符（中文、英文字母、数字、符号各算 1 个，去掉首尾空格后计算）；用户名必填、以 bot 结尾、不加 @、不能重复；添加时 Token 必填、格式正确、不能和已有机器人重复（提示「该 Token 已被其他机器人使用」）。保存时核对 Token 对应的机器人用户名与填写的一致，不一致不能保存，提示「用户名与 Token 不匹配」（编辑时改用户名或更换 Token 同样核对）；绕过页面直接提交同样拦截。「测试连接」只校验 Token，不发消息、不保存：成功显示「连接正常：@实际用户名」，失败显示「Token 无效，请检查后重试」。添加时状态选启用的显示「正常」，选停用的显示「停用」。（演示：Token 含「other」视为属于其他机器人。）PRD 5.3 机器人管理 · F05-04
  14. 删除：以下情况不能删除，点「删除」直接提示，只有「知道了」；同时满足多种时，在同一个提示里按顺序每种一行，全部列出：① 标「服务中」——「这个机器人正在服务，请联系技术更换后再操作。」；② 原服务机器人更换未满 7 天——「更换未满 7 天，MM-DD HH:mm（GMT+8）后可删除。」（时间 = 更换时刻 + 7 天）；③ 它发出的报表还有未到删除时间或正在重试的——「这个机器人还有 N 份报表等待自动删除，最晚 MM-DD HH:mm（GMT+8）删除完，之后再删除机器人。」（最晚 = 最后一份报表的删除时间，即发出 + 24 小时；到时仍在重试的，满 48 小时后转为「未删除 N 份」）；④ 有「未删除 N 份」标记——「请先处理「未删除 N 份」，再删除。」。其余机器人确认后在全部子站删除。（演示：在「停用服务机器人」场景里删除原服务机器人，可看到未满 7 天的提示。）PRD 5.3 机器人管理、规则 N67 · F05-04
  15. 操作日志：本页所有操作（添加、编辑、更换 Token、启用、停用、删除、总停用开关、确认已恢复、生成故障材料、清除未删除标记）都记入后台现有操作日志，Token 只记后 4 位。系统自动动作也记日志，操作人写 SYSTEM，详情写原因和切换前后的机器人：自动停用（疑似封禁、Token 失效）、自动切换服务机器人、确认已恢复后的状态恢复。跨子站同步的改动也写入其他子站的操作日志，详情注明「由 子站 同步」。操作日志沿用现有显示时区（789Bingo 为 −04:00），与本页时间（GMT+8）可能相差 12 小时。PRD 5.3 机器人管理、规则 N53、N56 · F05-04
