Telegram报表 · 需求要点 · v1.2

版本：v1.2端：Telegram 机器人（私聊）、789Bingo 后台、789Games 后台依据：需求开发 PRD 文档

一句话需求

新建 Telegram 报表机器人「BBWave报表助手」，已在 789Bingo、789Games 后台登记的人员与机器人私聊，按范围（789BINGO、789GAMES、全网数据）选择渠道或模糊搜索代理线，生成今日、昨日、前日 12 项指标及较昨日同时段对比的报表图片，发到本人私聊，发出满 24 小时自动删除；两个子站后台【系统管理 › Telegram报表配置】新增人员配置、渠道配置、机器人管理三个标签页。

业务流程

1
打开首页菜单：打开机器人私聊点「开始」，或发 /menu → 校验人员
↓
2
选数据范围：789BINGO / 789GAMES / 全网数据（只有一个子站权限时跳过）
↓
3
选查询对象：点渠道（父级进入下一级）或代理线查询（搜到 1 个直接出报表，多个时点选）
↓
4
生成并发送：生成 → 限流排队 → 发送前复核 → 发出图片到本人私聊（之前的报表保留）
↓
5
自动删除：发出满 24 小时删除；失败重试，满 48 小时仍未删除时后台标记并通知后台管理员
A - 已登记并启用

按权限显示按钮报表只发到本人私聊

B - 未登记或已停用

不返回数据回复未开通回复（带本人 Telegram ID），不自动删除；同一 ID 10 分钟内只回复 1 次（N43）

C - 在非服务机器人私聊（含原服务机器人）

回复更换通知提示打开当前服务机器人并点「开始」（没有服务机器人，或服务机器人疑似封禁、Token 失效时不回应；N67）

D - 子站停止出报表

按原因处理总停用开关打开：回复暂停提示；没有可接替的机器人：原机器人手动停用时回复「暂不可用」提示，疑似封禁或 Token 失效时全部子站和全网数据停止出报表，人员收不到回复（N52、N55）

F01-02报表菜单与按钮查看 PRD ›

要做什么
  • 一级（子站、全网数据）→ 二级渠道 → 不限层级的下一级菜单；按本人权限显示。
  • 布局：渠道（每行 1–3 个）→ 代理线查询 → 两个返回类按钮并排（首页没有）；一级菜单也有代理线查询。
  • 底部键盘默认收起，「⌨」展开，一次列出全部层级。
  • 新菜单替换本人私聊里的上一条菜单，未被替换的菜单类消息发出满 24 小时删除（N60）。
  • 配置变更不主动推送，人员下次操作时按 N61：本次会打开菜单或生成报表的直接按新权限处理；点已不可用的按钮发新首页菜单并只弹「该渠道已不可用，请在新菜单里选择」；其他操作先发新首页菜单再处理。
  • 关闭父级「菜单显示」时子渠道一起隐藏，不影响统计。

显示「全网数据」＝ 全部子站都有权限

全网数据显示代理线查询 ＝ 任一子站勾选

F01-04拒绝提示查看 PRD ›

要做什么
  • 点按钮被拒只弹提示；已登记并启用的人员发命令或点键盘被拒，回复拒绝回复，不含数据，1 分钟后删除（末行写删除时间）。
  • 未登记或已停用：点「开始」、发任何命令（含不支持的命令）、点键盘都回复未开通回复（带本人 Telegram ID，不自动删除）；点按钮时弹同一句。
  • 未开通回复限频：同一 Telegram ID 10 分钟内只回复 1 次，其余不回应、不占发送额度；排队时排在已登记人员的报表和菜单之后（N43、N51）。
  • 子站停止出报表的提示，点按钮时也回复消息。

F02-01报表生成与展示查看 PRD ›

要做什么
  • 按 Excel 格式截成一张图片发到本人私聊；缩略图点开看全图；不发文件。
  • 列：指标 | 今日 | 昨日 | 前日 | 较昨日同时段，12 项四组；全网数据 3 个工作表。
  • 图片下方：路径、统计时间（每站一组，写日期和时区）、删除时间（MM-DD HH:mm，GMT+8）；按钮：代理线查询和两个返回类按钮。
  • 内容保护：所有消息（含未开通回复）禁止转发、保存；未开通回复里的 Telegram ID 由本人手动抄写（N57）。
公式
今日 > 昨日同时段 → ▲ 绿；< → ▼ 红；相等或任一为 - → 无箭头
变化百分比 ＝（今日 − 昨日同时段）÷ |昨日同时段| × 100%，1 位小数；分母为 0 或任一为 - → -；其余相等 → 0.0%
人数、金额为 0 → 0；比值分母为 0 → -
留存变化 ＝ 今日留存率 − 昨日同时段留存率，单位「百分点」

F02-02指标口径查看 PRD ›

要做什么
  • 各子站按自己平台的时区切日（789Bingo 为 UTC+8，789Games 由技术按平台时区确定）：今日 = 00:00 至生成时刻；昨日、前日全天；全网数据 = 两站相加。
  • 12 项与平台报表一致，范围随按钮；不计测试用户。投注类与平台报表用同一归日口径；总投注额对「三方平台总投注」、GGR 对「平台游戏盈利额」（Q25）。
  • 渠道 = 所绑代理及下级的用户；自然流量 = 未归入自建渠道的用户。
公式
自然流量 ＝ 全站 − 各顶层渠道合计
全网合计：人数、金额 ＝ 两站相加；人均、留存 ＝ 合计分子 ÷ 合计分母
存提差 ＝ 存款金额 − 提款金额
人均首存 ＝ 首存金额 ÷ 新增首存人数；人均存款 ＝ 存款金额 ÷ 存款人数（分母 0 → -）
GGR ＝ 总投注 − 总派彩
日期 D 的次日留存 ＝ D 前一天注册用户在 D 当天有登录人数 ÷ 该日注册人数
日期 D 的 7日留存 ＝ D 往前第 7 天注册用户在 D 当天有登录人数 ÷ 该日注册人数

F02-03生成、排队与发送前复核查看 PRD ›

要做什么
  • 校验通过后发「正在生成报表…」；同一人员同时只生成一份，生成中再查不重复生成。
  • 30 秒内相同查询（未跨该站 00:00）复用本人上次结果，按新报表发出、重新计 24 小时。
  • 超 30 秒或一个子站取不到数据：失败提示 + 重试，不发部分数据。
  • 限流排队，超 2 分钟提示排队超时。
  • 全部人员同时生成中的报表总数有上限（技术配置），超出提示「⏳ 排队中，稍后发出」，等待时间计入 2 分钟（N69）。
  • 发出前复核，不通过就取消，删除「正在生成 / 排队中」提示，本人随即可以再生成；切换服务机器人时已在生成、排队中的报表由原机器人发完（N50、N52）。
  • 发送限制（技术配置）：单个私聊每秒 1 条，整体每秒 24 条；删除消息也走同一队列，已登记人员的报表和菜单优先于未开通回复和删除消息（N51）。
公式
超时 ＝ 生成时间 > 30 秒（不含排队）
排队超时 ＝ 排队时间 > 2 分钟（含同时生成超上限的等待）
同一人员 + 同一查询 → 最多一个任务、最多发出一份报表

Telegram 机器人后端

F02-04子站停止出报表查看 PRD ›

要做什么
  • 总停用开关打开回复「报表服务暂停中，请稍后再试。」；没有可接替的机器人、且原机器人只是手动停用时回复「报表机器人暂不可用，正在更换，请稍后再试。」（「暂不可用」提示，N55）。
  • 原机器人疑似封禁或 Token 失效、又没有可接替的：全部子站和全网数据停止出报表，人员收不到回复，后台告警（N52）。
  • 之后有机器人可接替或原机器人恢复时自动恢复出报表（N52）。
  • 点按钮也回复消息，1 分钟后删除；另一子站照常。
  • 全网代理线查询跳过该站，统一注明「X 暂停中」。
公式
受影响 ＝ 该子站 ∪ 全网数据（全网代理线查询只跳过该站）
原机器人疑似封禁或 Token 失效且没有可接替的 → 全部子站 ∪ 全网数据，不回复
涉及端
Telegram 机器人后端

F03-01代理线查询查看 PRD ›

要做什么
  • 点代理线查询或发 /agent → 机器人要求回复账号，提问末尾「（请直接回复本条）」（回复提问才算查询）；「/agent 账号」直接搜索。
  • 搜到 1 个直接出报表；2 个及以上列按钮（最多 10 个）点选；报表含下级。
  • 没搜到回复未找到，输入框自动进入回复状态可直接重输。
  • 提问、结果、未找到最后一行都有「⬅ 返回上一级」「🏠 首页菜单」（N23–N25）。
  • 提问、结果、未找到算菜单消息，按 N60 删除；人员发的账号文字随对应结果一并删除。
公式
命中 ＝ 账号包含输入内容（不区分大小写）；开头匹配排前
范围：二级及以下 → 当前范围；一级菜单或 /agent → 全网数据（无权限 → 第一个有权限的子站），只查有权限且未暂停的子站

F03-02代理线权限查看 PRD ›

要做什么

  • 四种查询方式结果一致。
公式
统计用户 ＝ 代理线用户 ∩ 有代理线查询权限的子站 ∩（有「全站」权限 ? 全部 : 本人可查看渠道）

F04-01发出 24 小时自动删除查看 PRD ›

要做什么
  • 报表和失败提示 24 小时删除；拒绝回复 1 分钟删除（末行写删除时间）；子站停止出报表提示 1 分钟删除（N55）。
  • 未开通回复不删除；菜单类消息被本人下一条菜单替换时删除，未被替换的发出满 24 小时删除（N60）；更换通知发出满 24 小时删除（N67）；这两类不加删除时间行。
  • 各类消息何时删除、删除失败怎么处理，见 PRD 3.7 示例表。
公式
删除时间 ＝ 发出时间（GMT+8）+ 24 小时，写「⏱ MM-DD HH:mm 自动删除（GMT+8）」

F04-03删除失败处理查看 PRD ›

要做什么
  • 失败自动重试；每份报表由发出它的机器人删除，机器人停用或更换后仍删除自己发出的报表。
  • 发出满 48 小时仍未删除：后台标「未删除 N 份」并告警；后台管理员通知人员手动删除后清除标记（只计报表）。
  • 消息已不存在（手动删除、清空私聊、注销账号）视为成功，不计入；因屏蔽机器人等删不掉的，满 48 小时计入「未删除 N 份」（N28）。
  • 删除消息排在已登记人员的报表和菜单之后，实际删除时间可能晚几分钟（N51）。
公式
N ＝ 该机器人发出、满 48 小时仍未删除的报表份数

F05-01渠道配置查看 PRD ›

要做什么
  • 默认渠道全站、自然流量；自建最多 20 个，可设父级，层级不限。
  • 绑定代理树状勾选，至少一个；保存时对账拦截。
  • 标红「范围重叠」「无可用代理」；「菜单显示」开关；改动立即生效、不主动推送。
  • 名称 1–10 个字符；改名影响全网合并时输入框下方提示，直接保存。
公式
渠道数据 ＝ 所绑代理及全部下级代理名下用户
同一子站：一个代理（含下级）只属于一个顶层渠道；子渠道代理 ⊆ 父级范围
重叠时 → 以代理先进入的顶层渠道为准，换上级不改已有归属
查询任何日期 → 按查询时的绑定关系和用户当前所属代理

F05-04机器人管理查看 PRD ›

要做什么
  • 添加、改名称或用户名、换 Token、删除各子站同步（新机器人在另一站初始停用）；表单校验，保存时核对用户名与 Token 一致（不一致提示「用户名与 Token 不匹配」）；测试连接成功显示「连接正常：@实际用户名」。
  • Token 保存后页面和接口都只返回后 4 位，任何账号都看不到完整 Token（5.3）。
  • 各站分别启停；总停用开关只停本站，二次确认。
  • 页面顶部显示当前服务机器人和私聊链接，可复制。
  • 更换服务机器人：原机器人私聊通知在任一子站已登记并启用的人员（同一 ID 只发一次）；发不出时提示后台管理员转告链接并告警；非服务机器人收到私聊一律回复更换通知，@ 当前服务机器人；同一 Telegram ID 10 分钟内只回复 1 次，排在该机器人到期删除的报表之后（N67）。
  • 疑似封禁、Token 失效时全站自动停用；封禁处理和故障材料。
  • 「服务中」「未删除 N 份」标签；服务中、还有报表待删除、有未删除标记、原服务机器人更换未满 7 天的不能删除（5.3）；顶部告警；权限四项；操作日志（系统自动动作记 SYSTEM，跨子站同步的写入其他子站日志，N53）。
公式
服务机器人在任一子站被停用 → 切换到可接替的（全部子站启用；正常优先，限流中其次，再按添加时间）；在途报表由原机器人发完
没有可接替的：原机器人手动停用 → 该站和全网数据回复「暂不可用」提示；疑似封禁或 Token 失效 → 全部子站和全网数据停止出报表（N52）
没有可接替期间：任一机器人变为可接替 → 自动切换并通知人员；原机器人在被停用的子站重新启用、确认已恢复或更换 Token → 仍是服务机器人，直接恢复出报表；以先发生的为准（N52）
排序：正常、限流中在前，停用在后；同组按添加时间
