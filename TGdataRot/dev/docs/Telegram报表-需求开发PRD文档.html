    1. 项目概述

    项目说明
    需求描述新建一个 Telegram 报表机器人，在授权的 Telegram 群内使用：群成员通过输入框左侧「菜单」按钮和输入框下方的报表键盘，选择全站 / cicc / 短信 / 网红 / 谷歌 / oem 渠道，或输入代理账号，在一张表格里按列查看 789Bingo、789Games 和全站（两站合计）12 项指标的今日实时数据与昨日全天对比；报表发出满 1 小时或生成新报表时自动删除。两站管理后台【系统管理 › Telegram报表配置】新增渠道配置和授权群。
    背景与目标管理层和运营需要在手机上随时查看各推广渠道和代理线的当日核心数据，不必登录管理后台；报表含经营数据，需要限定查看人员并自动清除。
    范围做：机器人查询报表、两站后台配置。不做：定时推送、导出、修改后台现有报表。
    多端范围Telegram 群（手机、电脑客户端）：做；Telegram 私聊：不提供数据，只回复引导；789Bingo 后台、789Games 后台：做；玩家端 H5 / App：不涉及。
    时间与时区全部时间按 GMT+8；「今日」「昨日」按 GMT+8 自然日。

    1
    打开报表键盘：在群里点左下角「菜单」选 /menu，或直接发送 /menu → 机器人校验本群权限（见 2.2 权限分支）
    ↓
    2
    按钮矩阵：打开授权群即在输入框下方显示按钮矩阵
    ↓
    3
    选查询对象：点渠道按钮；或点「代理线查询」后发送代理账号（见 2.3 查询对象分支）
    ↓
    4
    生成报表：显示「正在生成报表…」→ 删除本聊天上一份报表 → 发出新报表
    ↓
    5

    2.2 权限分支（按聊天类型）

    A - 授权群

    发出菜单群内所有成员都可操作；报表只显示授权了该群的站点列

    B - 群聊 · 群已授权

    发出菜单群内所有成员都可操作；报表只显示授权了该群的站点列

    C - 私聊机器人

    回复引导「本机器人仅在授权群内使用，请在群内发送 /menu。」

    2.3 查询对象分支

    A - 点渠道按钮

    渠道报表全站或 cicc / 短信 / 网红 / 谷歌 / oem

    B - 发送代理账号

    代理线报表回复机器人的提问输入账号，或发送「/agent 代理账号」

    C - 代理账号在有权限的站点都不存在

    回复未找到提示不生成报表，不删除旧报表

    2.4 系统时序

    触发执行方动作
    收到命令、按钮点击或文字机器人服务按 N4 校验权限，无权限按 N5 回复
    点渠道、发送代理账号、重试机器人服务、两站数据按有权限的站点和查询对象，分站点统计生成时刻的数据并汇总全站列（N10–N22）
    新报表发出机器人服务删除本聊天之前未删除的报表和失败提示（N27），新报表开始计时
    报表发出满 1 小时机器人服务删除该报表（N26）
    后台保存渠道配置或授权群两站后台从下一次操作起按新配置执行（N8、N32）

    3.2 机器人、权限与渠道规则

    编号规则起因功能点
    N1机器人拉进群后，群输入框左侧显示蓝色「菜单」按钮（Telegram 机器人命令菜单），点开列出两个命令：/menu 打开报表键盘、/agent 按代理线查询；点命令等同发送该命令。发送本机器人的其他命令时回复「不支持该命令，请点左下角「菜单」选择命令。」用户要求：输入框旁按钮唤起菜单；界面按标准 Telegram 机器人样式F01-01 菜单按钮与命令
    N2机器人加入授权群后，群成员打开群时，输入框下方就显示报表按钮矩阵（Telegram 自定义键盘，浅灰圆角按钮，3 列网格），不需要先发命令：①「📊 全站」「📊 cicc」「📊 短信」/「📊 网红」「📊 谷歌」「📊 oem」；②「🔍 代理线查询」（整行）。
    点按钮等于在群里发出按钮上的文字：点渠道立即生成报表；点「🔍 代理线查询」按 N23 提示输入。同时，聊天里有一条机器人的菜单消息「请选择渠道，点渠道即生成报表：」，消息下方带内联按钮矩阵，按钮内容和顺序与输入框下方的按钮矩阵完全一致；点内联按钮不在群里发文字，直接生成报表或提示输入代理账号。进群时聊天里默认只有菜单消息和按钮矩阵，不自动显示任何报表；点哪个按钮才生成哪个报表。机器人加入授权群（或群被授权）时发出这条菜单消息，之后每次发 /menu 再发一条；菜单消息不自动删除。按钮矩阵对群内所有成员显示，成员可用输入框右侧「⌨」收起或展开；收起后也可在「菜单」里发 /menu 重新显示。菜单不按站点区分，站点在报表表格里按列显示（N22）。    		用户要求：进入群组时对话框里显示按钮矩阵；按标准 Telegram 界面；不用按钮区分新旧站F01-02 报表菜单
    N4权限按群、按站点判断：群 ID 在某站点后台的授权群名单中且状态为「启用」，群内所有成员都能查看该站点，不区分成员个人。私聊机器人一律不返回数据（N5）。报表只显示有权限站点的列；两站都有权限时才显示「全站」列（N22）。每次收到命令、按钮点击或文字时都重新判断。用户确认：针对 Telegram 群使用F01-03 授权校验
    N5群的两站都没有权限时，不显示菜单、不返回任何数据，回复「本群未开通报表权限，请联系管理员开通。本群 ID：群 ID」。任何人私聊机器人时，回复「本机器人仅在授权群内使用，请在群内发送 /menu。」，不显示菜单。群里既不是命令、不是报表键盘按钮文字、也不是回复机器人提问的普通消息，机器人一律不回应。方便管理员把群 ID 加进名单；避免机器人在群里刷屏F01-03 授权校验
    N6渠道归属：用户的当前所属代理是某渠道绑定的代理，或是绑定代理的下级（任意层级），就归入该渠道。用户的代理链上有多个已绑定代理时，按离用户最近的一个归属，一个用户只归入一个渠道。不属于任何渠道的用户只计入「全站」。「全站」为本站全部用户，不用配置。用户确认：后台配置渠道对应代理F05-01 渠道配置
    N7同一站点内，一个代理账号只能绑定一个渠道；添加已绑定到其他渠道的代理时提示「代理 账号 已绑定到渠道「渠道名」，同一代理只能绑定一个渠道」，不能添加。一个渠道可以绑定多个代理，数量不限。避免同一用户被重复统计到两个渠道F05-01 渠道配置
    N8渠道配置保存后，机器人在本站的授权群里重新发出菜单消息并更新按钮矩阵（按 N9 显示或隐藏渠道按钮）；下一次生成的报表按新配置统计，今日、昨日两列都按新配置重算；已发出的报表不变。用户换了所属代理后，按新的所属代理统计（历史数据也按新归属）。保证同一份报表里今日、昨日口径一致F05-01 渠道配置
    N9渠道按钮的显示（「全站」不用绑定，始终显示）：本群有权限的站点里，只要有一个站点给这个渠道绑定了代理，就显示这个渠道按钮；都没有绑定时，聊天里的菜单按钮和输入框下方的按钮矩阵都不显示该渠道，其余按钮按 3 列依次补位。点渠道生成的报表只显示已绑定代理的站点列，只剩一个站点时不显示「全站」列。渠道配置改动后，机器人在相关授权群里重新发出菜单消息并更新按钮矩阵（N8）；有人仍点旧按钮或手动发出未开放渠道的按钮文字时，回复「该渠道暂未开放，请选择其他渠道。」，不生成报表。用户 2026-11-04 要求：对应渠道未绑定时不显示该渠道按钮F01-02 报表菜单

    3.3 统计时段与指标口径

    下表口径对渠道报表和代理线报表通用，按站点分别统计查询对象范围内的用户（「全站」渠道为该站全部用户；其他渠道按 N6；代理线按 N24）。报表的「全站」列为两站合计：人数和金额直接相加；人均金额和留存率用两站合计的分子、分母重新计算，不是两站数值的平均。同一个人在两站各有账号时按两个用户计。测试账号是否计入与后台【平台报表】一致。

    编号指标 / 规则口径功能点
    N10统计时段「今日」= 今日 00:00:00 至报表生成时刻（GMT+8），为生成时刻的实时数据，报表上写明「今日截至 YYYY-MM-DD HH:mm（GMT+8）」；「昨日」= 昨日 00:00:00–23:59:59。「全站」渠道下各站点列的昨日数据，和该站后台【平台报表】昨日日报表一致；今日数据比平台报表（每 30 分钟统计一次）更新，两者可能有差异。具体实现由技术确定。F02-02 指标口径
    N11新增注册人数时段内注册成功的用户数（同平台报表「注册人数」）F02-02
    N12新增首存人数时段内完成账号第一笔成功存款的用户数，不限注册时间（同平台报表「首充人数」）F02-02
    N13新增玩家存款金额时段内注册的用户，在同一时段内成功存款的金额合计（同平台报表「新客充值金额」）F02-02
    N14存款额时段内全部成功存款金额合计（同平台报表「存款」）F02-02
    N15总投注额时段内总投注金额，与 GGR 的总投注口径一致F02-02
    N33有效投注额时段内有效投注金额，取后台【平台报表】「自算有效投注」口径F02-02
    N16存提差存款额（N14）− 时段内成功提款金额合计，可为负数（同平台报表「净存提」）F02-02
    N17人均首存金额时段内首笔存款金额合计 ÷ 新增首存人数（N12）；人数为 0 时显示「-」F02-02
    N18人均存款金额存款额（N14）÷ 时段内有成功存款的用户数（去重）；人数为 0 时显示「-」F02-02
    N19GGR时段内总投注 − 总派彩，可为负数F02-02
    N20次日留存「今日」列 = 昨天注册的用户中，今天 00:00 至生成时刻有登录的人数 ÷ 昨天注册人数 × 100%；「昨日」列 = 前天注册的用户中，昨天有登录的人数 ÷ 前天注册人数 × 100%。登录同用户留存报表「总访问」口径。分母为 0 时显示「-」。今日列只统计到生成时刻，通常低于全天。F02-02
    N217日留存「今日」列 = 7 天前（今天往前数第 7 天）注册的用户中，今天 00:00 至生成时刻有登录的人数 ÷ 该日注册人数 × 100%；「昨日」列 = 8 天前注册的用户中，昨天有登录的人数 ÷ 该日注册人数 × 100%。只看当天是否登录，不是 7 天内任意一天。分母为 0 时显示「-」。F02-02
    N22表格布局与显示格式报表按 4 组显示，组标题依次为「👥 用户」「💰 存提」「🎮 投注」「📈 留存」：用户组为新增注册人数、新增首存人数；存提组为新增玩家存款金额、存款额、存提差、人均首存金额、人均存款金额；投注组为总投注额、有效投注额、GGR；留存组为次日留存、7日留存。

    8. 上线方式

    • 上线前：运营在 Telegram 创建机器人账号（名称、头像按 Q4 结论），交技术接入；两站运营各自配置 5 个渠道的代理和授权群；把机器人拉进 3 个群。授权群配置：789Bingo 后台登记「789Bingo 数据群」和「两站汇总群」；789Games 后台登记「789Games 数据群」和「两站汇总群」。
    • 灰度：先只授权产品和运营负责人，核对全站昨日数据与后台平台报表一致后，再逐步加人、加群。
    • 回滚：在两站授权群把记录全部停用，机器人即对所有人停止返回数据；已发出的报表 1 小时内自动删除。
    • 上线后数据核对：连续 3 天核对全站和各渠道昨日数据与后台报表一致。

    11. 各角色协作 Tips

    • 准备一组跨渠道的代理链（父子分属两个渠道）验证 N6。
