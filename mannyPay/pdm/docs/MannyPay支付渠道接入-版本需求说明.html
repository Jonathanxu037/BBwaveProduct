MannyPay支付渠道接入 · 版本需求说明 · v1.0

更新日期：2026-11-04（GMT+8）适用：v1.0可见角色：产品、开发依据：需求开发 PRD 文档 和原型，规则和数值以 PRD 为准

一、一句话概述

按平台现有的资金渠道配置流程接入 MannyPay：在线支付配置新增一条 MannyPay 配置，前台 Wallet › Deposit 就多一个 GCash 类充值标签；绑定银行配置把代付渠道选为 MannyPay，提款就由 MannyPay（InstaPay）出款；财务总表、手续费、余额卡片、监控大盘同步加入 MannyPay。

二、业务流程图

充值

1
配置：在线支付配置新增支付类型 MannyPay，填支付名称（示例 GCash6）、金额、层设置，状态正常（N1）
↓
2
前台出现标签：对应层级的玩家在 Deposit 看到新标签（N1、N7）
↓
3
扫码付款：选标签 → 输入金额 → 提交 → MannyPay 二维码页 → GCash 扫码（N2、N3）
↓
4
入账：MannyPay 确认成功且金额一致 → 入账一次 → 充值成功弹窗（N5）
↓
!
异常（分支）：下单失败、未付款关闭、二维码过期、金额不一致；达到切换规则时坑位切到备用渠道（N3、N4、N6、N16）

提现

1
配置：绑定银行配置把银行的代付渠道选为 MannyPay（N8、N11）
↓
2
发起出款：自动代付，或运营在三方出款 / 重新出款里选 MannyPay（N9）
↓
3
出款中：MannyPay 走 InstaPay 代付，同一订单不能重复发起（N10、N12）
↓
4
结果：成功 → 出款成功；失败 → 出款异常单，换渠道重新出款或驳回（N12）
↓
!
失败原因（分支）：单笔超过 ₱50,000、渠道余额不足、收款账户无效或银行不支持（N10、N11、N12）

三、业务点说明

每张卡片固定 4 项：作用、逻辑、场景 → 方案、依据。金额单位 PHP，时间均为 GMT+8。

1. 充值标签（在线支付配置）

作用
让玩家在 Deposit 看到并使用 MannyPay。
逻辑
前台每个充值标签就是一条状态为「正常」的在线支付配置；「支付类型」下拉新增 MannyPay，表单字段和现有一致；标签名称取「支付名称」，前台不显示「MannyPay」字样。
场景 → 方案
场景方案
状态正常、玩家在层设置内显示标签
状态维护置灰，显示前台维护说明，不能选
状态停用 / 玩家不在层设置内 / 地区不可见不显示
依据
N1 · N7

2. 充值与入账

作用
玩家扫码付款后正确入账。
逻辑
可充区间 = 层级限额与配置最小 / 最大金额的交集；提交后生成处理中订单并打开 MannyPay 二维码页；MannyPay 确认成功且金额一致才入账，同一订单只入账一次。
场景 → 方案
场景方案
MannyPay 下单失败不打开支付页，提示「This method is unavailable. Please try another.」，计入渠道失败次数
关闭二维码页未付款回到充值记录页，订单保持处理中，不弹成功弹窗
二维码过期订单记为失败；有效期以 MannyPay 规则为准
过期记失败后又收到成功金额一致时改为成功并入账一次，发短信和 push，不补弹窗
重复成功通知只入账一次
金额不一致不自动入账，转人工核对；通过时按实付金额入账
签名校验不通过不处理，记录告警
停留期间配置改为维护 / 停用点「提交」不下单，提示换方式并刷新支付方式
依据
N2 · N3 · N4 · N5 · N6

3. 主备切换（支付渠道动态配置）

作用
主渠道异常时自动切到备用渠道，减少充值中断。
逻辑
MannyPay 配置可被选为其他配置的备用渠道，也可设自己的备用渠道（不能选本渠道）；满足现有 3 条动态调整规则之一即切换，切换后坑位名称不变，记入支付渠道调整记录。
场景 → 方案
场景方案
GCash3 达到切换规则，备用渠道为 MannyPay坑位改走 MannyPay，前台名称不变
切换前已生成的订单按原渠道处理
依据
N16

4. 代付渠道（绑定银行配置）

作用
指定哪些银行或电子钱包的提款由 MannyPay 出款。
逻辑
添加 / 编辑银行配置的代付渠道新增 MannyPay，列表「代付渠道」列直接显示；页面不区分银行是否支持 MannyPay，由运营只给 MannyPay 能出款的银行选择。修改只影响之后发起的出款。
场景 → 方案
场景方案
批量替换代付渠道为 MannyPay沿用现有
给 MannyPay 不支持的银行选了 MannyPay出款失败，转入出款异常单
依据
N8 · N11

5. 出款与失败处理（提款记录）

作用
运营可以用 MannyPay 出款，失败时有处理路径。
逻辑
三方出款的出款类型、重新出款的出款渠道新增 MannyPay，不按金额置灰；发起后订单出款中，不能重复发起；明确成功则出款成功；明确失败才转入出款异常单，异常原因显示「其它：MannyPay 返回的原因」；结果未知时保持出款中，查询确认后更新，不重新发起；转单后又收到成功时标记「疑似重复出款」并告警，由财务核对追回。MannyPay 出款纳入现有渠道熔断告警和切换记录。
场景 → 方案
场景方案
单笔超过 ₱50,000（InstaPay 上限）MannyPay 返回失败，转入出款异常单，换渠道重新出款
渠道余额不足 / 收款账户无效同上，异常原因显示返回信息
想减少大额失败运营可调整现有「大额提现拆单设置」（全局、GCash、Maya 分别设置；银行卡提现是否拆单以现有规则为准）
依据
N9 · N10 · N12

6. 手续费（手续费设置）

作用
记录 MannyPay 充值、出款的手续费。
逻辑
新增规则的充值 / 出款渠道新增 MannyPay；手续费模式、类型、值、状态沿用现有；同一类型 + 渠道只能有一条启用的规则；保存后之后成功的订单按新规则计算，已成功的不重算。
场景 → 方案
场景方案
重复新增启用的同类规则提示「该渠道已有启用的规则」
依据
N13

7. 报表、余额与监控

作用
按渠道看 MannyPay 的数据和账户余额。
逻辑
财务总表的充值 / 出款渠道筛选、监控大盘的渠道标签新增 MannyPay，口径沿用现有；财务数据新增「资金余额(MannyPay)」，展示逻辑和现有资金余额卡片一致。
场景 → 方案
余额显示
≥ ₱5,000,000正常
≥ ₱2,000,000 且 < ₱5,000,000黄色
< ₱2,000,000红色
查询失败显示「-」和「查询失败，请稍后刷新」
依据
N14 · N15

四、关键点汇总

① 关键规则与数值

项目规则 / 数值
收款方式QRPh 二维码，玩家用 GCash 扫码
出款通道InstaPay，单笔上限 ₱50,000；超额由 MannyPay 返回失败
入账成功且金额一致才入账，同一订单只入账一次
余额预警< ₱5,000,000 黄色，< ₱2,000,000 红色（固定）
主备切换沿用现有 3 条动态调整规则
不做PESONet 出款、Scan-to-Pay、Intrabank 划转、前台提款页改动

② 未完全确认的问题

  • QA 当前没有出款异常单，「重新出款」弹窗的现有渠道选项未在 QA 核对，上线前按现有后台核对。
  • 前台标签名称「GCash6」只是示例，实际以运营配置的「支付名称」为准。

③ 需运营确认

  • MannyPay 配置的支付名称、层设置、最小 / 最大金额和排序。
  • 入款、出款手续费值（按与 MannyPay 约定的标准）。
  • 哪些银行的代付渠道切换为 MannyPay（只选 MannyPay 能出款的银行）。
  • 是否调整「大额提现拆单设置」来减少超额失败。
