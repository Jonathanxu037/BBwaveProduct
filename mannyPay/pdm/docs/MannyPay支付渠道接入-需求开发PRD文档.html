    0. 本迭代范围

    本迭代按现有资金渠道配置流程接入 MannyPay：收款时在「在线支付配置」新增一条 MannyPay 配置，前台 Deposit 多一个可配置的 GCash 类标签（QRPh 二维码）；出款时作为代付渠道（InstaPay），并把 MannyPay 加入现有的配置、主备切换、出款、报表和监控入口。与其他章节冲突时，以本章为准。

    类别本迭代包含顺延至
    前台（H5 / iOS / Android）Deposit「Payment Method」新增一个 MannyPay 标签（名称由后台配置，示例 GCash6）；到账、记录沿用现有；Withdraw 页不改-
    后台 · 入款在线支付配置新增支付类型 MannyPay；支付渠道动态配置中 MannyPay 可作其他配置的备用渠道，也可设自己的备用渠道-
    后台 · 出款绑定银行配置、三方出款、重新出款新增 MannyPay（代付走 InstaPay）；出款结果和失败处理沿用现有-
    后台 · 财务与监控财务总表、手续费设置、财务数据余额卡片、监控大盘新增 MannyPay-
    不包含MannyPay 的 PESONet 出款（单笔 > ₱50,000）、扫码付款（Scan-to-Pay）、资金划转到 AllBank OPC 账户（Intrabank）；前台提款页不改不顺延（见 Q3、Q7）

    1. 项目概述

    项目说明
    需求描述在管理后台【充值配置 › 在线支付配置】的「支付类型」新增 MannyPay，运营新增一条 MannyPay 配置后，前台 Wallet › Deposit 的「Payment Method」多一个标签（名称取「支付名称」，示例 GCash6）；【充值配置 › 绑定银行配置】和【财务管理 › 提款记录】的代付渠道新增 MannyPay，并在【支付渠道动态配置】【财务总览】【平台概况】加入 MannyPay；其余充值、提款规则沿用现有。
    背景与目标平台新增第三方支付渠道 MannyPay（依据：MannyPay API v1.2 文档）。目标：GCash 收款多一条可与现有标签互为主备的渠道，出款多一条代付渠道，主渠道异常时可切换，降低出入金中断风险。
    范围做：第 0 章「本迭代包含」。不做：第 0 章「不包含」。
    多端范围H5、iOS、Android：做（充值页同一套规则）；后台：做；PC：沿用 H5。
    时间与时区全文时间为 GMT+8。

    2. 整体业务流程

    2.1 充值主流程（用户视角）

    1
    选择支付方式：Wallet › Deposit → 选 MannyPay 标签（示例 GCash6）→ 输入或点选金额
    ↓
    2
    下单：点「提交」→ 平台生成处理中订单 → 打开 MannyPay 二维码支付页（下单失败见 7. 接口与异常）
    ↓
    3
    扫码付款：用户在 MannyPay 支付页用 GCash 扫码付款
    ↓
    4
    到账：MannyPay 确认支付成功 → 平台入账 → 弹出现有充值成功弹窗（见 2.2 充值结果分支）

    2.2 充值结果分支（按 MannyPay 结果）

    A - 支付成功
    入账金额一致才入账，同一订单只入账一次
    ↓
    充值成功弹窗沿用现有
    B - 未付款就关闭支付页
    订单保持处理中不弹成功弹窗
    ↓
    之后付款仍正常入账过期未付款则记为失败
    C - 支付失败 / 过期
    订单失败不入账
    ↓
    充值记录显示失败用户可重新充值

    2.3 出款主流程（运营视角）

    1
    配置代付渠道：绑定银行配置 → 支持 MannyPay 的银行代付渠道设为 MannyPay（自动或手动代付沿用现有）
    ↓
    2
    发起出款：自动代付由系统发起；手动时在待处理订单「出款 › 三方代付」或出款异常单「重新出款」选 MannyPay
    ↓
    3
    发起代付：向 MannyPay 发起 InstaPay 代付 → 订单「出款中」
    ↓
    4
    出款结果：明确成功 → 出款成功；明确失败 → 转入出款异常单；结果未知 → 保持出款中（见 N12）

    2.4 系统时序

    触发执行方动作
    用户点「提交」平台校验金额 → 生成处理中订单 → 向 MannyPay 申请二维码 → 打开支付页
    用户付款MannyPay → 平台MannyPay 通知支付结果；平台核对订单和金额后入账或记失败；没收到通知时平台主动查询（时效由技术确定）
    运营或系统发起出款平台 → MannyPay发起 InstaPay 代付 → 订单出款中 → 取得结果后更新订单
    打开财务数据页平台 → MannyPay查询 MannyPay 余额 → 按阈值显示颜色

    3.2 本需求规则

    编号规则起因功能点
    N1在线支付配置的「支付类型」下拉新增 MannyPay（收款方式为 QRPh 二维码，玩家用 GCash 付款）；可配多条，表单字段（含对接参数）和必填校验与现有支付类型一致。MannyPay 是独立的支付类型，不进入现有「收款渠道切换」（QRPH / BANKCARD 同一时间只能启用一个渠道的规则不适用），不影响 Bank Card（QRPH）。状态为「正常」时前台 Deposit 新增一个标签：名称取「支付名称」（运营填写，示例 GCash6），前台不显示「MannyPay」字样；图标沿用现有 GCash 类标签图标；排序、层设置、不可见地区按配置。其他标签不受影响。接入新渠道F02-01 在线支付配置新增 MannyPay
    N2可充区间 = [配置最小金额, min(层级每笔最高充值, 配置最大金额)]，金额为整数 PHP；当日累计充值受层级「当日最高充值」限制（沿用现有）。不在区间内提示「Please enter an amount between x-xxx」（沿用现有）。后台最小金额、最大金额为 ≥ 1 的整数；最小金额大于最大金额时不能保存，提示「最小金额不能大于最大金额」。沿用现有限额规则F01-01 充值方式展示与金额校验
    N3点「提交（Submit）」后生成状态为「处理中」的充值订单并打开 MannyPay 二维码支付页。MannyPay 下单失败或超时时不打开支付页，订单记为失败，前台提示「This method is unavailable. Please try another.」（线上已有同类提示时用线上文案），并计入该渠道下单失败次数（触发 N16 动态切换）。按钮提交中置灰，重复点击只生成一笔订单。二维码由 MannyPay 生成F01-02 二维码支付
    N4二维码有效期以 MannyPay 规则为准，平台不另设；过期仍未付款的订单按平台现有充值订单超时规则记为「失败」，上线前核对平台超时时间不短于二维码有效期。已记失败的订单之后收到 MannyPay 成功结果且金额一致时：订单改为「成功」并入账一次，发到账短信和 push，状态变更写入订单日志；玩家不在充值页时不补弹成功弹窗。金额不一致按 N5 人工核对。Q1 确认：以平台现有规则和 MannyPay 规则为准F01-03 支付结果与入账
    N5只有 MannyPay 确认支付成功（推送通知或平台查询结果）且金额与订单一致时入账，订单变「成功」并弹出现有充值成功弹窗。同一订单只入账一次，重复通知不重复入账；签名校验不通过的通知一律不处理，并记录告警。金额不一致时不自动入账，订单进入人工核对（沿用现有充值记录「通过 / 驳回」）：通过时按 MannyPay 确认的实付金额入账，赠送和流水按实付金额计算，记录操作人；驳回时不入账，订单记为失败。到账短信和 push 按现有规则发送。资金安全；账变短信门槛（规范第五章第 2 节）F01-03 支付结果与入账
    N6用户未付款就关闭二维码支付页时，回到充值记录页并显示该笔「处理中」订单，不弹成功弹窗；之后付款成功仍按 N5 入账。处理中订单计入现有「未处理线上充值订单数上限」。沿用现有回跳规则F01-03 支付结果与入账
    N7配置状态「正常」：前台显示可选；「维护」：前台置灰、显示「前台维护说明」，不能选；「停用」：前台不显示。状态为维护时维护说明必填，未填提示「状态为维护时请填写前台维护说明」；维护说明由运营用英文填写。保存后用户下一次打开充值页生效，已生成的订单不受影响。玩家停在充值页期间配置有变化时，点「提交」按最新配置校验：已维护或停用的不下单，提示「This method is unavailable. Please try another.」并刷新支付方式；坑位已切到备用渠道的，按备用渠道下单。沿用现有状态规则F02-01 在线支付配置新增 MannyPay
    N8绑定银行配置的代付渠道新增 MannyPay（单选，与 PayMongo、CoinPH、UnionBank、Dragonpay、Paycools、Starpay 并列）；代付方式自动 / 手动沿用现有。修改后只影响之后发起的出款，出款中的订单不受影响。批量替换代付渠道沿用现有：原代付渠道为所选渠道的银行全部替换为新渠道，可替换为 MannyPay；系统不判断银行是否支持 MannyPay，由运营替换前自行确认。新代付渠道F03-01 绑定银行配置新增 MannyPay
    N9待处理订单「出款 › 三方代付」的出款类型、出款异常单「重新出款」的出款渠道新增 MannyPay；选择后点「确定 / 确认发起」即向 MannyPay 发起代付，未选择时提示「请选择出款渠道」。人工出款入口F03-02 三方出款
    N10按平台现有方式处理：三方出款、重新出款、自动代付都可以选 MannyPay，不按金额置灰或拦截。MannyPay 代付走 InstaPay，单笔上限 ₱50,000，按实际出款金额（扣除手续费后）判断（口径见 Q10）；超过时 MannyPay 返回失败，订单按 N12 转入出款异常单，运营换其他渠道重新出款。大额提现拆单按现有设置执行（全局、GCash、Maya 分别设置；银行卡提现是否拆单以现有规则为准，见 Q9），是否调整由运营决定。Q3 确认：按平台现有方式，其他代付渠道没有按渠道的单笔上限F03-04 出款通道与结果
    N11绑定银行配置不新增列、不区分银行是否支持 MannyPay，只在「添加 / 编辑银行配置 › 代付渠道」里新增 MannyPay，由运营只给 MannyPay 可出款的银行选 MannyPay。收款银行 MannyPay 不支持时出款失败，按 N12 转入出款异常单。Q4 确认F03-01 绑定银行配置新增 MannyPay
    N12发起后订单变「出款中」，出款和驳回按钮置灰，同一订单不能再次发起；排队、无响应和超时的显示沿用现有待处理订单状态（三方排队中 / 三方无响应、等待时长 / 是否超时）。按 MannyPay 结果处理：① 明确返回成功 → 「出款成功」；② 明确返回失败（如渠道余额不足、收款账户无效、超过单笔上限）→ 订单转入「出款异常单」，异常原因显示「其它：MannyPay 返回的原因」，之后按现有流程重新出款或驳回；③ 结果未知 → 保持出款中，由平台查询确认，不重新发起，超过 30 分钟仍无结果由运营转技术核查。只有明确返回失败才转入异常单。已转入异常单或已换渠道出款后又收到 MannyPay 成功结果：不改变现有出款结果，提款记录中标记「疑似重复出款」并告警，由财务核对追回。MannyPay 返回成功但玩家未到账：按现有出款异常单补单流程处理，补单前先向 MannyPay 查询确认。防重复出款F03-04 出款通道与结果
    N13手续费设置「新增规则」的渠道下拉，类型为充值和提款时都新增 MannyPay；手续费模式（固定 / 阶梯费率）、手续费类型（按笔 / 按费率）、手续费值、备注、状态沿用现有，手续费值由运营按与 MannyPay 约定的标准配置，PRD 不写死（Q2）。手续费值 ≥ 0，最多 2 位小数。同一类型 + 同一渠道只能有一条启用的规则，重复时提示「该渠道已有启用的规则」。规则保存后，之后成功的订单按新规则计算，已成功的订单不重算。沿用现有手续费规则F04-02 手续费设置
    N14财务总表的充值渠道、出款渠道筛选新增 MannyPay；监控大盘「业务指标实时监控」渠道标签新增 MannyPay，充值成功率、提款成功率只统计 MannyPay 订单，口径沿用监控大盘现有口径（见 6.4）。订单按实际下单的渠道统计：主备切换后的订单计入 MannyPay；MannyPay 有多条配置时合并为一个渠道统计。新渠道纳入报表和监控F04-01 财务总表渠道筛选

    8. 验收标准

    8.1 验收条目

    1. F02-01 新增 MannyPay 配置、支付名称填 GCash6、状态正常 → 保存成功，前台对应层级的用户在 Deposit 看到 GCash6 标签，其他标签不变。
    2. F02-02 GCash3 的备用渠道设为 GCash6（MannyPay），GCash3 满足任一动态调整规则 → 坑位切到 MannyPay，前台名称不变，支付渠道调整记录新增一条；切换前已生成的订单仍按 PayMongo 处理。
    3. F02-02 设置 GCash6 的备用渠道 → 下拉里没有 GCash6 本身；把备用渠道改为维护后 GCash3 满足切换规则 → 不切换，保持 GCash3。
    4. F01-01 配置区间 ₱100–₱50,000、层级每笔最高充值 ₱30,000：输入 99 和 30,001 → 提示区间错误；输入 100 和 30,000 → 可提交。绕过前端直接下单同样拦截。
    5. F01-01 状态改为维护 → 前台置灰并显示维护说明；停用 → 前台不显示。
    6. F01-02 点「提交」→ 打开 MannyPay 二维码页，充值记录新增一笔处理中订单；连续点两次只生成一笔。
    7. F01-02 MannyPay 下单失败 → 不打开支付页，提示「This method is unavailable. Please try another.」。
    8. F01-02 停在充值页时后台把 GCash6 改为维护 → 点「提交」不下单，提示「This method is unavailable. Please try another.」，支付方式刷新为置灰。
    9. F01-03 扫码付 ₱500 → 余额 +₱500，弹出充值成功弹窗；重复推送同一成功通知 → 余额不再增加。
    10. F01-03 关闭二维码页不付款 → 订单处理中，不弹成功弹窗；二维码过期 → 订单失败。
    11. F01-03 过期记失败的订单收到金额一致的成功结果 → 订单改为成功，余额只增加一次，收到短信和 push，不弹成功弹窗。
    12. F01-03 订单 ₱500、实付 ₱400 → 订单处理中不入账；运营人工通过 → 余额 +₱400，赠送和流水按 ₱400 计算，记录操作人；驳回 → 订单失败。
    13. F01-03 充值 ₱100（GCash6 最小金额）到账 → 短信和 push 都收到；后台把最小金额改为 0 → 不能保存。
    14. F03-01 编辑 UB 的代付渠道选 MannyPay 并确定 → 列表「代付渠道」显示 MannyPay，之后提款到 UB 的订单由 MannyPay 出款；出款中的订单不受影响。
    15. F03-04 给 MannyPay 不支持的银行选了 MannyPay 后出款 → 出款失败，订单转入出款异常单，异常原因显示 MannyPay 返回的原因。
    16. F03-04 实际出款金额 ₱50,000.00 和 ₱50,000.01 → 都可以选 MannyPay；₱50,000.01 的订单 MannyPay 返回失败 → 订单转入出款异常单，异常原因显示 MannyPay 返回的信息，可换其他渠道重新出款；自动代付遇到 ₱50,000.01 的订单 → 照常发起，失败后同样转入出款异常单。
    17. F03-04 「大额提现拆单设置」的单笔最大出款金额设为 ₱50,000 后，用户提现到 GCash ₱120,000 → 按现有拆单规则拆成多笔子订单，每笔 ≤ ₱50,000，走 MannyPay 都能出款成功（拆单规则沿用现有）。
    18. F03-02 选 MannyPay 出款后 → 订单出款中，出款和驳回按钮置灰；MannyPay 返回成功 → 出款成功。
    19. F03-04 MannyPay 返回余额不足 → 订单转入出款异常单，异常原因「其它：渠道余额不足」；选其他渠道重新出款并成功 → 订单变为出款成功，离开出款异常单。
    20. F03-04 订单转入出款异常单并换渠道出款后，MannyPay 又返回成功 → 出款结果不变，提款记录标记「疑似重复出款」并告警。
    21. F03-04 MannyPay 出款连续失败达到现有熔断条件 → 异常记录出现 MannyPay 告警。
    22. F04-01 财务总表筛选充值渠道 MannyPay → 只显示 MannyPay 数据，笔数与充值记录一致。
    23. F04-02 新增「提款 + MannyPay」规则 ₱10 → 之后成功的 MannyPay 出款手续费为 ₱10；再新增同一类型同一渠道的启用规则 → 提示「该渠道已有启用的规则」；手续费值填 -1 或 1.234 → 不能保存，填 0 或 1.23 → 可保存。
    24. F04-03 余额 ₱5,000,000.00 → 正常；₱4,999,999.99 → 黄色；₱2,000,000.00 → 黄色；₱1,999,999.99 → 红色；查询失败 → 显示「-」。
    25. F04-04 监控大盘选 MannyPay → 成功率只统计 MannyPay 订单。

    9. 上线方式

    • 上线时：① 状态为「停用」时填写对接参数；② 层设置只选测试层级，状态改为「正常」；③ 用测试层级账号收款、出款各验证一笔。
    • ④ 验证通过后：层设置放开到目标层级；观察期成功率目标见 Q14；绑定银行配置按需把银行切到 MannyPay。
    • 回滚：在线支付配置改为停用；绑定银行配置批量替换回原代付渠道。出款中的 MannyPay 订单按 N12 等结果，不重新发起。

    10. 风险与依赖

    风险等级应对
    重复入账或重复出款造成资金损失高N5、N12：只入账一次；出款中不能再次发起；结果未知先查询；明确失败才转异常单，转单后又成功的标记「疑似重复出款」并告警
    MannyPay 余额不足导致出款大面积失败中N15 余额预警；N17 纳入渠道熔断告警；大面积失败时批量替换代付渠道换回原渠道；失败订单转入异常单后换渠道重新出款
    单笔 > ₱50,000 的 MannyPay 出款会失败，需人工换渠道中按现有出款异常单流程处理；运营可按需调整大额提现拆单设置（N10）
