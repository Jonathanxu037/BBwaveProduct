MannyPay支付渠道接入 · 需求要点 · v1.0

版本：v1.0端：H5 / iOS / Android / 后台依据：需求开发 PRD 文档

一句话需求

在管理后台【充值配置 › 在线支付配置】的「支付类型」新增 MannyPay，运营新增一条 MannyPay 配置后，前台 Wallet › Deposit 的「Payment Method」多一个标签（名称取「支付名称」，示例 GCash6）；【充值配置 › 绑定银行配置】和【财务管理 › 提款记录】的代付渠道新增 MannyPay，并在【支付渠道动态配置】【财务总览】【平台概况】加入 MannyPay；其余充值、提款规则沿用现有。

业务流程

1
配置：在线支付配置新增一条支付类型为 MannyPay 的配置（支付名称、层设置、金额、状态正常）→ 前台 Deposit 出现新标签
↓
2
充值：选新标签 → 输入金额 → 点「提交」→ 打开 MannyPay 二维码页 → 用 GCash 扫码付款
↓
3
入账：MannyPay 确认成功且金额一致 → 入账一次 → 充值成功弹窗
↓
4
出款：银行代付渠道为 MannyPay 或人工选 MannyPay → 走 InstaPay → 出款中 → 成功或转出款异常单
A - MannyPay 出款成功

出款成功InstaPay 实时到账

B - MannyPay 返回失败

转入出款异常单如单笔超过 ₱50,000、余额不足、账户无效；换渠道重新出款

F01-03支付结果与入账查看 PRD ›

要做什么

  • 未付款关闭保持处理中；二维码有效期以平台现有规则和 MannyPay 规则为准，过期记失败（N4、N6）

F02-02主备渠道查看 PRD ›

要做什么
  • 支付渠道动态配置里 MannyPay 配置可被选为其他配置的备用渠道，也可设自己的备用渠道；沿用现有 3 条动态调整规则和切换记录（N16）
公式
满足任意 1 条即切换：① 单用户连续失败 ≥ N 次且累计 ≥ M 人；② 最近 X 分钟成功率 < Y%；③ 最近 X 分钟下单失败率 ≥ Z% 或失败次数 ≥ K 次
涉及端
后台前台（坑位名称不变）

F03-04出款通道与结果查看 PRD ›

要做什么
  • MannyPay 代付走 InstaPay，不按金额置灰或拦截；单笔超过 ₱50,000 由 MannyPay 返回失败（N10）
  • 出款中不能重复发起；失败转出款异常单并记原因；结果未知保持出款中，查询确认后更新（N12）
公式
无（失败处理沿用现有出款异常单流程）
