后台活动奖励领取限制配置

各活动配置页新增「活动奖励领取限制」板块（淡色光晕为新增内容）。有列表的活动，加在「创建活动」「修改」（或「编辑」）打开的配置页；没有列表的，加在进入菜单直接显示的配置页。各活动的入口和接入方式见 PRD 5.1（活动配置页：活动奖励领取限制板块）。

规则批注

  1. 适用范围：活动按 A–D 四种方式接入（见下一条），板块位于现有配置之后、「保存」之前；用户领取、系统自动发放、审核、人工和批量发放都按该活动的配置判定。PRD 规则 N1、N19 · F02-01 活动奖励领取限制板块
  2. 接入方式：A 完整接入（两项 + 领取限制白名单，以后新增的活动也按 A）；B 两项 + 沿用活动原白名单（不显示领取限制白名单）；C 只加同设备（IP 沿用活动现有条件，先判断现有 IP 限制，再判断同设备）；D 不改（新用户转盘、完成任务砸金蛋，不加板块）。各活动的方式见 PRD 5.1。演示：切换上方各场景，对比板块差异。PRD 规则 N14、N17 · F02-02 活动接入方式
  3. 两项配置：同设备、同 IP（C 方式只有同设备），每项有勾选框、限制周期（活动期间 / 每天 / 7 天 / 15 天 / 一个月）；单次领取类活动另有最多领取次数，不勾选或填 0 为不限制；多次领取类活动不显示次数，该位置显示灰字「只允许首个领取的账号领取」，不勾选为不限制。新建活动时各项都不勾选，限制周期默认「活动期间」；活动原有限制已有统计周期的（C 方式，如每日首充原有 IP 限制按每天），新增项的周期固定沿用原有周期「每天」、不可选（演示：「每日首充活动」）；新用户首充（单次领取类）例外，同设备项显示下拉，可选五种周期，默认「活动期间」；不设同账户项（单个账号的次数沿用活动自身规则）。各活动的领取类型见 PRD 5.1。演示：对比「KYC认证送彩金活动」（单次）和其他场景（多次）。PRD 规则 N2、N4、N18
  4. 单次领取类：次数口径：每个账号只能领一次，按本活动成功发放的次数统计，同设备、同 IP 为所有账号合计，次数即该设备或 IP 上能领取的账号数；不同活动分别计算。PRD 规则 N3
  5. 多次领取类：绑定首个领取的账号：勾选后，限制周期内首个在该设备（或 IP）成功领取本活动的账号与之绑定，其他账号领取本活动的任何奖励都被拦截（同设备 L01、同 IP L02）；绑定账号自己的多次领取按活动原规则；同设备、同 IP 分别绑定。解除绑定：「每天」「一个月」在下一个周期开始时解除；「7 天」「15 天」按滚动窗口，领取当天往前 7 / 15 个自然日内该设备（或 IP）有其他账号成功领取过即拦截，否则可以领取并成为新的绑定账号（例：选 7 天，账号 A 最后一次在设备 X 领取是 2026-11-04，账号 B 在 2026-11-10 被拦截，2026-11-11 可以领取）；「活动期间」一直绑定。PRD 规则 N18
  6. 保存校验（只对单次领取类的次数）：勾选后次数必填，为 0–9999 的整数；为空时提示「请输入最多领取次数」，不是 0–9999 的整数时提示「请输入 0–9999 的整数」，两种情况都不能保存，焦点停在出错的输入框。演示：点「保存校验提示」，或在 KYC认证送彩金活动清空次数、填 1.5 后点「保存」。PRD 规则 N13 ①
  7. 生效：随活动保存，保存后立即生效；活动进行中修改设置，已领取次数不清零，取消勾选期间成功发放的次数同样计入；复制活动时一起复制；留痕沿用【日志管理 › 操作日志】。PRD 规则 N13 ②–⑤
  8. 审核、人工和批量发放：① 审核发放：申请时被拦截不生成申请，Toast「奖励领取限制[编号]」；审核时被拦截，【派奖审核】和该活动「活动统计」的这条记录显示「奖励领取限制[编号]」，默认不发放，玩家申请记录沿用「未通过」，审核人可以强制通过（照常发放、计入次数、不改变已有绑定）。转盘、抽奖类只在转动前判定，中奖后进入派奖审核的，审核时不再判定。② 人工发放、批量发放：被拦截的记录显示原因，不随批量发出；不能强制发放，确需发放走现有【修改余额审批】人工加款。本页不演示审核和发放页面。PRD 规则 N19
  9. 领取限制白名单（只在 A 方式显示）：沿用后台现有白名单导入组件（导入文件、已导入文件下载、导入结果统计），不改组件；每个活动单独导入，只对本活动生效，随活动「保存」生效。名单内会员跳过同设备、同 IP 判定，其领取仍计入该设备和该 IP 的次数。演示：点「导入文件」查看导入结果。PRD 规则 N15 · F02-03 领取限制白名单
  10. 活动白名单是否受限制：活动自身有白名单（参与名单、指定名单、指定奖励名单）时，同设备、同 IP 每项下方多一个勾选框「本活动白名单用户也受此限制」，默认勾选。勾选：名单中的会员同样按该项判定，右侧灰字「（名单内会员也按此项限制）」；不勾选：名单中的全部会员跳过该项判定，其领取仍计入该设备和该 IP 的次数（多次领取类同样绑定该设备和 IP），右侧灰字「（名单内全部会员不受此项限制）」。活动没有自身名单时不显示。B、C 方式「沿用原白名单」，即通过这个勾选框决定名单内会员是否受限。领取限制白名单中的会员始终跳过两项判定。演示：点「导入签到活动（活动有自身名单）」「修改活动配置页」（老用户充值转盘）「每日首充活动」，对比「KYC认证送彩金活动（活动无自身名单）」。PRD 规则 N16 · F02-01 活动奖励领取限制板块

评审待确认

  2. 未列入的活动与分批上线：已确认：邮箱认证奖励按 A 接入，其余无菜单活动由技术确认是否在用；全部活动一次上线。PRD 待确认 Q7
