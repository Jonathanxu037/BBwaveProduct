单一设备领取奖励限制 · 需求要点 · v1.0

版本：v1.0端：H5、PWA、iOS、Android、管理后台依据：需求开发 PRD 文档

一句话需求

【活动中心】下每个活动的配置页增加「活动奖励领取限制」板块：可勾选同设备、同 IP，每项设置限制周期（活动期间 / 每天 / 7 天 / 15 天 / 一个月）和最多领取次数，填「0」为不限制。用户领取和系统发放前按配置判定，超过次数不发放，前台提示「奖励领取限制[编号]」。白名单沿用后台现有白名单导入功能，名单内会员不受这两项限制。

判定流程

只判断已勾选且次数大于 0 的项。拦截时不发放、不扣参与次数，自动发放不提示（N6、N8）。需判定的设备标识或 IP 取不到时暂不发放，提示「奖励领取限制[L03]」（N11）。

开发功能点

F01-01领取次数限制判定查看 PRD ›

要做什么
  • 活动现有校验通过后、发放前，按 同设备 → 同 IP 判定；用户领取、自动发放、充值到账都判定（N1、N5、N8）
  • 次数 = 本活动成功发放的次数，同设备、同 IP 为所有账号合计；不同活动分别计算（N3）
  • 周期：活动期间（上线后累计）、每天（自然日）、7 天 / 15 天（含当天往前滚动）、一个月（自然月），均按 GMT+8（N4）
  • 单账号次数沿用活动自身规则（N9）；自动发放取账号最近一次登录的设备和 IP（N8）
  • 同 IP 含移动网络共用出口 IP 的账号，次数按活动参与规模设置（N10）
  • 并发时合计成功次数不超过上限；重复点击只发放一次（N12）
  • ※ 现有设备标识能否唯一区分手机待技术确认（Q3），确认前不建议勾选同设备；本版不考虑跨浏览器、浏览器和 App 之间、清缓存或重装后的设备识别（N10）
公式
该项已领取次数 ≥ 最多领取次数（次数大于 0，当前限制周期内）→ 拦截
同设备 / 同 IP 已领取次数 = 该设备 / IP 上所有账号在当前周期内成功领取本活动的次数之和
涉及端
H5 / PWAiOSAndroid后端

F01-02拦截处理与提示查看 PRD ›

要做什么
  • 不发放、不扣参与次数、不计次数；转盘和抽奖在转动前拦截；按钮保持可点（N6）
  • Toast「奖励领取限制[编号]」：L01 同设备达上限、L02 同 IP 达上限、L03 取不到设备标识或 IP
  • 充值优惠：选择时超过 → 置灰并显示「奖励领取限制[编号]」；到账时超过 → 不发优惠，充值照常到账，不新增通知（N7）
公式
无
涉及端
H5 / PWAiOSAndroid后端

F01-03设备标识或 IP 获取失败处理查看 PRD ›

要做什么

F02-01活动奖励领取限制板块查看 PRD ›

要做什么
  • 所有活动（含以后新增）的配置页加板块：有列表的加在「创建活动」「修改」打开的配置页，无列表的加在直接显示的配置页（清单见 PRD 5.1）
  • 同设备、同 IP 各一行：勾选框、限制周期、最多领取次数（0–9999 整数，0 为不限制）；默认不勾选；不设同账户项（N2）
  • 随活动保存后立即生效；修改后已领取次数不清零；复制活动时一起复制；留痕沿用现有操作日志（N13）
公式
无
涉及端
管理后台后端

F02-03领取限制白名单查看 PRD ›

要做什么
  • 沿用后台现有白名单导入组件（导入文件、已导入文件下载、导入结果统计、保存、重置），放在板块最后一行，不改组件（N15）
  • 每个活动单独导入，随活动保存生效；名单内会员跳过同设备、同 IP，其领取仍计入设备和 IP 次数
  • 复制活动不复制白名单
公式
无
涉及端
管理后台后端

F02-02新用户转盘原配置并入查看 PRD ›

要做什么
  • 去掉原有设备、IP 两项，改用本板块（N14）
  • 上线迁移：设备项 → 「同设备 · 活动期间 · 原值」；IP 项口径不同，不迁移，上线当天由运营填写
  • 原白名单导入和已导入名单保留，作为本活动的领取限制白名单
