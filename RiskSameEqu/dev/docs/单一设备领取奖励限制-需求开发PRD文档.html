    0. 本迭代范围

    本需求只做一期，789Bingo（老站）、789Games（新站）两个站都做，Jira 按站点分别建单（老站标【B】、新站标【G】）。与其他章节冲突时，以本章为准。

    前台（H5、PC、PWA、iOS、Android）和系统发放用户领取和系统发放前按配置判定，超过上限不发放；一个账号能多次领取的活动，同一设备、同一 IP 只允许前 N 个领取的账号领取（N18）；用户领取被拦截时，提示带编号的限制文案（N3–N12、N19）-

    1. 项目概述

    项目说明
    需求描述后台【活动配置 › 活动限制管理】列出【活动中心】的全部活动（分期的活动每期一行），运营对每个活动（每期）统一配置三个条件（N17）：同设备、同 IP 可勾选，每项设置限制周期（活动期间 / 每天 / 7 天 / 15 天 / 一个月）和数量（单次领取类为最多领取次数，多次领取类为最多账号数），填「0」为不限制；领取限制白名单可单独导入，名单内会员不受这两项限制（N15）。领取和发放前按配置判定，超过上限不发放，前台提示「奖励领取限制[编号]」；一个账号能多次领取的活动，同一设备、同一 IP 只允许前 N 个领取的账号领取（N18）。各活动原有的同 IP、同设备领取限制删除，统一按本栏目的配置限制，上线时按生产环境配置迁移，迁移结果显示在列表中；邀请好友的邀请资格规则和完成任务砸金蛋的每天名额保留（N9、N14）。前台页面不改。789Bingo、789Games 两个站都做。
    背景与目标用户在同一设备、同一网络下切换多个账号，可重复领取同一活动的奖励。目标：运营按活动限制同设备、同 IP 的领取次数或领取账号数，活动之间互不影响。参考 Wiki《【风控】新用户转盘活动增加同设备领取限制》，扩大到活动中心的活动，沿用现有设备标识，不依赖数美（三方设备识别服务）。
    多端范围H5、PC、PWA、iOS、Android 的规则和提示文案相同（PC 与 H5 一致）；Maya、GLife 小程序同样适用，按 H5 的方式获取浏览器标识作为设备标识（N10）。管理后台在【活动配置】下新增【活动限制管理】栏目，各活动配置页删除原有的同 IP、同设备配置项。本版只在现有技术能力范围内判定同设备、同 IP，超出部分以后对接第三方风控服务机构时优化。
    时间与时区GMT+8。「每天」「7 天」「15 天」按自然日（00:00:00–23:59:59），「一个月」按自然月。活动限制管理列表中的有效期与【活动中心】该活动（期）配置页显示的时间一致（N17 ③）。

    2. 整体业务流程

    2.1 领取判定流程

    运营在【活动配置 › 活动限制管理】的「配置限制」弹窗里设置该活动（该期）的同设备、同 IP 和领取限制白名单并保存；领取或发放时按下图判定。

    图中「已达上限」：只判断已勾选且数量大于 0 的项。单次领取类：该设备或 IP 本周期内已领取次数 ≥ 最多领取次数（规则 N3）；多次领取类：该设备或 IP 本周期内的有效绑定账号（按各账号本周期内在该设备或 IP 首次成功领取的先后取前 N 个，N 为最多账号数）已满 N 个，且当前账号不在其中（规则 N5、N18）。活动限制管理中三项都未配置的活动（期），只做活动现有校验。拦截时不发放、不扣参与次数；自动发放被拦截时不提示（规则 N6 拦截处理、N8 自动发放）。需判定的设备标识或 IP 取不到时本次不发放，用户领取时提示「奖励领取限制[L03]」（规则 N11）。活动名单会员：该项下方「本活动白名单用户也受此限制」未勾选时跳过该项，勾选时照常判断（规则 N16）。

    2.2 系统时序

    触发执行方动作
    运营在活动限制管理保存配置后台 → 后端「配置限制」弹窗里的设备限制、IP 限制和本次导入的领取限制白名单按活动（分期的活动按期）保存，对之后的领取和发放立即生效（N13、N15）
    用户登录前台 → 后端登录记录（【登录日志】或会员操作日志）已保存设备标识的沿用现有，没有的新增保存，取值与领取判定使用的设备标识一致；保留时长不短于对应活动从产生奖励到发放的时间（N8）
    本需求上线后端先把各活动原有、生效且已开启的同 IP、同设备限制迁移到活动限制管理，再删除原有限制和配置项（N14）
    运营进入活动限制管理或点「刷新」后台 → 后端重新读取【活动中心】的全部活动和各期，生成列表；新生成的一期默认沿用该活动上一期的配置，没有上一期的期和新建的不分期活动默认不限制（N13 ④、N17）
    用户点击领取前台 → 后端前台带上现有设备标识；后端记录请求 IP
    收到领取请求或到达自动发放时间后端活动现有校验通过后，按 N5 的顺序（同设备 → 同 IP）判定，通过才发放；自动发放的设备和 IP 取该账号最近一次登录的记录（N8）
    用户发起充值前台 → 后端记录这笔充值发起时的设备标识和 IP（N7）
    充值到账后端按充值发起时记录的设备标识和 IP 判定：所选优惠超限或取不到时只到账本金、不通知（N7 ①）；老用户充值转盘、返现充值转盘此时判定资格，被拦截时不给转盘次数、不弹出转盘（N7 ③）
    审核通过、人工发放、批量发放后台 → 后端发放前按 N5 判定，被拦截的记录不发放、显示拦截编号（N19）
    发放成功后端记录账号、设备标识、IP，计入该活动的已领取次数；多次领取类同时计入该设备和 IP 的已绑定账号（N3、N4、N18）
    被拦截或取不到设备标识、IP后端 → 前台用户领取时，前台显示带编号的 Toast（页面底部短暂出现、自动消失的提示条）；自动发放时本次不发放、不提示；均不扣参与次数，不计次数

    9. 上线方式

    • 789Bingo、789Games 两个站分别上线。上线时系统按生产环境的配置，把各活动原有限制逐期迁移到【活动配置 › 活动限制管理】，再删除原有限制和配置项，不做上线前预演；迁移规则见规则 N14。没有迁移内容的活动（期）默认不限制。
    • 上线前由平台管理员在【权限管理】中给运营分配「活动限制管理」权限，并告知栏目位置；789Games 没有【活动配置】菜单时随本需求新增。
    • 上线后运营在【活动配置 › 活动限制管理】列表核对迁移结果：每个活动（期）一行，「设备限制」「IP 限制」「白名单导入」三列显示当前配置，迁移结果就显示在这里，按 5.1 活动表「原有限制」列和 N14 迁移规则逐个活动、逐期对照。显示「不限制」的行（原来没有限制、原配置不生效或关闭、读不到原有限制配置的）按需点「配置」补配；原数值明显偏大（如每日首充 1000、新用户首充 10000、新站新用户转盘迁移后的 999999）的按活动参与规模重新设置；新站新用户转盘核对全局白名单迁移后的领取限制白名单。
    • 迁移后的判定按本需求执行：严格按设置的数量判定；需判定的 IP 取不到时拦截（L03）；只统计上线后的领取；新用户转盘按账号数和设备标识判定；789Games 输返活动自动发放也判定（第 10 章）。
    • 每次在活动中心新建一期或复制活动生成新一期后，新一期默认沿用该活动上一期的配置和领取限制白名单，需要时到活动限制管理修改；没有上一期的期和新建的不分期活动默认不限制。
    • 上线后第 1 天查看拦截数据和客服咨询：个别误伤，核实后导入该活动（期）的领取限制白名单；集中误伤，调大次数或取消勾选。
    • 回滚：
      ① 关闭限制：在活动限制管理中取消勾选并保存，不需要发版。
      ② 回退版本：上线迁移前保存各活动（期）原有同 IP、同设备限制的配置记录；需要回退版本时，按记录把各活动原有限制恢复为上线前的配置，由运营在各活动配置页核对（N14）。
