    0. 本迭代范围

    本需求只做一期。与其他章节冲突时，以本章为准。

    类别本迭代包含顺延至
    管理后台【活动中心】下所有活动（含以后新增的活动）的配置页增加「活动奖励领取限制」板块（N1、N2），领取限制白名单沿用现有白名单导入功能（N15）；新用户转盘原有的设备、IP 两项并入该板块（N14）-
    前台（H5、PWA、iOS、Android）和系统发放用户领取和系统自动发放前按配置判定，超过次数不发放；用户领取时提示带编号的限制文案（N3–N12）-
    不包含同账户限制（各活动自身已有单账号规则）；全平台总开关、全平台统一白名单；接入数美等三方设备识别；拦截记录查询页；邀请好友活动的邀请资格规则不顺延
    不包含跨浏览器、浏览器和 App 之间、清除缓存或重装 App 后的同一设备识别（N10）对接三方风控服务后，按其技术方案优化

    ※ 本版只按平台现有设备标识识别设备。同一台设备换浏览器、在浏览器和 App 之间切换、清除缓存或重装 App 后，可能被识别成新设备，本版不考虑；后续对接三方风控服务后再优化（N10）。

    1. 项目概述

    项目说明
    需求描述【活动中心】下每个活动的配置页增加「活动奖励领取限制」板块：可勾选同设备、同 IP，每项设置限制周期（活动期间 / 每天 / 7 天 / 15 天 / 一个月）和最多领取次数，填「0」为不限制。领取和发放前按配置判定，超过次数不发放，前台提示「奖励领取限制[编号]」。每个活动可导入白名单，名单内会员不受这两项限制。
    背景与目标同一设备、同一网络切换多个账号可重复领取同一活动奖励。目标：运营按活动限制同设备、同 IP 的领取次数，活动之间互不影响。参考 Wiki《【风控】新用户转盘活动增加同设备领取限制》，扩大到所有活动，沿用现有设备标识，不依赖数美。
    多端范围H5、PWA、iOS、Android 规则和提示文案相同；管理后台：做。
    时间与时区GMT+8。「每天」「7 天」「15 天」按自然日（00:00:00–23:59:59），「一个月」按自然月。

    2. 整体业务流程

    2.1 领取判定流程

    运营在活动配置页设置限制、导入白名单并保存；领取或发放时按下图判定。

    只判断已勾选且次数大于 0 的项。拦截时不发放、不扣参与次数，自动发放不提示（N6、N8）。需判定的设备标识或 IP 取不到时暂不发放，提示「奖励领取限制[L03]」（N11）。

    2.2 系统时序

    触发执行方动作
    运营保存活动后台 → 后端领取限制和导入的白名单随活动配置一起保存，对之后的领取和发放生效（N13、N15）
    用户点击领取前台 → 后端前台带上现有设备标识；后端记录请求 IP
    收到领取请求或到达自动发放时间后端活动现有校验通过后按 N5 判定，通过才发放
    发放成功后端记录账号、设备标识、IP，计入该活动的已领取次数（N3、N4）
    被拦截或取不到设备标识、IP后端 → 前台用户领取时前台显示带编号的 Toast；自动发放时本次不发放；不扣参与次数，不计次数

    3.2 本需求规则

    编号规则起因功能点
    N1适用范围：【活动中心】下所有活动（含以后新增的活动）的配置页都增加「活动奖励领取限制」板块（入口见 5.1）。用户领取、系统自动发放、次数由充值或投注获得的奖励（如老用户充值转盘），都按该活动的配置判定。用户要求所有活动都可配置（2026-11-10）F02-01 活动奖励领取限制板块
    N2板块有同设备、同 IP 两项，每项包括勾选框、限制周期（活动期间 / 每天 / 7 天 / 15 天 / 一个月）、最多领取次数。不勾选或次数填「0」，表示该项不限制。新建活动时两项都不勾选，限制周期默认「活动期间」。单个账号的领取次数沿用各活动自身规则，本板块不设同账户项。用户要求，去掉同账户项（2026-11-11）F02-01 活动奖励领取限制板块
    N3领取次数 = 该活动成功发放奖励的次数，每发放一次计 1 次（领取、转盘或抽奖、签到、兑换、充值优惠、自动发放各计 1 次）。
    同设备：该设备上所有账号合计；同 IP：领取时 IP 相同的所有账号合计。
    不同活动分别计算；新建或复制出的活动从 0 开始。    		按活动统一计次，运营好理解F01-01 领取次数限制判定
    N4限制周期（GMT+8）：
    「活动期间」：本功能上线后，活动开始至结束累计。
    「每天」：自然日 00:00:00–23:59:59，次日重新计算。
    「7 天」「15 天」：含领取当天往前 7 / 15 个自然日，每天 00:00:00 滚动。例：选 7 天，11 月 10 日领取时统计 11 月 4 日 00:00:00 至 11 月 10 日 23:59:59。
    「一个月」：自然月，每月 1 日 00:00:00 重新计算。例：11 月 30 日领取时统计 11 月 1 日至 30 日，12 月 1 日从 0 开始。
    只计成功发放的次数；上线前的历史领取不计。    		资料未覆盖历史领取是否有设备和 IP 记录，从上线起计算最简单F01-01 领取次数限制判定
    N5判定顺序：活动现有资格校验通过后，按 同设备 → 同 IP 判断已勾选且次数大于 0 的项。某项已领取次数 ≥ 最多领取次数即拦截，不再判断后面的项。活动现有校验不通过时，按活动现有处理，不做本判定。不改变活动现有提示的优先级；两项同时超过只提示第一项F01-01 领取次数限制判定
    N6用户领取被拦截时：不发放；不扣参与次数、抽奖机会或兑换码次数；不计次数；领取按钮保持可点。转盘、抽奖类在转动前拦截。
    Toast 统一为「奖励领取限制[编号]」，编号表示拦截原因：
    L01 = 同设备达到上限；L02 = 同 IP 达到上限；L03 = 需判定的设备标识或 IP 取不到（N11）。
    编号对应的客服回复口径见客服 QA。    		提示统一简短，不向玩家暴露判定方式，客服按编号解释（用户 2026-11-11 要求）F01-02 拦截处理与提示
    N7充值页选择、到账后发放的优惠（如充值活动、每日首充、新用户首充、新用户转盘大礼包）：
    ① 选择时按 N5 判定，超过时该优惠置灰不可选，下方显示「奖励领取限制[编号]」，用户可不选优惠继续充值；
    ② 到账发放前再判定一次，超过时（如期间同设备其他账号已领取）不发放该优惠，充值金额照常到账，不新增通知（客服按 QA 解释）。    		避免用户付款后才发现拿不到优惠F01-02 拦截处理与提示
    N8系统自动发放（如自动发放的登录送彩金、邀请奖励、免费旋转）：发放前按 N5 判定，超过的账号本次不发放，不提示。设备和 IP 取该账号最近一次登录的记录。所有活动都适用（用户 2026-11-10 确认）F01-01 领取次数限制判定
    N9活动自身的领取规则（含单账号领取次数）和已有的同类限制（3.1）照常生效，与本需求限制都满足才能领取；被活动自身规则拦截时，按活动现有提示。不改动现有活动规则F01-01 领取次数限制判定
    N10同一设备：按平台现有设备标识判定（与新用户转盘现用标识相同），实现由技术确定；能否唯一区分一台手机待确认（Q3），确认前不建议勾选同设备。
    同一 IP：按领取请求的 IP 判定（自动发放见 N8）。同一 Wi-Fi 或移动网络同一出口的账号都算同一 IP，移动网络下共用者可能很多，次数按活动参与规模设置。
    ※ 本版不考虑：同一设备换浏览器、在浏览器（H5、PWA）和 App 之间切换、清除缓存或重装 App 后被识别成新设备，以现有标识的识别结果为准；对接三方风控服务后再优化。    		沿用现有设备标识，开发量最小（用户 2026-11-10 确认）F01-01 领取次数限制判定
    N11需要判定同设备或同 IP（已勾选、次数大于 0、会员不在白名单）但取不到对应的设备标识或 IP 时：不发放，不扣参与次数，不计次数。用户领取时显示 Toast「奖励领取限制[L03]」，可再次点击；自动发放时本次不发放。防止清除设备标识等方式绕过限制（参考 Wiki 接口异常处理）F01-03 设备标识或 IP 获取失败处理
    N12同一设备或同一 IP 的多个账号同时领取同一活动时，合计成功次数不超过最多领取次数，超出的按 N6 拦截；同一账号重复点击只发放一次（沿用现有）。并发下保证上限准确F01-01 领取次数限制判定
    N13配置与生效：
    ① 勾选后次数必填，为 0–9999 的整数：为空提示「请输入最多领取次数」，否则提示「请输入 0–9999 的整数」，提示显示在输入框下方，活动不能保存。未勾选的项，周期和次数置灰，不保存。
    ② 随活动一起保存（配置页现有的「保存」），保存后对之后的领取和发放立即生效；已发放的奖励不受影响。
    ③ 活动进行中修改次数或周期，已领取次数不清零，按新设置判断（如次数从 3 改为 1，已领 2 次的设备不能再领）。
    ④ 复制活动时一起复制。
    ⑤ 留痕沿用【日志管理 › 操作日志】：已记录活动配置保存的不额外开发，未记录的补记操作人、时间、活动。    		误伤时运营可随时调大次数或取消勾选F02-01 活动奖励领取限制板块
    N14新用户转盘配置页去掉「同一台设备只能领取 N 次」「同一注册 IP 累计最多计入 N 个账号」，改用本板块。上线时：

    ③ 原有白名单导入及已导入名单保留，作为本活动的领取限制白名单，不重复添加。    		用户要求并入新板块（2026-11-10）F02-02 新用户转盘原配置并入

    8. 验收标准

    8.1 验收条目

    1. F02-01 5.1 清单内每个活动的配置页都有本板块，只有同设备、同 IP 两项；新建活动时两项不勾选、周期为「活动期间」。
    2. F02-01 勾选后次数为空提示「请输入最多领取次数」，填 -1、1.5、10000、abc 提示「请输入 0–9999 的整数」，均不能保存；填 0 和 9999 可以保存。取消勾选后周期和次数置灰，保存后该项不生效。
    3. F01-01 同设备 · 活动期间 · 1 次：账号 A 在设备 X 领取后，账号 B 在设备 X 领取被拦截，提示「奖励领取限制[L01]」；账号 B 在设备 Y 领取成功。
    4. F01-01 同设备 · 每天 · 1 次：设备 X 当天已由账号 A 领取，账号 B 当天 23:59:59 领取被拦截，次日 00:00:00 后领取成功。
    5. F01-01 同设备 · 7 天 · 1 次：账号 A 于 11 月 4 日在设备 X 领取，账号 B 于 11 月 10 日 23:59:59 领取被拦截，11 月 11 日 00:00:00 后领取成功。
    6. F01-01 同设备 · 一个月 · 1 次：账号 A 于 11 月 1 日在设备 X 领取，账号 B 于 11 月 30 日 23:59:59 领取被拦截，12 月 1 日 00:00:00 后领取成功。
    7. F01-01 同 IP · 活动期间 · 3 次：同一 IP 下合计已领 2 次时，第 3 次成功；合计 3 次后，任一账号再领被拦截，提示「奖励领取限制[L02]」。
    8. F01-01 两项同时达到上限时只提示「奖励领取限制[L01]」；仅同 IP 达到上限时提示 L02。
    9. F01-01 不勾选或次数填 0 时不限制；活动 A 的记录不影响活动 B；复制活动 A 得到的新活动带上限制配置，次数从 0 开始。
    10. F01-01 活动现有校验不通过（如未 KYC、已达活动自身的单账号次数）时，只出现活动现有提示。
    11. F01-01 自动发放的活动勾选同设备 · 每天 · 1 次：设备 X 上账号 A 已收到后，账号 B 当天不再收到，无提示。
    12. F01-01 活动进行中把同设备次数从 3 改为 1：已领 2 次的设备不能再领；改回 3 后可再领 1 次。
    13. F01-01 设备 X 上两个账号同时领取（同设备 1 次），只有一个成功；同一账号快速重复点击只发放一次；绕过前端直接调接口同样拦截。
    14. F01-02 被拦截后余额和奖励记录不变，参与次数、抽奖机会、兑换码次数不扣，转盘不转动。
    15. F01-02 充值活动勾选同设备 · 活动期间 · 1 次：设备 X 已由账号 A 领取后，账号 B 在充值页看到该优惠置灰并显示「奖励领取限制[L01]」，不选优惠可正常充值。
    16. F01-03 需判定同设备时取不到设备标识、或需判定同 IP 时取不到 IP：提示「奖励领取限制[L03]」，不发放、不扣次数，恢复后可领取；不需要判定的项（未勾选、次数为 0、白名单会员）取不到时不受影响。
    17. F02-03 活动 A 同设备 · 活动期间 · 1 次，设备 X 已由账号 A 领取：导入含账号 B 的白名单并保存活动后，账号 B 在设备 X 领取成功；之后不在名单的账号 C 被拦截；账号 B 在活动 B 不享受白名单。
    18. F02-03 白名单导入的文件模板、导入结果统计、已导入文件下载、重置，与后台现有白名单导入一致；只导入不保存活动时不生效；复制活动不带白名单。
    19. F02-01 修改并保存领取限制后，【日志管理 › 操作日志】有对应记录（操作人、时间、活动）。
    20. F02-02 新用户转盘：原有两项不再显示；上线前设为「同一台设备只能领取 3 次」的活动，上线后显示「同设备 · 活动期间 · 3」，同 IP 不勾选；原白名单导入和已导入名单保留，页面只有一处白名单导入。

    9. 上线方式

    • 上线时所有活动两项均不勾选，现有领取不受影响；新用户转盘按 N14 迁移设备项。
    • 上线当天运营立即给新用户转盘填写同 IP 项（N14）。
    • 其他活动由运营按需配置，保存即生效。
    • 上线后第 1 天看拦截数据和客服咨询：个别误伤导入白名单，集中误伤调大次数或取消勾选。
    • 回滚：取消勾选并保存即可，不需要发版。

    10. 风险与依赖

    风险等级应对
    现有设备标识若只是 UA，同型号手机会被当成同一设备，开启同设备后大量误伤高技术确认前不勾选同设备（N10、Q3）
    移动网络大量用户共用出口 IP，同 IP 次数过小会误伤大量正常用户中同 IP 次数按活动参与规模设置；误伤时调大次数或取消勾选（N10、N13）
    家人共用设备、同一 Wi-Fi，正常用户被拦截中核实后导入该活动白名单（N15）
    提示只显示编号，玩家不知道原因，咨询量可能增加低客服按 QA 的编号对照表解释（N6）
    新用户转盘上线到运营填写同 IP 项之间没有 IP 限制中上线当天运营立即填写（N14）
    换浏览器、浏览器和 App 之间切换、清缓存或重装后被识别成新设备，限制被绕过中本版接受（N10）；取不到标识时不发放（N11）；对接三方风控服务后优化
    自动发放取最近一次登录的设备和 IP，可能与实际领取设备不同低本版接受（N8）
    上线前的领取不计入，上线初期可能被再领一次低一次性影响，接受（N4）
    依赖：各端领取时都能带上现有设备标识中开发评审时逐个活动确认（Q3）
