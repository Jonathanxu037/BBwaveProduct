单一设备领取奖励限制 · 需求要点 · v1.1

版本：v1.1平台：789Bingo（老站）、789Games（新站）端：H5、PC、PWA、iOS、Android、管理后台依据：需求开发 PRD 文档

一句话需求

后台【活动配置】下新增栏目【活动限制管理】，列出【活动中心】的全部活动（分期的活动每期一行），每个活动（每期）统一配置「设备限制」（同设备）、「IP 限制」（同 IP）、「白名单导入」（领取限制白名单）三个条件（规则 N17）：设备限制、IP 限制每项设置限制周期（活动期间 / 每天 / 7 天 / 15 天 / 一个月）和数量（单次领取类「最多领取 N 次」，多次领取类「最多 N 个账号」），填「0」为不限制；领取限制白名单沿用后台现有白名单导入功能，名单内会员不受这两项限制。用户领取、系统自动发放、审核、人工和批量发放前都按配置判定，超过上限不发放，前台提示「奖励领取限制[编号]」；一个账号能多次领取的活动，每个限制周期内同一设备、同一 IP 只允许前 N 个领取的账号领取（规则 N18）。新生成的一期默认沿用该活动上一期的配置（规则 N13）。各活动原有的同 IP、同设备限制上线时沿用原有数据迁移到本栏目，再删除原有限制和对应配置项，统一按本栏目配置（规则 N14）；前台页面不改。789Bingo（老站）、789Games（新站）两个站都做，Jira 按站点分别建单（老站【B】、新站【G】）。

判定流程

图中「已达上限」：只判断已勾选且数量大于 0 的项。单次领取类：该设备或 IP 本周期内已领取次数 ≥ 最多领取次数（规则 N3）；多次领取类：该设备或 IP 本周期内的有效绑定账号（按各账号本周期内在该设备或 IP 首次成功领取的先后取前 N 个，N 为最多账号数）已满 N 个，且当前账号不在其中（规则 N5、N18）。活动限制管理中三项都未配置的活动（期），只做活动现有校验。拦截时不发放、不扣参与次数；自动发放被拦截时不提示（规则 N6 拦截处理、N8 自动发放）。需判定的设备标识或 IP 取不到时本次不发放，用户领取时提示「奖励领取限制[L03]」（规则 N11）。活动名单会员：该项下方「本活动白名单用户也受此限制」未勾选时跳过该项，勾选时照常判断（规则 N16）。

开发功能点

F01-01领取次数限制判定查看 PRD ›

要做什么
  • 判定顺序：活动现有校验（活动资格、单账号领取规则）→ 同设备 → 同 IP，在发放前判定；用户领取、系统自动发放、充值到账、获得充值转盘资格、审核和人工发放、批量发放时都判定；判定读取活动限制管理中该活动（该期）的配置（N1、N5、N7、N8、N19）
  • 单次领取类活动（绑定手机号码、KYC 认证送彩金、新用户首充、导入用户登录送彩金（789Games 叫登录送彩金活动（白名单）），每个账号只能领一次，与设备限制、IP 限制同时生效，Q12）：次数 = 本活动成功发放的次数；同设备、同 IP 按所有账号合计；不同活动、同一活动的不同期分别计算（N3）
  • 多次领取类活动（如签到、充值优惠、转盘、返水、Crown Rush（皇冠冲榜））：填「最多 N 个账号」（0–999999 的整数，0 为不限制）；每个限制周期内，按各账号在该设备（或 IP）首次成功领取本活动的先后取前 N 个，作为有效绑定账号；有效绑定账号已满 N 个且当前账号不在其中时，领取本活动的任何奖励都拦截（L01 / L02），未满 N 个时领取成功并成为有效绑定账号（N5）；N=1 即只有首个领取的账号能领取；活动进行中重新勾选或调小账号数时只保留前 N 个，其余已绑定账号从保存起被拦截（N13 ③）；有效绑定账号自己的多次领取按活动原规则；「每天」「一个月」在下一个周期开始时清空已绑定账号，「7 天」「15 天」按滚动窗口判断（领取当天往前 7 / 15 个自然日内在该设备或 IP 成功领取过本活动的账号，按窗口内首次成功领取的先后取前 N 个；窗口内账号数 ≥ N 且当前账号不在前 N 个中时拦截），「活动期间」整个活动期间累计（N18）
  • 周期：活动期间（上线后累计）、每天（自然日）、7 天 / 15 天（含当天往前滚动）、一个月（自然月），均按 GMT+8；所有活动都可选五种周期，默认「活动期间」（N4）
  • 活动自身的领取规则（活动资格、单账号次数、同一手机号只能领一次、完成任务砸金蛋（新站砸金蛋送彩金活动）同 IP 和同设备每天各有名额）照常生效，与本需求限制都满足才能领取；例：本需求 IP 限制设为「每天 · 最多 1 个账号」时，砸金蛋每天 100 个名额由 100 个不同 IP 各 1 个账号参与，设备同理（N9、N14）
  • 上线时按生产环境配置，把原有生效且已开启的限制数据逐期迁移到活动限制管理，再删除原有限制和活动配置页上对应的配置项，不做上线前预演；迁移后按本需求的功能和配置方式生效，迁移结果显示在列表的三列配置中，运营上线后核对，「不限制」的行按需补配（N14）。删除清单：充值活动、每日首充、新用户首充、负盈利活动（新站输返活动）、新盈利活动 V2（新站新输返活动）的「同一 IP 每天 N 个账号」；消费活动（新站返水活动）、幸运转盘（新站抽奖活动）的「同 IP 只有一个账号可以参与」开关；新用户转盘的同设备 N 次、同 IP 限制和新站全局开关、全局白名单；签到、导入签到、新用户充值活动计划、充值类条件里不生效的 IP 配置项。迁移（N 为原数值）：「同一 IP 每天 N 个账号」→ IP 限制 · 每天，单次领取类「最多领取 N 次」、多次领取类「最多 N 个账号」；「同 IP 只有一个账号可以参与」→ IP 限制 · 每天，单次 1 次、多次最多 1 个账号；新用户转盘同设备 N 次 → 设备限制 · 活动期间 · 最多 N 个账号，同 IP（每天 N 次）→ IP 限制 · 每天 · 最多 N 个账号，新站以活动自身数值为准（都迁移为最多 999999 个账号）；新站全局开关删除、不迁移，全局白名单会员 → 新用户转盘各期的领取限制白名单；原数值超过 999999 → 按 999999 迁移；789Bingo 返水活动（独立配置）上线时读不到原有限制配置，按不限制上线，由运营配置；不生效、未勾选、关闭的不迁移；活动自身名单不迁移；操作日志记「系统」迁移。迁移后严格按设置的数量判定，取不到 IP 时拦截（L03），只统计上线后的领取，自动发放同样判定。保留邀请好友的「同设备不允许互相邀请」和「IP 限制」（同一注册 IP 最多计入 N 个好友，邀请资格规则，不迁移；本需求的 IP 限制另外生效）、完成任务砸金蛋同 IP 和同设备每天名额（活动自身规则，不迁移）、新用户转盘按名单发指定奖励的白名单、活动参与名单和指定名单
  • 自动发放取账号最近一次登录的设备和 IP，取不到时不发放；登录记录（【登录日志】或会员操作日志）已保存设备标识的沿用现有，没有的新增保存，取值与领取判定一致，保留时长不短于对应活动从产生奖励到发放的时间；Maya、GLife 小程序按 H5 的方式取浏览器标识作为设备标识（N8、N10）；被拦截时不发放，首页奖励弹窗、站内信、推送、短信、聊天室播报都不触发（N8）
  • 审核发放：申请时被拦截不生成申请，Toast「奖励领取限制[编号]」；审核时被拦截，【派奖审核】和该活动「活动统计」的记录显示「奖励领取限制[编号]」，默认不发放，玩家申请记录沿用「未通过」，审核人可强制通过（单次领取类计入次数；多次领取类只放行这一次，该账号不加入已绑定账号）；转盘、抽奖类只在转动前判定，中奖后进入派奖审核的，审核时不再判定（N19 ①）
  • 人工和批量发放：发放前同样判定，被拦截的记录显示原因、不随批量发出，不能强制发放，确需发放走【修改余额审批】；只触发一次的奖励被拦截后不自动补发（N19 ②、④）
  • 同 IP 按领取请求的 IP 判定；移动网络下共用同一出口 IP 的账号也算同 IP，次数或账号数要按活动参与规模设置（N10）
  • 多个账号同时领取时，单次领取类合计成功次数、多次领取类合计绑定账号数不超过上限；重复点击只发放一次（N12、N18）
  • ※ 设备标识和 IP 的取值方式由技术确定（已确认 Q3）；本版不考虑换浏览器、在浏览器和 App 之间切换、清除缓存或重装 App 后的设备识别（N10）
公式
单次领取类：该项已领取次数 ≥ 最多领取次数（最多领取次数大于 0，按当前限制周期统计）→ 拦截
同设备 / 同 IP 已领取次数 = 该设备 / IP 上所有账号在当前周期内成功领取本活动（本期）的次数之和
多次领取类：有效绑定账号 = 该设备 / IP 在当前周期内成功领取过本活动的账号，按首次成功领取的先后取前 N 个（N = 最多账号数，大于 0）
有效绑定账号已满 N 个，且当前账号不在其中 → 拦截；未满 N 个 → 领取成功，当前账号成为有效绑定账号
7 天 / 15 天：领取当天往前 7 / 15 个自然日内在该设备 / IP 成功领取过本活动的账号，按窗口内首次成功领取的先后取前 N 个；窗口内账号数 ≥ N 且当前账号不在前 N 个中 → 拦截

F01-02拦截处理与提示查看 PRD ›

要做什么
  • 被拦截时不发放、不扣参与次数、不计次数；转盘和抽奖在转动前拦截；按钮保持可点；签到被拦截时不记签到，连续签到天数可能因此中断（N6）
  • Toast「奖励领取限制[编号]」：L01 = 同设备达到上限；L02 = 同 IP 达到上限；L03 = 取不到设备标识或 IP（N11）
  • 充值页可选的优惠（充值活动、新用户充值活动计划）：选择时已超过 → 该优惠置灰，下方显示「奖励领取限制[编号]」，可不选优惠继续充值；到账时再判定一次，设备标识和 IP 取这笔充值发起时的记录，超过或取不到 → 不发放该优惠，充值金额照常到账，不通知（N7 ①）
  • 每日首充、新用户首充：充值页没有可选项，到账或完成 KYC 后自动发放时按自动发放判定；新用户首充的次日奖励跟随首充奖励：首充奖励已发放的账号，次日奖励不再判定、不计次数，首充奖励被拦截的账号不发放次日奖励（N7 ②、N8）
  • 老用户充值转盘、返现充值转盘：获得资格时判定（取这笔充值发起时的设备标识和 IP），被拦截时不给转盘次数、不弹出转盘、不提示，充值金额照常到账；充值前不提示（N7 ③）
  • 各活动的前台规则说明不加限制提示

F01-03设备标识或 IP 获取失败处理查看 PRD ›

要做什么

  • 不需要判定的项（未勾选、数量为 0、领取限制白名单会员、按 N16 跳过该项的名单会员）取不到时不受影响

F02-01配置限制弹窗查看 PRD ›

要做什么
  • 列表每行点「配置」打开「配置限制」弹窗，标题带活动名称，分期的活动带期数（PRD 5.1）
  • 弹窗分「设备限制与 IP 限制」「白名单导入」两个区
  • 「设备限制」「IP 限制」各一行：勾选框、限制周期（五种都可选，默认「活动期间」）；单次领取类填「最多领取 N 次」，多次领取类填「最多 N 个账号」，都是 0–999999 的整数，0 为不限制（N2、N4、N18）；未配置时不勾选；不设同账户项
  • 「白名单导入」区导入领取限制白名单，所有活动都有（F02-03）
  • 活动自身有白名单时，两项下方各有勾选框「本活动白名单用户也受此限制」，默认勾选，只在弹窗中显示和修改，列表不显示；不勾选时名单内全部会员跳过该项判定，其领取仍计入次数；需要单独放行某个会员时导入领取限制白名单（N16）
  • 「保存」：为空时单次领取类提示「请输入最多领取次数」、多次领取类提示「请输入最多账号数」，不是 0–999999 的整数提示「请输入 0–999999 的整数」；通过后提示「保存成功」，立即生效。「取消」或「×」不保存设备限制、IP 限制的修改，本次导入的白名单也不生效（N13 ①②、N15 ③）
  • 修改后已领取次数和已绑定账号不清零；取消勾选期间成功发放的次数同样计入；多次领取类重新勾选或调小账号数时，只保留当前周期内最先绑定的前 N 个账号，其余已绑定账号从保存起被拦截；在活动中心新生成的一期（新建或复制生成）默认沿用同一活动上一期的配置（勾选、周期、数量、「本活动白名单用户也受此限制」和领取限制白名单），运营可修改，新旧两期互不影响；「上一期」指在新一期之前创建、离它最近的一期；没有上一期的期和新建的不分期活动默认不限制；删除活动或期后配置失效；每次保存记入【日志管理 › 操作日志】（操作人、时间、活动名称、期数和该期的活动名称、修改前后的配置）（N13）
  • 各活动的领取类型由技术按 PRD 5.1 固定，运营不能切换（N13 ⑦）

F02-02活动限制管理列表查看 PRD ›

要做什么
  • 入口【活动配置 › 活动限制管理】，两站相同，789Games 没有【活动配置】菜单时新增；新增权限项「活动限制管理」，由平台管理员在【权限管理】中分配（Q13）
  • 每次进入或点「刷新」重新读取【活动中心】的全部活动和各期（含新用户转盘、完成任务砸金蛋、需复测的活动，状态按线上数据显示）；新建的活动、新生成的期自动出现，新一期默认沿用上一期的配置，没有上一期的期和新建的不分期活动默认不限制；分期的活动一期都没有时不出现；789Bingo 写死的返水单独一行「返水活动（独立配置）」，按多次领取类、不分期（N13 ④、N17 ①②）；上线时按实际代码读取已有的活动，读到的都出现在列表，邮箱认证奖励读到时按单次领取类处理（N1、Q7）
  • 以后每次新增活动，技术都要同步更新活动限制管理的活动清单，让新活动出现在列表；新活动的开发验收必须包含这一项（N17 ⑨）
  • 期数按现有各期的创建先后编号，删除某一期后剩下的期重新编号（N17 ③）
  • 列：活动名称｜期数 / 状态与有效期｜设备限制｜IP 限制｜白名单导入｜操作。同一活动的多期，活动名称合并单元格只显示一次；分期活动第二列显示「第 N 期」（按创建先后编号）和该期名称、状态、有效期；不分期的活动显示「开启」或「关闭」和有效期（长期有效显示「长期」）；有效期与【活动中心】该活动（期）配置页显示的时间一致，列头提示写明所用时区；已过结束时间显示「已结束」（N17 ③④）
  • 三个配置列只显示本活动（本期）当前的配置情况：设备限制、IP 限制列「不限制」（未勾选或数量为 0）、「周期 · N 次」（单次领取类）、「周期 · 最多 N 个账号」（多次领取类）；白名单导入列只显示「已导入 N 人」或「未导入」（N17 ③）
  • 已结束、已关闭的照常列出可配置；在活动中心删除的活动或期从列表消失，配置失效（N17 ④⑤）
  • 按活动中心菜单顺序排列，同一活动按期数倒序；「活动名称」下拉列表（「全部」和列表中的每个活动，默认「全部」，每次读取活动中心后更新选项），选择后点「搜索」只显示该活动的全部行（分期的活动为其各期），回到第 1 页；「刷新」保留当前选择，所选活动已删除时回到「全部」（N17 ⑥⑦）
  • 分页沿用后台现有组件，每页 20 条，可切换 50 条；无数据显示「暂无数据」（PRD 5.2）
  • 各站活动、是否分期、领取类型、自身名单和删除的原有限制见 PRD 5.1 活动表
  • 上线时按生产环境配置，把原有限制的数据逐期迁移到本栏目，迁移结果显示在列表的「设备限制」「IP 限制」「白名单导入」三列；运营上线后在列表核对，「不限制」的行按需补配（N14、PRD 第 9 章）
  • 读取活动中心失败沿用后台现有的加载失败提示；两名运营同时修改同一活动（期），以后保存的为准；弹窗打开期间该期被删除，点「保存」不保存，沿用后台现有的保存失败提示（PRD 第 7 章）

F02-03领取限制白名单查看 PRD ›

要做什么
  • 所有活动（期）都有，在「配置限制」弹窗的「白名单导入」区导入，沿用后台现有白名单导入组件（导入文件、已导入文件下载、导入结果统计），组件不改（N15）
  • 每个活动（分期的活动每期）单独导入，导入后点弹窗「保存」才生效，点「取消」或关闭弹窗不生效；名单内会员跳过同设备、同 IP 判定（多次领取类也不受账号数限制），其领取仍计入该设备和 IP 的次数和已绑定账号数（N15、N18 ⑥）
  • 新生成的一期默认沿用上一期的名单，运营可重新导入（N13 ④）
