单一设备领取奖励限制 · 需求要点 · v1.0

版本：v1.0平台：789Bingo（老站）、789Games（新站）端：H5、PC、PWA、iOS、Android、管理后台依据：需求开发 PRD 文档

一句话需求

【活动中心】下的活动按接入方式（规则 N17）在配置页增加「活动奖励领取限制」板块：可勾选同设备、同 IP（C 方式只有同设备，D 方式不加板块），每项设置限制周期（活动期间 / 每天 / 7 天 / 15 天 / 一个月）和最多领取次数，填「0」为不限制。用户领取、系统自动发放、审核、人工和批量发放前都按配置判定，超过次数不发放，前台提示「奖励领取限制[编号]」；一个账号能多次领取的活动不设次数，每个限制周期内同一设备、同一 IP 只允许首个领取的账号领取（规则 N18）。A 方式的活动另设领取限制白名单，沿用后台现有白名单导入功能，名单内会员不受这两项限制。789Bingo（老站）、789Games（新站）两个站都做，Jira 按站点分别建单（老站【B】、新站【G】）。

判定流程

图中「已达上限」：只能领取一次的活动，判断已勾选且次数大于 0 的项；一个账号能多次领取的活动，该设备或 IP 在本周期内已由其他账号领取过即为已达上限（规则 N18）。D 方式（不改）的活动不经过本流程。拦截时不发放、不扣参与次数；自动发放被拦截时不提示（规则 N6 拦截处理、N8 自动发放）。需判定的设备标识或 IP 取不到时本次不发放，用户领取时提示「奖励领取限制[L03]」（规则 N11）。活动名单会员：该项下方「本活动白名单用户也受此限制」未勾选时跳过该项，勾选时照常判断（规则 N16）。

开发功能点

F01-01领取次数限制判定查看 PRD ›

要做什么
  • 活动现有校验通过后、发放前，按同设备 → 同 IP 的顺序判定（C 方式先判活动现有 IP 限制，再判同设备）；用户领取、系统自动发放、充值到账、获得充值转盘资格、审核和人工发放、批量发放时都判定（N1、N5、N7、N8、N19）
  • 单次领取类活动（绑定手机号码、KYC 认证送彩金、新用户首充、导入用户登录送彩金（789Games 叫登录送彩金活动（白名单））；后者待技术确认，Q12）：次数 = 本活动成功发放的次数；同设备、同 IP 按所有账号合计；不同活动分别计算（N3）
  • 多次领取类活动（签到、充值优惠、转盘、返水、闯关）：不设次数；每个限制周期内，首个在该设备（或 IP）成功领取本活动的账号与之绑定，其他账号领取本活动的任何奖励都拦截（L01 / L02）；绑定账号自己的多次领取按活动原规则；「每天」「一个月」在下一个周期开始时解除绑定，「7 天」「15 天」按滚动窗口判断（领取当天往前 7 / 15 个自然日内该设备或 IP 有其他账号成功领取过即拦截，否则可领取并成为新的绑定账号），「活动期间」一直绑定（N18 ④）
  • 周期：活动期间（上线后累计）、每天（自然日）、7 天 / 15 天（含当天往前滚动）、一个月（自然月），均按 GMT+8；活动原有限制已有周期的沿用原周期，C 方式的同设备项固定为「每天」、不可选；新用户首充（单次领取类）例外，可选五种周期，默认「活动期间」（N4）
  • 单账号次数沿用活动自身规则（N9）
  • 自动发放取账号最近一次登录的设备和 IP，取不到时不发放；被拦截时不发放，首页奖励弹窗、站内信、推送、短信、聊天室播报都不触发（N8）
  • 审核发放：申请时被拦截不生成申请，Toast「奖励领取限制[编号]」；审核时被拦截，【派奖审核】和该活动「活动统计」的记录显示「奖励领取限制[编号]」，默认不发放，玩家申请记录沿用「未通过」，审核人可强制通过；转盘、抽奖类只在转动前判定，中奖后进入派奖审核的，审核时不再判定（N19 ①）
  • 人工和批量发放：发放前同样判定，被拦截的记录显示原因、不随批量发出，不能强制发放，确需发放走【修改余额审批】；只触发一次的奖励被拦截后不自动补发（N19 ②、④）
  • 同 IP 按领取请求的 IP 判定；移动网络下共用同一出口 IP 的账号也算同 IP，次数要按活动参与规模设置（N10）
  • 多个账号同时领取时，合计成功次数不超过上限，多次领取类只绑定一个账号；重复点击只发放一次（N12、N18）
  • ※ 设备标识和 IP 的取值方式由技术确定（已确认 Q3）；本版不考虑换浏览器、在浏览器和 App 之间切换、清除缓存或重装 App 后的设备识别（N10）
公式
单次领取类：该项已领取次数 ≥ 最多领取次数（最多领取次数大于 0，按当前限制周期统计）→ 拦截
同设备 / 同 IP 已领取次数 = 该设备 / IP 上所有账号在当前周期内成功领取本活动的次数之和
多次领取类：该设备 / IP 在当前周期内已绑定其他账号 → 拦截
涉及端
H5 / PC / PWAiOSAndroid后端

F01-02拦截处理与提示查看 PRD ›

要做什么
  • 被拦截时不发放、不扣参与次数、不计次数；转盘和抽奖在转动前拦截；按钮保持可点；签到被拦截时不记签到，连续签到天数可能因此中断（N6）
  • Toast「奖励领取限制[编号]」：L01 = 同设备达到上限；L02 = 同 IP 达到上限；L03 = 取不到设备标识或 IP（N11）
  • 充值页可选的优惠（充值活动、新用户充值活动计划）：选择时已超过 → 该优惠置灰，下方显示「奖励领取限制[编号]」，可不选优惠继续充值；到账时再判定一次，设备标识和 IP 取这笔充值发起时的记录，超过或取不到 → 不发放该优惠，充值金额照常到账，不通知（N7 ①）
  • 每日首充、新用户首充：充值页没有可选项，到账或完成 KYC 后自动发放时按自动发放判定；新用户首充的次日奖励跟随首充奖励：首充奖励已发放的账号，次日奖励不再判定、不计次数，首充奖励被拦截的账号不发放次日奖励（N7 ②、N8）
  • 老用户充值转盘、返现充值转盘：获得资格时判定（取这笔充值发起时的设备标识和 IP），被拦截时不给转盘次数、不弹出转盘、不提示，充值金额照常到账；充值前不提示（N7 ③）
  • 各活动的前台规则说明不加限制提示
公式
无

F01-03设备标识或 IP 获取失败处理查看 PRD ›

要做什么
  • 需要判定同设备或同 IP，但取不到设备标识或 IP 时：不发放、不扣次数，显示 Toast「奖励领取限制[L03]」，可再次点击；自动发放时本次不发放、不提示（N8、N11）
  • 不需要判定的项（未勾选、次数为 0、领取限制白名单会员、按 N16 跳过该项的名单会员）取不到时不受影响

F02-01活动奖励领取限制板块查看 PRD ›

要做什么
  • 两个站都做：按活动接入方式（F02-02）给活动配置页加板块：有活动列表的，加在「创建活动」「修改」（或「编辑」）打开的配置页；没有列表的，加在进入菜单直接显示的配置页（清单见 PRD 5.1）；不涉及【活动配置】栏目
  • 同设备、同 IP 各一行（C 方式只有同设备）：勾选框、限制周期；单次领取类另有最多领取次数（0–9999 的整数，0 为不限制），多次领取类不显示次数，该位置显示灰字「只允许首个领取的账号领取」（N2、N18）；默认不勾选，周期默认「活动期间」；C 方式的同设备项周期固定「每天」、不显示下拉，新用户首充例外（N4）；不设同账户项
  • 板块下方说明文字按领取类型显示（PRD 5.1）；各活动的接入方式和领取类型由技术按 PRD 5.1 固定，运营不能切换（N13 ⑥）
  • 随活动保存，保存后立即生效；修改后已领取次数不清零；取消勾选期间成功发放的次数同样计入，重新勾选后按当前周期内全部成功发放次数判断；复制活动时一起复制；留痕沿用现有操作日志（N13）
  • 活动自身有白名单时，每项下方加勾选框「本活动白名单用户也受此限制」（C 方式只在同设备下方），默认勾选；不勾选时名单内全部会员跳过该项判定，其领取仍计入次数；不能单独放行某一个会员（N16）

F02-02活动接入方式查看 PRD ›

要做什么
  • A 完整接入：板块有同设备、同 IP 两项 + 领取限制白名单（N17）。789Bingo：绑定手机号码（单次）、KYC 认证送彩金（单次）、登录送彩金、签到、导入签到；789Games：绑定手机号码（单次）、KYC认证送彩金（单次）、登录送彩金、签到、签到活动(白名单)；两个站的圣诞闯关、实物奖品、Crown Rush，以及以后新增的活动；VIP 奖励开发时按 A 接入（N1）
  • B 两项 + 沿用原白名单：板块有两项，不设领取限制白名单；沿用活动现有名单，名单内会员是否受限由「本活动白名单用户也受此限制」勾选框决定（N16）。789Bingo：老用户充值转盘、导入用户登录送彩金（单次）、返现充值转盘（尚未上线，随其上线接入，待确认 Q8 ②）；789Games：老用户充值转盘、登录送彩金活动（白名单）（单次）；两个登录送彩金是否每人只能领一次待技术确认（Q12）
  • C 只加同设备：IP 沿用活动现有限制，先判活动现有 IP 限制，再判同设备，不会出现 L02（N5、N17）。789Bingo：消费活动（含返水）、负盈利活动、新盈利活动 V2、新用户充值活动计划、充值活动、每日首充、新用户首充（单次）、邀请好友，幸运转盘暂定未上线、上线时接入；789Games：充值活动、返水活动、输返活动、新输返活动、每日首充、新用户首充（单次）、新用户充值活动计划、邀请好友，抽奖活动暂定未上线、上线时接入
  • D 不改：新用户转盘、完成任务砸金蛋（789Games 叫砸金蛋送彩金活动），沿用当前已有逻辑（N14）
  • 标「单次」的为单次领取类（按次数判定，N3），其余为多次领取类（绑定首个领取账号，N18）
  • 789Bingo 返水已写死使用另外一套：由技术确认现有限制是否生效，生效则按 C 方式补充同设备限制（Q10）
  • 新用户充值活动计划：由技术确认现有 IP 限制是否生效，生效按 C 方式，不生效改为 A 方式（Q8 ③）
  • 全部活动一次上线（Q7）

F02-03领取限制白名单查看 PRD ›

要做什么
  • 只用于 A 方式的活动（含以后新增的活动）；放在板块最后一行，沿用后台现有白名单导入组件（导入文件、已导入文件下载、导入结果统计、保存、重置），组件不改（N15）
  • 每个活动单独导入，随活动保存生效；名单内会员跳过同设备、同 IP 判定（多次领取类也不受绑定限制），其领取仍计入该设备和 IP 的次数，首次领取同样绑定该设备和 IP（N15、N18 ⑥）
  • 复制活动时不复制白名单
