单一设备领取奖励限制 · 需求要点 · v1.0

版本：v1.0端：H5、PWA、iOS、Android、管理后台依据：需求开发 PRD 文档

一句话需求

【活动中心】下每个活动的配置页增加「活动奖励领取限制」板块：可勾选同设备、同 IP、同账户，每项设置限制周期（活动期间 / 每天 / 7 天 / 15 天 / 一个月）和最多领取次数，填「0」为不限制。用户领取和系统发放前按配置判定，超过次数不发放。每个活动可配置领取限制白名单，名单内会员不受同设备、同 IP 限制。

判定流程

只判断已勾选且次数大于 0 的项。拦截时不发放、不扣参与次数，自动发放不提示（N6、N8）。需判定的设备标识或 IP 取不到时暂不发放，提示「正在核验领取资格，请稍后再试」（N11）。

开发功能点

F01-01领取次数限制判定查看 PRD ›

要做什么
  • 活动现有校验通过后、发放前判定；用户领取、自动发放、充值到账都判定（N1、N5、N8）
  • 次数 = 本活动成功发放的次数；同设备、同 IP 为所有账号合计，同账户为该账号自己；不同活动分别计算（N3）
  • 周期：活动期间（上线后累计）、每天（自然日）、7 天 / 15 天（含当天往前滚动）、一个月（自然月），均按 GMT+8（N4）
  • 自动发放取账号最近一次登录的设备和 IP（N8）；活动自身规则照常生效（N9）
  • 并发时合计成功次数不超过上限；重复点击只发放一次（N12）
  • 同 IP 含移动网络共用出口 IP 的账号，次数按活动参与规模设置（N10）
  • ※ 现有设备标识能否唯一区分手机待技术确认（Q3），确认前不建议勾选同设备；本版不考虑跨浏览器、浏览器和 App 之间、清缓存或重装后的设备识别（N10）
公式
该项已领取次数 ≥ 最多领取次数（次数大于 0，当前限制周期内）→ 拦截
同设备 / 同 IP 已领取次数 = 该设备 / IP 上所有账号在当前周期内成功领取本活动的次数之和
涉及端
H5 / PWAiOSAndroid后端

F01-02拦截处理与提示查看 PRD ›

要做什么
  • 不发放、不扣参与次数、不计次数；转盘和抽奖在转动前拦截；按钮保持可点（N6）
  • Toast：同账户「本活动领取次数已达上限」、同设备「此设备领取次数已达上限」、同 IP「当前网络领取次数已达上限」
  • 充值优惠：选择时超过 → 置灰并显示文案；到账时超过 → 不发优惠，充值照常到账，不新增通知（N7）
公式
无
涉及端
H5 / PWAiOSAndroid后端

F02-01活动奖励领取限制板块查看 PRD ›

要做什么
  • 所有活动（含以后新增）的配置页加板块：有列表的加在「创建活动」「修改」打开的配置页，无列表的加在直接显示的配置页（清单见 PRD 5.1）
  • 三项各一行：勾选框、限制周期、最多领取次数（0–9999 整数，0 为不限制）；默认不勾选（N2）
  • 随活动保存后立即生效；修改后已领取次数不清零；复制活动时一起复制；修改写入现有操作日志（N13）
公式
无
涉及端
管理后台后端

F02-03领取限制白名单查看 PRD ›

要做什么
  • 每个活动单独配置；「管理白名单」弹窗（高度为页面 3/4）按会员名添加、查询、移除；添加、移除写入现有操作日志（N15）
  • 名单内会员跳过同设备、同 IP，同账户照常；其领取仍计入设备和 IP 次数
  • 添加、移除立即生效；创建活动时需先保存活动；复制活动不复制白名单；列表默认 20 条、添加时间倒序
公式
无
涉及端
管理后台后端
