规则批注

  1. 单次领取类（按次数）：每个账号只能领一次的活动（绑定手机号码、KYC 认证送彩金、新用户首充、导入用户登录送彩金（789Games 叫登录送彩金活动（白名单）））。只判断本活动已勾选且次数大于 0 的项，某项已领取次数（该设备或 IP 上所有账号在本周期内的成功发放次数合计）≥ 最多领取次数即拦截。PRD 规则 N2、N3、N4 · F01-01 领取次数限制判定
  2. 多次领取类（绑定首个账号）：其余活动（如签到、登录送彩金、充值优惠、转盘、返水、闯关）。勾选同设备后，限制周期内首个在该设备成功领取本活动的账号与该设备绑定，其他账号领取本活动的任何奖励都提示「奖励领取限制[L01]」；同 IP 相同，提示 L02。绑定账号自己的多次领取按活动原规则；同设备、同 IP 分别绑定。解除绑定：「每天」「一个月」在下一个周期开始时解除；「7 天」「15 天」按滚动窗口，领取当天往前 7 / 15 个自然日内该设备（或 IP）有其他账号成功领取过即拦截，否则可以领取并成为新的绑定账号（例：选 7 天，账号 A 最后一次在设备 X 领取是 2026-11-04，账号 B 在 2026-11-10 被拦截，2026-11-11 可以领取）；「活动期间」一直绑定。PRD 规则 N18 ④
  3. 判定顺序：活动现有校验（含单账号次数）通过后，按「同设备 → 同 IP」的顺序判断，两项都被拦截时只提示第一项。C 方式（只加同设备）的活动先按活动现有 IP 限制判断，被拦截时沿用现有提示，通过后再判断同设备，不会出现 L02。演示：勾选模拟操作里的「活动只加同设备（C 方式）」。PRD 规则 N5、N9、N17
  4. 拦截：不发放、不扣参与次数，按钮保持可点；转盘和抽奖在转动前拦截；签到被拦截时不记签到，连续签到天数可能因此中断。Toast「奖励领取限制[编号]」：L01 同设备，L02 同 IP。PRD 规则 N6 · F01-02 拦截处理与提示
  5. 充值相关：① 充值页可选的优惠：选择时被拦截 → 优惠置灰，下方显示「奖励领取限制[编号]」，可不选优惠继续充值（见「充值页」场景）；到账发放前再判定，被拦截 → 不发放优惠，充值金额照常到账。② 每日首充、新用户首充：只在实际发放时按自动发放判定；新用户首充的次日奖励跟随首充奖励，首充奖励已发放的不再判定、不计次数，首充奖励被拦截的不发放次日奖励。③ 老用户充值转盘、返现充值转盘：在获得参与资格时判定，被拦截时不给转盘次数、不弹出转盘，充值金额照常到账，不提示。PRD 规则 N7
  6. 取不到设备标识或 IP：需要判定同设备或同 IP 但取不到时，不发放、不扣参与次数，Toast「奖励领取限制[L03]」，可再次点击。PRD 规则 N11 · F01-03 设备标识或 IP 获取失败处理
  7. 名单内会员：领取限制白名单（只在 A 方式的活动）中的会员跳过同设备、同 IP 判定；活动自身名单中的会员，在该项未勾选「本活动白名单用户也受此限制」时跳过该项。他们的领取仍计入该设备和该 IP 的次数，多次领取类同样绑定该设备和 IP。PRD 规则 N15、N16、N18 ⑥
  8. 自动发放：发放前同样判定，被拦截的账号本次不发放，也不提示，首页奖励弹窗、站内信、推送、短信、聊天室播报都不触发；设备和 IP 取该账号最近一次登录的记录，取不到时本次不发放。PRD 规则 N8
  9. 本版不考虑的识别情况：同一设备换浏览器、在浏览器和 App 之间切换、清除缓存或重装 App 后被识别成新设备，以现有标识的识别结果为准；对接三方风控服务后再优化。PRD 规则 N10
