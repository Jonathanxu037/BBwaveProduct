规则批注

  1. 入口与权限：菜单【活动配置 › 活动限制管理】，789Bingo、789Games 两站都在【活动配置】下新增这个栏目（789Games 没有【活动配置】菜单时一并新增）；新增权限项「活动限制管理」，在后台【权限管理】中由平台管理员分配。各活动配置页不加限制板块，只删除原有的同 IP、同设备配置项。PRD 规则 N17
  2. 统一配置：活动中心的所有活动（含新用户转盘、完成任务砸金蛋）都可配置同设备、同 IP、领取限制白名单三项；上线时按实际代码读取已有的活动，读到的都出现在列表里，以后新增的活动也自动出现。各活动原有的同 IP、同设备限制全部删除（后台活动配置页上对应的配置项一起去掉），统一按本栏目的配置限制；上线时系统把原有数据自动迁移到本栏目（直接按上线时生产环境的配置迁移，迁移结果就是列表里显示的当前配置，运营上线后核对、补配；如「同一 IP 每天有 N 个账号可以申领」→ IP 限制 · 每天，多次领取类「最多 N 个账号」、单次领取类「最多领取 N 次」；新站新用户转盘以活动自身数值为准，「一台设备只给一个账号」全局开关删除、不迁移；新站新用户转盘的全局白名单 → 该活动各期的白名单导入；原数值超过 999999 的按 999999 迁移；789Bingo 独立配置的返水活动上线时读不到原有限制配置，按不限制上线，由运营在本栏目配置）。活动自身的领取规则（单账号次数、同一手机号只能领一次、完成任务砸金蛋同 IP、同设备每天名额（活动规则：例如本栏目 IP 限制设为每天最多 1 个账号，即每天 100 个名额由 100 个不同 IP 各 1 个账号参与），邀请好友「同设备不允许互相邀请」和「IP 限制」（同一注册 IP 最多计入 N 个好友，属于邀请资格规则，保留、不迁移））照常生效；本栏目的 IP 限制对邀请好友另外生效，限制同一 IP 下最多几个账号能领取。用户领取、系统自动发放、审核、人工和批量发放，都按本栏目对该活动（分期活动为该期）的配置判定。PRD 规则 N1、N17、N19
  3. 读取活动中心：每次进入本栏目或点「刷新」，都重新读取活动中心的全部活动和各期。新建的活动、新建的期自动出现：新的一期（新建或复制生成）默认沿用该活动上一期的配置（设备限制、IP 限制、「本活动白名单用户也受此限制」和白名单导入的名单），运营可在本栏目修改；该活动的第一期和不分期的新活动默认不限制。已结束、关闭的活动和期照常列出，可查看和配置，配置对之后的领取生效；在活动中心删除的活动或期从列表消失，配置一起失效；删除某一期后，剩下的期重新按创建先后编号。列表包含活动中心的全部活动（含需复测的活动，状态按线上数据显示）和 789Bingo 独立配置的返水活动。开发注意：以后每次新增活动，都要同步更新本栏目的活动清单，让新活动出现在列表里。演示：点「活动中心新建一期，刷新后出现」；或先点模拟操作，再点列表上方「刷新」。PRD 规则 N17
  4. 列表：分期活动（有活动列表、可建多期）每期一行，不分期的活动一个活动一行；按活动中心菜单顺序排列，同一活动按期数倒序。列：① 活动名称，同一活动的多期合并为一个单元格；② 期数 / 状态与有效期：分期活动显示「第 N 期」（按活动列表创建先后编号），下方小字为期名、状态、有效期，不分期的活动显示当前状态和有效期，长期有效写「长期」，有效期与活动中心该活动（期）配置页显示的时间一致（同一时区，列头「?」写明时区）；③ 设备限制、④ IP 限制：未勾选显示「不限制」，单次领取类显示「周期 · N 次」（次数为 0 显示「不限制」），多次领取类显示「周期 · 最多 N 个账号」（数量为 0 显示「不限制」）；⑤ 白名单导入：「已导入 N 人」或「未导入」。③–⑤ 只显示本活动（本期）这三项当前的配置情况；⑥ 操作「配置」。PRD 规则 N17
  5. 搜索与分页：「活动名称」下拉列表，选项为「全部」和列表中的每个活动（每次读取活动中心后更新），选择后点「搜索」，只显示该活动的全部行（分期活动的各期）；默认「全部」。「刷新」保留当前选择，所选活动已删除时回到「全部」。搜索后回到第 1 页。分页沿用后台现有分页，每页 20 条，可切换为 50 条。演示：「第 2 页」。PRD 规则 N17 ⑦⑧
  6. 配置弹窗：两项限制：点「配置」打开「配置限制」弹窗，标题为「配置限制 · 活动名称 · 第 N 期」（不分期的活动不带期数）。同设备、同 IP 各一行，每行有勾选框、限制周期（活动期间 / 每天 / 7 天 / 15 天 / 一个月，默认「活动期间」）；单次领取类填「最多领取 N 次」，多次领取类填「最多 N 个账号」；不勾选或填 0 为不限制。不设同账户项（单个账号的次数沿用活动自身规则）。各活动的领取类型见 PRD 5.1。PRD 规则 N2、N18
  7. 限制周期：所有活动的设备限制、IP 限制都可选「活动期间 / 每天 / 7 天 / 15 天 / 一个月」，默认「活动期间」。演示：「每日首充活动」。PRD 规则 N4
  8. 单次领取类：次数口径：每个账号只能领一次，按本活动成功发放的次数统计，同设备、同 IP 为所有账号合计，次数即该设备或 IP 上能领取的账号数；不同活动分别计算。PRD 规则 N3
  9. 多次领取类：最多 N 个账号：勾选并填 N 后，限制周期内按各账号在该设备（或 IP）首次成功领取本活动的先后取前 N 个，作为有效绑定账号；有效绑定账号已满 N 个且当前账号不在其中时，领取本活动的任何奖励都被拦截（同设备 L01、同 IP L02），未满 N 个时领取成功并成为有效绑定账号；这 N 个账号自己的多次领取按活动原规则；N=1 即只允许首个领取的账号；同设备、同 IP 分别绑定。周期：「每天」「一个月」在下一个周期开始时清空；「7 天」「15 天」按滚动窗口，领取当天往前 7 / 15 个自然日内在该设备（或 IP）成功领取过本活动的账号，按窗口内首次成功领取的先后取前 N 个，窗口内账号数 ≥ N 且当前账号不在前 N 个中时拦截，否则可以领取（例：选 7 天、最多 1 个账号，账号 A 最后一次在设备 X 领取是 2026-11-04，账号 B 在 2026-11-10 被拦截，2026-11-11 可以领取）；「活动期间」整个活动期间累计。活动进行中重新勾选或调小账号数并保存后，同样按首次成功领取的先后只保留前 N 个，其余账号从保存起被拦截。PRD 规则 N13 ③、N18
  10. 活动白名单是否受限制：活动自身有白名单（参与名单、指定名单、指定奖励名单）时，同设备、同 IP 每项下方多一个勾选框「本活动白名单用户也受此限制」（名单名称按该活动现有叫法），默认勾选。勾选：名单中的会员同样按该项判定，右侧灰字「（名单内会员也按此项限制）」；不勾选：名单中的全部会员跳过该项判定，其领取仍计入该设备和该 IP 的次数（多次领取类同样绑定该设备和 IP），右侧灰字「（名单内全部会员不受此项限制）」。活动没有自身名单时不显示。演示：对比「导入签到活动」和「签到活动」。PRD 规则 N16
  11. 领取限制白名单：所有活动都有，沿用后台现有白名单导入组件（导入文件、已导入文件下载、导入结果），不改组件。每个活动单独导入，分期活动每期单独导入，只对本活动（本期）生效，导入后点「保存」才生效，点「取消」不生效。名单内会员跳过同设备、同 IP 判定，其领取仍计入该设备和该 IP 的次数；与活动自身原有的名单相互独立。演示：在弹窗里点「导入文件」查看导入结果。PRD 规则 N15
  12. 保存与取消：「保存」校验已勾选项的数量：为空时单次领取类提示「请输入最多领取次数」、多次领取类提示「请输入最多账号数」，不是 0–999999 的整数提示「请输入 0–999999 的整数」，提示显示在输入框下方，不能保存，焦点停在出错的输入框；校验通过提示「保存成功」、关闭弹窗、列表该行摘要刷新，立即生效。「取消」或右上角「×」关闭弹窗，不保存本次修改（含导入的白名单）。活动进行中修改设置，已领取次数和已绑定账号不清零，取消勾选期间成功发放的次数同样计入；多次领取类重新勾选或调小账号数时只保留前 N 个已绑定账号。每次保存记入【日志管理 › 操作日志】（操作人、时间、活动名称、期数和该期的活动名称、修改前后的配置）。演示：点「保存校验提示」，或在弹窗里清空次数、填 1.5 后点「保存」。PRD 规则 N13
  13. 审核、人工和批量发放：① 审核发放：申请时被拦截不生成申请，Toast「奖励领取限制[编号]」；审核时被拦截，【派奖审核】和该活动「活动统计」的这条记录显示「奖励领取限制[编号]」，默认不发放，玩家申请记录沿用「未通过」，审核人可以强制通过（照常发放、不改变已有绑定；单次领取类计入次数，多次领取类只放行这一次，该账号不加入已绑定账号）。转盘、抽奖类只在转动前判定，中奖后进入派奖审核的，审核时不再判定。② 人工发放、批量发放：被拦截的记录显示原因，不随批量发出；不能强制发放，确需发放走现有【修改余额审批】人工加款。本页不演示审核和发放页面。PRD 规则 N19
