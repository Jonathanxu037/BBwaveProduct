    1. 项目概述

    项目说明
    需求描述在管理后台【提现管理 › 提现出款设置 › 每日提款限制设置】把原有三项限额和新增的 7 条提款风控规则合并成一个规则列表（每条可开关、可调数值、可选适用支付会员层级），在【充值配置 › 支付层级配置】给每个层级加「提款风控规则」执行 / 豁免开关；会员提交提现时命中任一规则，订单转入【提现管理 › 提现风控审核】人工审核，审核页新增优先级列和命中详情弹窗。会员端显示、审核通过和驳回流程不变。
    背景与目标现有提现风控只看单笔金额、每日笔数、每日累计金额和【风控配置】的 12 项条件，识别不了充得少提得多、当日不投注就提现、拆单绕过限额、改收款资料后提现、长期未登录和未使用的沉睡账号提现、返奖金额相对有效投注异常偏高这几类风险。目标：这些提现在出款前进入人工审核，审核人能直接看到命中原因和当时的数值；VIP 会员由运营按层级豁免，不在代码里写死。依据：运营风控方案《提现风控方案》（Xyan）及 2026-10-22 三轮确认结论。
    范围做：第 0 章「本迭代包含」各行。不做：第 0 章「不包含」「第二期」两行。
    多端范围管理后台：做。后端：做。H5 / PC / iOS / Android：界面不改，只需验证命中新规则时不弹窗、订单显示 Under review（见 7.2 跨端验收矩阵）。
    时间与时区所有「当日」按 GMT+8 自然日计算：当天 00:00:00 至本次提现申请提交时间。上线时间：资料未覆盖，待排期。

    2. 整体业务流程

    2.1 主流程（会员提交提现）

    1
    提交提现：会员提交提现申请 → 通过现有前置校验（KYC、绑卡、流水稽核、首提限制，本需求不改）。
    ↓
    2
    层级提现上限：按会员所在支付会员层级的「每笔最高提款」「当日最高提款金额」判断，超出直接拦截（现有逻辑，先于风控规则）。
    ↓
    3
    风控判定：记录会员此刻的支付会员层级 → 对开关开启、且该层级在「适用层级」里的每条规则逐条判定（规则见 3.2）→ 同时按【风控配置】原有条件判定（现有）。
    ↓
    4
    判定结果：命中任一条 → 进入提现风控审核（见 2.2 判定结果分支）；都没命中 → 走现有流程。
    ↓
    5
    人工审核：审核人在【提现风控审核】点「查看命中详情」→ 通过：进入待处理订单出款；驳回：金额退回会员余额，按「提款驳回提醒」发站内信（现有流程）。

    2.2 判定结果分支（按命中情况）

    A - 没有命中任何规则和原有条件

    走现有流程【风控配置】「未触发时自动通过」开启时直接进入出款；关闭时按现状进入风控审核

    B - 命中本需求新增规则

    进入提现风控审核不受「未触发时自动通过」影响；顶栏「风控审核」+1；会员端订单显示 Under review，不弹窗

    C - 命中原有三项（单笔、笔数、累计）

    进入提现风控审核并弹窗会员端按【每日提款限制设置】配置的英文标题和内容弹窗（现有）

    同一笔同时命中多条规则、或同时命中【风控配置】原有条件时，只生成一条待审核记录，命中原因在命中详情里逐条列出。规则计算失败或超时按命中处理（N19 规则计算异常）。

    2.3 系统时序（后端）

    触发执行方动作
    会员提交提现后端写入订单时记录提交时支付会员层级；读取当前生效的规则配置（开关、数值、适用层级）
    风控判定后端逐条计算；每条命中记录规则、统计区间、实际值、阈值（快照）；单条规则计算失败或超时按命中记录「规则计算异常」
    判定完成后端有命中：订单状态为待风控审核，「风控审核」计数 +1；没有命中：走现有流程
    订单离开待审核状态（通过、驳回、会员取消、系统处理）后台 → 后端通过、驳回沿用现有流程；「风控审核」计数 −1
    运营修改配置后台 → 后端保存后只对之后提交的提现生效；每项改动写一条修改记录

    3.2 本需求规则

    通用口径（下面各条直接引用）：

    • 当日：GMT+8 当天 00:00:00 至本次提现申请提交时间。
    • 成功充值：会员通过支付通道发起、状态为成功的充值订单金额，不含失败、取消、处理中。代理代充、后台人工加款、活动奖励等人为操作的入账不计入规则判断，由审核人员在审核时结合资金明细判断。
    • 叫法：本文统一用「支付会员层级」指会员所在的支付层级（后台菜单【充值配置 › 支付层级配置】，审核页列名「会员层级」，界面沿用现有名称）；统一用「提现」，后台现有菜单和字段里的「提款」保持原名。
    • 有效投注：沿用现有有效流水口径，只算已结算注单，按结算时间计入。
    • 当日提现总额：当日已成功 + 审核中 / 处理中 + 本次申请金额；不含已驳回、失败、会员取消。
    • 自上一笔成功提现以来：上一笔提现成功的时间至本次申请时间；没有成功提现记录时从注册时间算起。
    • 新增 7 条规则（N3–N9）发布时开关默认关闭，VIP 迁移完成后由运营逐条开启。
    • 「>」「<」不含等于，刚好等于阈值不命中；「≥」含等于，刚好等于阈值命中。
    编号规则起因功能点
    N1判定时点和范围：会员提交提现、通过现有前置校验和层级提款上限之后判定；只判定开关开启、且会员提交时所在层级在该规则「适用层级」里的规则。层级按提交时判断并记录在订单上，之后调层级不影响已提交的订单现状缺口：规则无法按层级区分F04-01 提现风控判定
    N2原有三项并入规则列表，判定口径不变：单笔提款金额 > 指定值（默认 10,000 PHP）；当日提现笔数（含本次）> 上限（默认 10 笔）；当日累计提款金额（含本次）> 上限（默认 50,000 PHP）。单笔原来就有开关；笔数和累计金额新增开关，默认开启。上线时三项沿用现网已配置的开关和数值，不重置；上面的默认值只用于新环境统一在一个列表里管理和选层级F01-01 规则列表与开关
    N3充提差风控：当日有成功充值时，当日提现总额 > 当日成功充值 × 倍数（默认 10）即命中；当日没有成功充值时不判断（由 N4 处理）识别充得少、提得多F01-02 新增规则配置
    N4无充值提现风控：当日没有任何成功充值，且本次申请金额 ≥ 门槛（默认 1,000 PHP）即命中；本次申请 < 门槛不命中识别当天不充值就提大额F01-02 新增规则配置
    N5当日低投注风控：当日有效投注 < 当日成功充值 × 倍数（默认 5）即命中；当日没有成功充值时不判断。命中详情另附前一日和近 7 日的成功充值、有效投注，只供参考，不参与判断识别充值后不投注就提现F01-02 新增规则配置
    N6拆分提现风控：本次申请往前 N 分钟（默认 30，滑动窗口，含本次）内有效申请 ≥ M 笔（默认 3），且这些申请累计金额 > 单笔大额提现的指定值（N2，即使单笔大额提现开关关闭也取它的数值）。有效申请 = 提交成功且未被会员取消；大额拆单产生的子订单不算多笔识别拆成小额绕过单笔限额F01-02 新增规则配置
    N7资料变更风控：最近一次修改提现账号、收款人或提现方式后 N 小时内（默认 72，申请时间 − 修改时间 ≤ N 小时）的每一笔提现都命中。含新增绑定和客服在后台代改；不含注册后第一次绑定。修改时间取资料实际生效的时间：会员自己修改为保存成功时间，后台代改为审核通过时间；修改记录取自会员操作日志里提现账号、收款人、提现方式的变更识别盗号后改收款资料提现F01-02 新增规则配置
    N8静默账号风控：本次登录距上次登录 > N 天（默认 15，按 N × 24 小时计），且本次登录后到提现申请之间没有成功充值即命中。登录只算登录日志里登录成功的记录（含自动登录，不含 token 续期）；没有上次登录记录（注册后第一次登录）时不判断识别沉睡账号被盗后提现F01-02 新增规则配置
    N9异常返奖率风控：自上一笔成功提现以来，全部游戏的派彩 ÷ 有效投注 > 倍数（默认 5）即命中。派彩为已结算注单的返奖金额，含返还的投注本金，倍数按含本金口径设定；有效投注 ≥ 门槛（默认 1,000 PHP）才判断，低于门槛或为 0 时不判断识别漏洞利用、作弊造成的异常盈利F01-02 新增规则配置
    N10数值校验：倍数 0.1–999，最多 1 位小数；金额、笔数、分钟、小时、天数为正整数。开关开启的规则数值必填；开关关闭的规则不校验。任一处不合法时输入框标红、提示原因，整页不保存。后端同样校验防止误配置F01-04 校验与保存
    N11适用层级：每条规则点「配置层级」勾选适用的支付会员层级，弹窗列出当前全部层级。支付层级配置里为「豁免」的层级置灰、不可勾选；例外：单笔大额提现、当日提现次数、当日累计提现金额、资料变更风控、静默账号风控、异常返奖率风控六条，豁免层级也可勾选，标「豁免层级（本规则仍检查）」。「全选」只作用于可勾选层级，部分勾选时显示半选。至少勾选一个层级，否则提示「请至少勾选一个层级；不需要这条规则时请关闭开关」。点「确认」立即生效并写修改记录，不用再点页面「保存」；「取消」或 × 不改动每条规则按层级单独控制F01-03 配置适用层级
    N12适用层级的默认和联动：没配置过的规则默认勾选全部「执行」层级；N11 的六条例外规则默认勾选全部层级（含豁免层级）。层级改为「豁免」后，在其他规则里不再生效并置灰，在六条例外规则里仍按勾选生效；改回「执行」后自动加入所有规则的适用层级（之前在某条规则里取消过的也加回），运营可再到各规则里取消。新建层级自动加入所有规则的适用层级，运营可再到各规则里取消（10-26 确认）。原有三项对豁免层级照常检查（豁免层级可勾选并默认勾选），与现状一致（10-26 确认）。层级被删除时，自动从各规则的勾选里去掉层级豁免与规则勾选保持一致F01-03 配置适用层级
    N13支付会员层级「提款风控规则」：执行 = 该层级可以在各规则的「配置层级」里被勾选；豁免 = 该层级在除 N11 六条例外以外的规则里不能勾选、不检查。新增层级默认「执行」，编辑时回显当前值；Tier VIP 由运营设为豁免。阈值不按层级设置；层级自带的每笔 / 当日最高提款保持现状VIP 豁免由运营配置，不在代码里写死层级名F02-01 执行 / 豁免
    N14修改确认：执行 ↔ 豁免改动时，点「确定」后弹确认框，写明该层级的会员人数和影响；确认后保存。Default layer（分层值 0，新会员默认层级）改动时不弹普通确认框，改为「谷歌验证」：输入 6 位验证码，通过才保存；未输入提示「请输入谷歌验证码」，不是 6 位数字提示「请输入 6 位数字验证码」，错误提示「谷歌验证码错误，请重新输入」，都不关弹窗；取消或 × 不保存，编辑弹窗保留。只改 Default layer 的其他字段不需要验证防止误操作让整个层级少检查规则F02-02 修改确认与谷歌验证
    N15命中处理：命中任一规则（含原有三项）→ 订单进入【提现风控审核】待审核，顶栏「风控审核」+1（所有后台页面同步显示，新进来时数字闪动提醒），不受「未触发时自动通过」影响。与【风控配置】原有条件同时命中只生成一条记录。会员端只显示 Under review；新增规则命中不弹窗，原有三项照常弹窗。顶栏计数 = 当前处于待审核状态的订单数，订单离开待审核状态（通过、驳回、会员取消、系统处理）即 −1；会员能否取消审核中的订单沿用现状命中后统一由人工判断F03-01 命中进入审核

    7.1 验收条目

    2. F04-01 提现风控判定：会员 Tier VIP（豁免）提交只满足充提差风控条件的提现 → 不进入审核；同一会员提交满足资料变更风控条件的提现 → 进入审核。
    3. F01-02 充提差风控（倍数 10）：当日成功充值 3,000，当日提现总额 30,000 → 不命中；30,001 → 命中；当日已驳回的提现不计入。
    4. F01-02 无充值提现风控（门槛 1,000）：当日无成功充值，申请 999 → 不命中；1,000 → 命中；当日有一笔成功充值 → 不判断。
    5. F01-02 当日低投注风控（倍数 5）：当日成功充值 3,000，有效投注 15,000 → 不命中；14,999 → 命中；未结算注单不计入；当日无成功充值 → 不判断。
    6. F01-02 拆分提现风控（30 分钟、3 笔、单笔大额 10,000）：30 分钟内 3 笔累计 10,000 → 不命中；10,001 → 命中；第 1 笔在 31 分钟前 → 不计入；会员取消的申请、拆单子订单不计入。
    7. F01-02 资料变更风控（72 小时）：修改后 72 小时整提交 → 命中；72 小时 1 秒 → 不命中；注册后第一次绑定 → 不命中；客服后台代改 → 命中。
    8. F01-02 静默账号风控（15 天）：间隔 15 天整 → 不命中；15 天 1 秒且登录后未充值 → 命中；登录后有一笔成功充值 → 不命中。
    9. F01-02 异常返奖率风控（5 倍、门槛 1,000）：有效投注 999 → 不判断；有效投注 1,000、派彩 5,000 → 不命中；派彩 5,001 → 命中；没有成功提现记录时从注册时间统计。

    8. 上线方式

    • 上线前：用近 30 天提现数据回测各规则命中量，确定默认阈值（待确认 Q7）；确认谷歌验证可复用（Q4）。
    • 原有配置：单笔大额提现、当日提现次数、当日累计提现金额沿用现网已配置的开关和数值，发布时不重置。
    • 发布顺序：① 发布代码，新增 7 条规则的开关默认关闭（10-26 确认）；② 运营在支付层级配置把 VIP 层级设为豁免，用条件转移把 VIP 等级 ≥ 30 的会员转入；③ 运营核对各规则的适用层级和数值后逐条开启。
    • 上线后验证：第 1 天核对命中量与回测是否接近，抽查命中详情的数值；关注待审核积压和风控超时。
    • 回滚：关闭对应规则的开关即可停止判定，不需要发版；已进入审核的订单按现有流程处理完。

    11. 各角色协作 Tips

    设计

    • 沿用现有后台组件，新增控件只有开关、配置层级弹窗、优先级标签、命中详情弹窗。
    • 命中详情的英文比中文长，表格列宽按英文验证。

    前端

    • 顶栏「风控审核」计数所有后台页共用一个数据源。
    • 配置层级弹窗确认后直接调接口保存，不依赖页面底部「保存」。

    后端

    • 订单落库时就存提交时层级和每条命中的快照，审核页只读快照；规则名称和触发原因以英文保存，另存结构化数值，中文界面用模板渲染。
    • 所有展示内容（命中详情、提示、导出）都跟随后台语言选择显示同一语种，不混排。
    • 每条规则独立计算、独立超时，一条失败不影响其他规则。
    • 同一会员并发提交时按落库顺序计算当日总额和拆分窗口。

    测试

    • 按 7.1 的边界值两侧各测一次，并测 23:59:59 / 00:00:00 跨天。
    • 用「切换层级 → 提交 → 改配置」验证快照不变。

    运营

    • 上线按第 8 章顺序：先设 VIP 豁免和迁移，再逐条开启规则。
    • 上线首周每天看命中率和积压，及时调阈值。

    客服

    • 会员问「提现一直在审核中」时，只说明订单在人工审核，不透露规则和阈值。对玩家的回复口径见客服 QA。
