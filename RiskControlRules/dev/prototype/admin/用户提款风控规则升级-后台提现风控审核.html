规则批注

  1. 进入方式：会员提交提现时命中任意一条提款风控规则 → 订单直接进入本页待审核，同时后台页头的「风控审核」计数 +1（所有后台页面的页头都同步显示，新进来时数字闪一下提醒）；不受「未触发时自动通过」影响。审核通过或驳回后 −1。
  2. 触发风控条件列：每笔订单只显示「查看命中详情」按钮，不在列表里直接列原因。同一笔同时命中提款风控规则和风控配置原有条件时，只有一条记录，原因都在弹窗里列出。
  3. 后台语言：顶栏语言下拉切换「简体中文 / English」，整个后台画面（列表、弹窗、提示）都跟着切换，包括命中详情里的规则名称、触发原因、统计区间、实际值和阈值；三个后台原型页共用当前选择。中英对照见 assets/admin-en-dict.js。
  4. 命中详情弹窗（表格排版，跟随后台语言）：上方「订单信息表」：订单号、会员名、提交时层级、提现金额、订单日期、共命中几条。下方「命中规则表」每条命中一行，列为：序号、优先级（颜色）、命中规则（规则名称）、类型（提款风控规则 / 原有风控条件）、触发原因（一句话说明，实际数值对比阈值）、统计区间、实际值、阈值。命中当日低投注风控时，表下另附「前一日及近 7 日充值和投注」表。数值取提交时的配置，之后改配置不影响；不显示规则编号；原有风控条件的统计区间、实际值、阈值沿用现有风控配置的展示（原型里用需求说明样式标注，上线不显示这段说明）。
  5. 会员名（现有功能，按线上还原）：会员名为蓝色，后面依次是条状图图标和复制按钮。点会员名或条状图图标，打开「用户资金情况」弹窗：两个标签页「24小时资金详情」「上次提款成功后」（旁边红字提示「提款成功查询时间至多一周」），两列显示账号、名称、当前登录时间、当前IP信息、账户余额、上次充值金额、充值次数 / 金额、提款次数 / 金额、投注总金额、输赢总金额、退水总金额、未结算金额、活动金额、红包金额、后台加钱 / 扣钱、三方投注总额、备注、上次提款成功时间，下方是三方投注明细表（平台名称、注单量、有效投注金额，没有数据时显示 No Data）。点复制按钮把会员名复制到剪贴板，提示「复制成功」。
  6. 稽核明细（现有功能，按线上还原）：点「稽核明细」打开弹窗：稽核实际扣除金额(PHP)、实际出款金额、稽核手续费检核通过、稽核操作记录，下方稽核明细表（创建时间、类别名称、交易单号、充值金额、要求打码量、已完成打码量、通过/不通过、扣除金额、操作，没有记录时显示 No Data），右下角「取消」关闭。
  7. 列表其余各列：订单日期、订单号、订单状态、用户信息（会员名、会员层级、真实姓名、名 / 中间名 / 姓、余额、近 7 天有效投注、提款次数、币种）、提款金额 / 手续费、实际出款金额、收款账户信息、用户资金情况、用户 7 日输赢、IP 区域、提现终端、出款方式、稽核明细、审核备注、订单类型、处理时间、操作时间、操作人，按线上现有显示方式，本需求不改；「会员层级」显示提交时的层级。
  8. 优先级：高 = 拆分提现风控、资料变更风控（第二期加关联风险账号）；中 = 充提差风控、无充值提现风控、当日低投注风控、静默账号风控、异常返奖率风控、规则计算异常（第二期加同设备、同 IP）；低 = 单笔大额提现、当日提现次数、当日累计提现金额。风控配置原有条件也分级（10-26 确认）：用户 IP 在黑名单、真实姓名在黑名单、在 NDRP 名单、余额与资金明细余额不一致、在风控预警中有待处理或已确认风险记录为高；其他原有条件（如用户首次提款、提款 IP 与其他用户重复、7 天总输赢）为低。没有命中任何条件、因【风控配置】「未触发时自动通过」关闭而进入审核的订单显示「—」，排在最后（10-26 确认）。一笔取最高的一级；只用于排序和颜色，不影响审核权限。
  9. 命中详情：逐条列出统计区间、实际值和当时的阈值；当日低投注风控另外列出前一日和近 7 日的充值、投注。
  10. 用户信息：显示提交提现时的会员层级（记录在订单上）。需要把会员调到 Tier VIP 时，直接点「会员层级」后面的蓝色铅笔，在「更换用户层级」弹窗（账号、*迁移至下拉，取消 / 确定）里选择层级，提示「修改成功」；也可在【用户管理 › 会员 › 编辑用户】修改。这两处都是现有功能，本需求不改。调整后，列表在「（提交时）」后追加「当前 X」；这笔已提交的订单仍按提交时的层级判断，之后提交的提现按新层级检查。
  11. 通过 / 驳回：沿用现有流程。驳回必须填原因，金额退回余额，发站内信；会员端订单从 Under review 变为对应状态。
  12. 空列表：没有待审核订单时显示「暂无数据」。
