用户提款风控规则升级 · 需求要点 · v1.0

版本：v1.0端：管理后台、后端依据：需求开发 PRD 文档

一句话需求

在管理后台【提现管理 › 提现出款设置 › 每日提款限制设置】把原有三项限额和新增的 7 条提款风控规则合并成一个规则列表（每条可开关、可调数值、可选适用支付层级），在【充值配置 › 支付层级配置】给每个层级加「提款风控规则」执行 / 豁免开关；会员提交提现时命中任一规则，订单转入【提现管理 › 提现风控审核】人工审核，审核页新增优先级列和命中详情弹窗。会员端显示、审核通过和驳回流程不变。

业务流程

1
提交提现：会员提交 → 现有前置校验 → 层级提现上限（超出直接拦截）
↓
2
风控判定：记录提交时层级 → 判定开关开启且适用该层级的规则 → 同时判定【风控配置】原有条件
↓
3
人工审核：点「查看命中详情」→ 通过：出款；驳回：退回余额并发站内信
A - 都没命中

走现有流程按「未触发时自动通过」开关处理

B - 命中新增规则

进入提现风控审核顶栏「风控审核」+1；会员端 Under review，不弹窗

C - 命中原有三项

进入提现风控审核并弹窗弹窗沿用现有配置

开发功能点

F01-01规则列表与开关查看 PRD ›

要做什么
  • 原有三项（单笔大额提现、当日提现次数、当日累计提现金额）并入规则列表，口径不变。
  • 当日提现次数、当日累计提现金额新增开关，默认开启。
  • 第二期三条显示为灰色占位，第一期上线不显示。
公式
单笔 > 10,000 PHP；当日笔数（含本次）> 10；当日累计（含本次）> 50,000 PHP（均为默认值）

F01-02新增规则配置查看 PRD ›

要做什么
  • 新增 7 条规则，每条有开关和数值输入框；发布时开关默认关闭。
  • 当日 = GMT+8 当天 00:00 至本次申请时间；有效投注只算已结算。
  • 成功充值只算会员经支付通道成功的充值；代理代充、后台人工加款、活动奖励不计入，由审核人员人工判断。
公式
充提差风控：当日有成功充值 且 当日提现总额（已成功 + 审核中 / 处理中 + 本次）> 当日成功充值 × 10
无充值提现风控：当日成功充值 = 0 且 本次申请 ≥ 1,000 PHP
当日低投注风控：当日有成功充值 且 当日有效投注 < 当日成功充值 × 5
拆分提现风控：30 分钟内有效申请 ≥ 3 笔 且 累计 > 单笔大额提现的指定值
资料变更风控：申请时间 − 最近一次修改提现账号 / 收款人 / 提现方式的生效时间 ≤ 72 小时（后台代改按审核通过时间）
静默账号风控：本次登录 − 上次登录 > 15 天 且 登录后无成功充值（没有上次登录记录时不判断）
异常返奖率风控：有效投注 ≥ 1,000 PHP 且 派彩（含本金）÷ 有效投注 > 5（自上一笔成功提现以来）
涉及端
后台前端后端

F01-03配置适用层级查看 PRD ›

要做什么
  • 每条规则点「配置层级」勾选支付会员层级，点「确认」立即生效并写记录。
  • 豁免层级置灰不可勾选；单笔大额提现、当日提现次数、当日累计提现金额、资料变更风控、静默账号风控、异常返奖率风控六条可勾选、默认勾选。
  • 至少勾选一个层级；「全选」只作用于可勾选层级。
公式
规则生效 ＝ 开关开启 且 提交时层级 ∈ 已勾选层级 且（层级为「执行」或 规则 ∈ 六条例外）

后台前端后端

F03-01命中进入审核查看 PRD ›

要做什么
  • 命中任一规则，订单进入提现风控审核，不受「未触发时自动通过」影响。
  • 顶栏「风控审核」= 待审核笔数，新进来时闪动；订单离开待审核状态（通过、驳回、取消、系统处理）即 −1。
  • 与原有条件同时命中只生成一条记录。
公式
进入审核 ＝ 命中新增规则 或 命中原有三项 或 命中【风控配置】原有条件
涉及端
后台前端后端

F03-02优先级与排序查看 PRD ›

要做什么
  • 列表第一列显示「高 / 中 / 低 / —」彩色标签；「—」= 没有命中任何条件、因自动通过关闭进入审核。
  • 默认按高 → 中 → 低 → 「—」排序，同级按订单日期正序。
公式
高：拆分提现风控、资料变更风控；原有条件里的 IP 黑名单、姓名黑名单、NDRP 名单、余额不一致、风控预警风险记录
中：充提差风控、无充值提现风控、当日低投注风控、静默账号风控、异常返奖率风控、规则计算异常
低：单笔大额提现、当日提现次数、当日累计提现金额；其他原有条件
订单优先级 ＝ 命中规则中最高的一级
涉及端
后台前端后端

F04-02命中记录与快照查看 PRD ›

要做什么
  • 每条命中记录统计区间、实际值和提交时的阈值；之后改配置不影响。

  • 单条规则计算失败或超时，按命中记「规则计算异常」（优先级中），其他规则照常计算；配置读取失败或判定服务不可用时同样转人工。
