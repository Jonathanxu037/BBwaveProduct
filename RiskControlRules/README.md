# 用户提款风控规则升级功能需求 · v1.0

在管理后台【提现管理 › 提现出款设置 › 每日提款限制设置】把原有三项限额和新增的 7 条提现风控规则合并成一个规则列表（每条可开关、可调数值、可选适用支付会员层级），在【充值配置 › 支付层级配置】给每个层级加「提款风控规则」执行 / 豁免开关；会员提交提现时命中任一规则，订单转入【提现管理 › 提现风控审核】人工审核，审核页新增优先级列和命中详情弹窗。会员端显示、审核通过和驳回流程不变。 涉及端：管理后台、后端。

## 按角色访问

需求包发布成四个角色站点，每个角色一个文件夹，各自的访问链接只发给对应的人：

| 角色 | 包含人员 | 文件夹 | 访问链接 | 能看的页面 |
|---|---|---|---|---|
| 产品 | 产品经理、行政管理人员 | `pdm/` | `<Pages 地址>/<仓库名>/pdm` | 全部页面；默认页是需求与原型中心（含需求文档架构图、运营需求修改记录）；顶栏可切换运营、开发、报告视角 |
| 运营 | 运营、客服、商务 | `opr/` | `<Pages 地址>/<仓库名>/opr` | 原型、需求修改总结（默认页）、运营需求确认、文案确认、后台操作手册、客服QA |
| 开发 | UI 设计、前端、后端、测试 | `dev/` | `<Pages 地址>/<仓库名>/dev` | 原型、需求要点（默认页）、PRD、开发自查清单 |
| 报告 | 汇报和评审对象 | `repo/` | `<Pages 地址>/<仓库名>/repo` | 全部原型页面、完整 PRD（默认页），只读 |

本文件夹是源文件（相当于产品站点的内容）。四个角色站点由 `.claude/tools/build_role_sites.ps1` 生成，不手工修改。

## 发布到 GitHub Pages

1. 解压压缩包，把里面的 `pdm`、`opr`、`dev`、`repo` 四个文件夹和 `index.html`、`.nojekyll`、`README.md` 放到仓库根目录。
2. 提交并推送，在仓库的 Settings › Pages 里选择发布分支。
3. 把四个访问链接分别发给产品、运营、开发和报告对象。直接打开仓库根地址（没有分身份的链接）时，先进这台电脑上次使用的角色站点；没有记录时进产品站点，需要输入密码。

不需要构建。本地预览时，可以在源文件夹页面地址后加 `?role=pdm`、`?role=opr`、`?role=dev` 或 `?role=repo` 模拟不同角色。

产品站点打开时要先输入访问密码（向该需求的产品管理人获取）；运营、开发和报告站点不需要。

注意：静态页面没有登录，这只是按链接和密码做的简单区分，不是真正的权限控制；拿到别的角色链接的人也能打开，懂技术的人也能绕过密码。
